各タスクは「計画 → 確認 → 実装 → 報告」で進め、1 タスク 1 コミット（`feat:` と `docs:` は分ける）。順序どおりに進める。

**着手の順番**: 段階2の修正を、T28a より前に行う。修正の内容は 2 つ。
- 定期面談の通報の欄を、「労働法令違反の疑い」と「通報の要否」に合わせて有効・無効にする。相談の経過の通報・ハローワーク相談の欄も同じにする。
- 支援実績の方法を種別ごとに絞る（ADR-0014）。

段階2の手間の測定（段階2の A）は、この修正の後の画面で測る。
各タスクで `make test`・`make lint`・`make e2e` を通す。業務画面・サービス・監査ログ・権限・e2e は段階1・2の作法を踏襲する。

ゴール: 台帳・支援計画・支援の記録から、在留申請に添付する参考様式（支援計画書・確認書・雇用条件書など）と社内保管の書類を、admin を開かずに生成できる。
生成物ごとに、どのデータ・どの様式の版から作ったかを追える。署名を要する書類は「生成 → 署名済みスキャンの添付 → 証跡」の流れで追える。

ゲート: ダミーデータで確かめる（「段階3の完了条件」の A）。実申請での使用は段階3の条件に含めず、MVP 完了（段階4）後の価値検証（B）で行う（`docs/tasks-phase2.md` の末尾の節に足す）。

## テンプレートと版の持ち方（段階4で様式マスタに移せる形）

段階4の F13 で、様式マスタの登録・切替の画面とマッピング定義の取込を作る。段階3では、そのときに作り直さずに済むよう、表は仕様書 第7章のとおりに作る。中身はリポジトリのファイルから読み込む。

- **ファイル**（git で管理。旧版は消さない。制約5）
  - `templates/forms/<様式ID>/<適用開始日>/`
    - `original.*`: 入管から取得したファイル。手を加えない。
    - `template.docx`: Word の様式だけ。original の写しに差込タグだけを置いたもの。
    - `manifest.json`: 様式 ID・名称・適用開始日・言語・所有者・署名済み添付が必須か・方式（`xlsx-cells`／`docx-tags`）。出典（URL・掲載ページ・取得日・original と template の SHA-256・改正日〔分かれば〕）も持つ。
  - `mappings/<様式ID>/<適用開始日>.json`: データ項目 → セル（`シート!A1`）または差込タグ。書式（日付の書き方・チェックの記号・桁区切り）と検査の規則（T30）を持つ。
- **表**（`forms_engine`）: `FormTemplate`（1 行＝様式 ID×適用開始日×言語×所有者）、`FormMapping`（版に 1 対 1。JSON 列）、`GeneratedDocument`（`FormTemplate` の行を参照）。
- **読み込み**: 管理コマンド `load_form_templates`（`make forms`）。何度実行しても同じ結果になり、新しい版を足すだけで旧版を消さない。既にある版の original・template の SHA-256 が変わっていたら止める（版を足すように促す）。
- **版の選び方**: 生成の基準日（申請日・届出日。既定は今日）に適用される最新の版を自動で選ぶ。別の版を明示的に選ぶ画面と、旧版での再生成は段階4（F13）で作る。段階3では版の参照を履歴に残すだけにする。
- **差込タグの検査**: Word の template は、タグを外した本文が original の本文と同じであることをテストで確かめる（タグを置く以外の変更をしていない）。Excel は original をそのまま開き、書き込むのはマッピング定義のセルだけ。書き込んだ後もシート構造・入力規則・保護が変わっていないことをテストで確かめる（制約3）。
- 段階4では、同じファイルの形を画面から登録・取込できるようにするだけで、表と生成履歴はそのまま使う。

## 共通の方針

- **元データ**: 帳票はすべて確定値（台帳・契約の版・計画の版・記録）から作る。生成のためだけの入力欄は作らない。様式にあって元データに無い項目は、タスクの計画で、元データに足すか生成の画面で入れるかを決める。
- **人の確認**: 生成物は担当者が開いて確かめてから使う（第6章）。入管システムには送らない（制約1）。
- **個人情報**: 生成履歴のスナップショットは暗号化して持つ（在留カード番号・旅券番号を含む場合がある。制約2）。出力ファイルは添付と同じく URL を作らず、認可つきのダウンロードだけで取り出す（ADR-0011）。生成・ダウンロードは監査ログに残す（制約6）。
- **フォント**: 公式の様式は MS 明朝などを前提にしている。LibreOffice で置き換えたフォントでは改行や改ページがずれるおそれがある。T29 で、空の様式を変換して公式の PDF（記載例）とページ数・欄の位置を比べ、使うフォント（日本語と中国語〔簡体字〕）を決める。
- **権限**: 生成は `forms.generate`（両ロール）。要配慮の添付を含む添付セットの出力は、`can_download()` と同じ判定（担当者・管理者）に従う。
- **監査対象**: `GeneratedDocument` は作成と状態の変更を記録する（上書きはしない）。`FormTemplate`・`FormMapping` の読み込みも記録する。
