# 管理者向けの運用手順

日常の設定は、業務画面の左のナビの **「設定」**（管理者だけに表示）で行います。管理画面（admin）を開く必要はありません。

- どの操作も監査ログに残ります（「設定」→「監査ログ」で検索できます）。
- ユーザー・担当者・事務所・外国人は削除しません。やめるときは「無効化」「有効を外す」で残します。
- 本番では、ここに書いたコマンドはサーバーの管理者が実行します（`docker compose exec web ...`）。

## 管理者は 2 人以上置く

管理者が 1 人だけだと、その人が端末をなくしたり休んだりしたときに、ほかの人の MFA リセットやロック解除ができなくなります。

- 管理者ロールのユーザーを、常に 2 人以上にしておきます。
- 最後の管理者は無効化できないようになっています（「最後の管理者は無効化できません」と出ます）。

## 担当者を迎える（招待）

1. 「設定」→「担当者」→「担当者を追加」で、氏名・常勤区分・事務所・役割（支援責任者／支援担当者）・対応言語・養成講習修了日を入れて保存します。
2. 「設定」→「ユーザー」→「ユーザーを招待」で、ユーザー名・メールアドレス・氏名・ロールを入れます。「担当者」に 1. の人を選ぶと紐づきます。
3. 本人に招待メールが届きます。本人がリンクからパスワードを設定し、初回ログインで二要素認証（認証アプリ）と回復用コードを設定します。
4. 招待メールの期限が切れたときは、そのユーザーの画面の「招待の再送」で送り直します（前のリンクは使えなくなります）。

ロールを後から変えるときは、管理画面のユーザー（`/admin/core/user/`）で行います（開発者向けの操作。日常的には使いません）。

## 担当者が退職したとき

ユーザーと担当者は連動しないので、両方を行います。

1. 「設定」→「ユーザー」→ その人 →「ユーザーの無効化」。すぐにログアウトされ、ログインできなくなります。
2. 「設定」→「担当者」→ その人 →「有効」のチェックを外して保存します。
3. 引き継ぎ:
   - 外国人台帳で担当者をその人に絞り、各外国人の詳細の「担当者」の「変更」（「履歴」タブの「担当者を変える」）で、新しい担当者・引き継いだ日（開始日）・理由を入れて替えます。前の担当者は履歴に残り、定期届出は 3月31日時点の担当者を履歴から出します（ADR-0037）。誤って替えたときは、履歴の行を取り消します（今の担当者は前の行に戻ります）。履歴に「推定」の印のある行は、変更の記録が無いため登録の日を開始日として作った行です。違っていれば、取り消して正しい行を入れます。
   - ダッシュボードで担当者をその人に絞り、各届出タスクの「担当者・メモ」で担当者を替えます。

## 端末（スマートフォン）をなくしたとき

1. **本人が回復用コードを持っている**: ログイン画面の「6 桁のコード または 回復用コード」の欄に回復用コードを入れてログインできます（1 つのコードは 1 回だけ）。新しい端末で認証アプリを使えるようにするには、2. の二要素認証のリセットを管理者に頼みます。
2. **回復用コードも無い**: 管理者が「設定」→「ユーザー」→ その人 →「二要素認証のリセット」を行います。本人は次のログインで二要素認証を設定し直します。
3. **管理者全員がログインできない（最後の手段）**: サーバーで次のコマンドを実行します。
   ```
   docker compose exec web python manage.py reset_mfa <ユーザー名>
   ```
   漏洩が疑われるときは、全員をリセットします（`reset_mfa --all --yes`）。

## 自動ログアウト（修正 1 回目 J8。ADR-0030）

- 操作が無いまま 60 分たつと、自動でログアウトします（`SESSION_IDLE_TIMEOUT_MINUTES`）。ログインから 12 時間たったときも、操作の途中でもログアウトします（`SESSION_ABSOLUTE_TIMEOUT_HOURS`。延長できません）。
- 5 分前に画面の下に知らせが出ます。無操作のほうなら「延長する」で延ばせます。12 時間のほうは延ばせないので、入力中の内容を保存してください。
- 時間が来ると、知らせが「ログアウトしました」に変わります。画面はそのまま残るので、必要な入力を写してから、もう一度ログインします。
- 手元の `.env` に `SESSION_IDLE_TIMEOUT_MINUTES=30` が残っているときは 30 分のままです。60 分にするには `.env` を直します（`make env` は既存の値を変えません）。

## 操作のメニュー・日付と時刻の入力（修正 1 回目 B15・B16）

- 表や記録の詳細の操作は、主な操作のボタンと「…」のメニューに並びます。取消・終了の登録など、元に戻しにくい操作はメニューの中に赤字で出ます。メニューは Enter で開き、Esc かメニューの外を押すと閉じます。
- 日付は「2026-07-10」のほか、「20260710」「2026/7/10」「R8.7.10」「令和8年7月10日」でも入れられます。欄を離れると 2026-07-10 の形に直り、曜日が出ます。横の「カレンダー」から年・月を選んで日を押しても入れられます（「今日」もあります）。
- 生年月日は、年・月・日をそれぞれ選びます。
- 時刻は「930」「9:30」と入れても、欄の選択（5 分刻み）から選んでもかまいません。

## 入力の補助（修正 1 回目 B13・B14・B17）

- 必須の欄はラベルが太字です。「入れる場合は必須」の欄は、その区画を入れるときだけ必須です。
- 法人番号・在留カード番号・旅券番号・郵便番号・電話番号・メール・金額は、欄を離れると決まった形に直し、欄の下に「「…」に直しました」と出ます（全角→半角、ハイフン・カンマを外す、郵便番号は 000-0000 など）。形が合わないとき（法人番号の検査用数字など）も知らせます。保存のときも同じ形に直します。外国人の氏名のカナは、ひらがなをカタカナに直します。
- 入力の途中で画面の中のリンクを押すと、「保存せずに移動しますか」と確かめます。閉じる・再読み込み・戻るときは、ブラウザの確かめが出ます。

## ログインがロックされたとき

パスワードを続けて間違えると、そのユーザー名でのログインが一定時間止まります（既定は 5 回で 30 分。`AUTH_LOCKOUT_FAILURE_LIMIT`・`AUTH_LOCKOUT_MINUTES`）。

1. 「設定」→「ユーザー」で「ロック中」と出ているユーザーを開きます。
2. 「ロック解除」→「ロックを解除する」。すぐにもう一度ログインできます。
3. 本人がパスワードを忘れているときは、ログイン画面の「パスワードを忘れた場合」から本人が再設定します（T25）。
   - 登録しているメールアドレスにリンクが届きます（60 分以内に 1 回だけ使える）。二要素認証（認証アプリ・回復用コード）は変わりません。
   - 再設定してもロックは解除されません。ロック中なら、完了の画面に解けるまでの分が出ます。急ぐときは上の手順で解除します。
   - 再設定が終わると、本人に「パスワードが変更されました」のメールが届きます。心当たりのない変更の連絡を受けたら、監査ログの「パスワードの再設定」「パスワードの再設定の申請」を操作者・接続元 IP で確認します。
   - メールはジョブで送ります。届かないときは、`qcluster` が動いているか（`docker compose ps`）と、メールアドレスの登録を確認します。同じユーザーへのリンクは 10 分に 1 通まで、同じ接続元からの申請は 1 時間に 10 回までです。
   - それでも届かないときの予備として、サーバーの管理者が次のコマンドで仮のパスワードを設定し、本人に安全な方法で伝えることもできます。本人はログイン後、管理画面の右上の「パスワードの変更」（`/admin/password_change/`）で自分のパスワードに変えます。
   ```
   docker compose exec web python manage.py changepassword <ユーザー名>
   ```

心当たりのない失敗が続いているときは、監査ログと「設定」→「監査ログ」の操作者・期間で確認し、必要なら開発者に連絡します。

## 誤って無効化した外国人を戻す

1. 「外国人台帳」で「無効化済みを含む」にチェックを入れて絞り込み、その外国人を開きます。
2. 上部の無効化のお知らせにある「無効化を外す」を押し、理由を入れて実行します。監査ログには、元の無効化の理由と外した理由の両方が残ります。
3. 無効化のときに取り消された在留情報・旅券は戻りません。「基本」タブの各「追加」から、新しい行として登録し直します。
4. 取消になった届出タスクも戻りません。
   - 日付で起票されるもの（在留期間更新・旅券更新の確認・雇用契約の期間満了確認）は、翌朝 6:00 の日次の起票で起票し直されます。すぐに必要なら `make filings` を実行します。
   - それ以外（雇用契約の変更・終了の届出など）は、外国人詳細の「届出」タブの「届出を起票」で手で起票します。

## 年に 1 回（年末まで）: 祝日の更新

届出の期限は、行政機関の休日（土日・祝日・年末年始）に当たると翌開庁日に繰り延べます。祝日は jpholiday というライブラリから取るため、翌年の祝日が入った版に更新します。

1. jpholiday の新しい版を確認し、`backend/pyproject.toml` の `jpholiday==` を更新して `make lock` → `make build` を実行します。
2. 翌年の祝日の一覧を出し、内閣府の「国民の祝日について」と照らし合わせます（法改正や特例の祝日を含む）。
   ```
   docker compose exec web python -c "import jpholiday; [print(d, n) for d, n in jpholiday.year_holidays(2027)]"
   ```
3. `make test` を実行し、期限の計算のテストが通ることを確かめます。

## 様式が改正されたとき（段階3。T40）

様式マスタは「様式 ID × 適用開始日 × 言語 × テンプレート × マッピング定義 × 規則」で版を持ちます。旧版は削除しません（CLAUDE.md の制約5）。生成のときは、基準日に適用される版が選ばれます（基準日が最初の版より前なら最も古い版）。作業は開発者が行い、担当者は画面で新しい版を使うだけです。

1. **改正の情報を確かめる**: 入管の様式の掲載ページ（参考様式: https://www.moj.go.jp/isa/applications/ssw/10_00020.html 、分野の様式: https://www.moj.go.jp/isa/applications/ssw/nyuukokukanri07_00201.html ）と提出書類一覧・確認表を見て、改正日・Last-Modified を確かめます。ファイルを取得し、SHA-256 を控えます。
2. **新しい版のフォルダを作る**: `templates/forms/<様式>/<適用開始日>/`（日本語以外は `<適用開始日>.<言語>`。例 `2026-10-18.ja-zh`）に、入管のファイル（original）と manifest.json（URL・掲載ページ・取得日・改正日・SHA-256・ADR）を置きます。.doc の様式は `tools/forms/convert_doc.py` で converted.docx を作ります。
3. **テンプレートとマッピングを道具で作る**: 様式ごとの道具（README の「よく使うコマンド」の `tools/forms/…`）で template.docx とマッピング定義（`mappings/<様式>/<適用開始日>.json`）を作り、生成前の検査の規則（`.rules.json`）を前の版から写して直します。道具の出力は手で直しません（直したら道具を直す）。新しい版で欄や文が変わったときは、道具の定義（SPEC など）を版ごとに分けます。
4. **確かめる**: `make test`（道具の出力の再現・空の様式との頁数と文言・差込の位置）を通し、`make forms` で読み込みます。生成物を公式の様式（記載例）と並べて見比べます（段階3の A の③と同じ）。
5. **中国語の版を確かめる**: 掲載ページの「英語及び９か国語による様式について」の中国語の版（今は 10 の様式をまとめた Word 1 つ。2025-04-01）が新しくなっていないか、第1-6号・第1-17号の中国語の版が個別に出ていないかを確かめます。新しい版が出ていれば、日本語の現行の版と文を比べ（`tests/forms_engine/test_form_languages.py` の比べ方）、同じなら日中併記の版を足します（ADR-0027）。第1-6号は旧い併記の版＋補足の頁、第1-17号は自作の訳文（ADR-0035）を、新しい版が出るまで使います（ADR-0027 の追記）。新しい版が出たら、その版を足して切り替えます。
6. **申請の書類の一覧が改定されたとき**: `application_sets/sources/` の Excel を差し替え、`tools/forms/make_application_sets.py` の `VALID_FROM` を改定日にして、新しい定義（`application_sets/<種類>/<改定日>.json`）を足します。旧い定義は残します。
7. 版を足したことを ADR（または既存の ADR の追記）と `docs/tasks-phase*.md` に書きます。
8. **様式マスタで確かめる**（段階4 T53。ADR-0042）: 管理者が設定の「様式マスタ」で、新しい版が「使用中」になっていること、出典・SHA-256・欄の数が manifest と合っていることを確かめます。基準日が新しい版の適用開始日の後の生成から、新しい版が選ばれます。
9. **新しい版に不備が見つかったとき**: 様式マスタでその版を開き、理由を入れて「この版を停止する」を押すと、前の版が選ばれるようになります（監査ログに残ります）。直した版を読み込んだら「この版の停止を解除する」を押します（版が 1 つだけのときは停止できません）。
10. **作り直すとき**: 生成物の画面の「版を選んで作り直す」で、同じ版や旧い版を選んで、生成のときのデータで作り直せます（新しい生成履歴ができ、元の生成履歴は残ります）。生成物の画面の「記入済み（編集用）」で、記入済みの docx・xlsx をダウンロードして手直しにも使えます（監査ログに残ります）。

## 支援計画書（第1-17号）を作る（段階3。T31）

1. 外国人の詳細の「支援」タブで、計画の版を選び、「支援計画書を作る（第 n 版）」を押す。
2. 基準日（申請予定日）を入れ、Ⅲ欄７「支援の適正性を確保していることの有無」を申告する（支援責任者が受入れ機関の役員の親族などでないこと、登録拒否事由に当たらないことを確かめてから）。
3. 「検査する」で不足の一覧を見る。「生成不可」は、各行の「直す」から直す画面へ行き、直してから戻る。「警告」は内容を確かめ、「警告を確かめたうえで生成します」に印を付けて「生成する」。
4. 生成物の画面で PDF をダウンロードし、記載例と見比べる。署名の行が 11 頁目に出るのは既知の差（ADR-0020）。
5. 本人に写しを渡したら、生成物の画面の「写しの交付を記録する」から交付記録を作る（計画の版は生成物の版になる）。
6. 前もって、設定の「自機関」に名称のふりがなと「支援業務を開始する予定年月日」（登録支援機関登録簿の値）を入れておく。Ⅲ欄７の支援責任者は、外国人の担当者の事務所の「支援責任者」（設定の「事務所」の編集の「支援責任者を変える」で、開始日と理由を入れて選ぶ。履歴が残る。修正 1 回目 A5、ADR-0028・0037）。空だと警告が出る。Ⅳ欄の「氏名（役職）」とⅢ欄７の役職は、設定の「担当者」の「役職」から入る（空なら氏名だけ）。
7. Ⅱ欄２の住所は、ほかの欄と同じ大きさで、〒の行の下に出る（PDF にする一時の写しでだけ住所の場所を結合する。保存する Excel は公式のまま。ADR-0032）。住所が長くて欄に収まらないときは、生成前の検査で警告が出る。標準の計画の実施予定の文が長いと、欄に収まらない警告が出る（設定の「標準の支援計画」で短くできる）。

## 事前ガイダンス・生活オリエンテーションの確認書を作る（段階3。T32）

1. 記録の画面（支援記録 → 事前ガイダンス／生活オリエンテーション）で「確認書を作る」を押す。記録の「説明した担当者」が確認書の説明者になる。通訳は「通訳なし・説明した担当者が通訳した・別の人が通訳した」から選び、別の人なら氏名・所属と言語を入れる（確認書には出ない。修正 1 回目 B7）。
2. 生成不可（細目の未チェック・保証金等の契約が「有」）が出たら、記録を取り消して正しい内容で記録し直す（確認書の文と記録が食い違う書面に、本人が署名しないため）。
3. 生成した PDF を印刷し、本人に示して確認のうえ署名をもらう。署名済みの確認書は、記録の画面の「署名済みの確認書」から添付する（署名日も入れる）。
4. 確認書は提出しない。支援を実施した事務所で保管する（記載例 ★1）。

## 雇用契約の書類（第1-6号・第1-5号・第1-4号）を作る（段階3。T34）

1. 外国人詳細の「契約」タブで版を選び、「第 n 版の書類」の「第1-6号を作る」「第1-5号を作る」「第1-4号を作る」を押す。基準日（申請予定日）を入れて「検査する」。
2. 第1-4号（報酬に関する説明書）は、先に同じ欄の「報酬の説明を入れる」で入れておく（比較の型・様式に書く報酬の単位・申請人と日本人の役職・職務・経験・報酬・賃金規程・同等以上と考える理由）。報酬の説明は後から直せる（監査ログに残る）。新しい版を作ると前の版の説明が写る。
   - 「台帳と契約から入れる」で、職務内容（契約の版の従事する業務）・報酬の単位・経験年数の目安を一度に入れられる（保存はしないので、確かめてから保存する。修正 1 回目 B12）。経験年数は、在留情報に技能実習3号の行があれば 5 年、2号の行だけなら 3 年の目安（運用要領 本体 印刷49頁）。修了したかどうかは人が確かめる。
   - 比較対象となる日本人労働者も、最も近い職務の日本人もいないときは、第1-4号は使えない（生成不可）。任意の様式で、報酬額を決めた方法や経緯を説明した文書を作る（記載例 2 頁）。
   - 比較対象（様式の ２）の報酬や賃金規程の報酬が申請人を上回ると、強い警告が出る。生成はできるが、役職・経験の違いを確かめてから使う。
   - 作成責任者は生成の画面で入れる（初期値は受入れ機関の代表者）。
3. 第1-6号の「１時間当たりの金額」は、月給 ÷ 月の所定労働時間数（日給は 1 日の所定労働時間数）で計算した額と 1 円を超えて違うと警告が出る（労働基準法施行規則 第19条）。月によって所定労働時間数が違う場合は、月の時間数に 1 年間の 1 か月平均（年 ÷ 12）を入れる。
4. 手当・控除・交代制が様式の行を超えると、超えた行は出ない（警告。合計は全部の行で計算する）。超えた分は任意の様式の別紙に書く。
5. 第1-6号の別紙２（無期転換後の条件）は生成しない。契約の版に添付した別紙２ を一緒に使う。
6. 窓口（Ⅸ４・５）は、版の部署名・担当者職氏名・連絡先の 3 つの欄から出る。T34 より前の版は 1 つの文を部署名の欄に出す（警告）。次の版で 3 つの欄に分けて入れる。
7. 第1-6号・第1-5号は署名が要る（帳票タブで署名済みのスキャンを添付する）。第1-4号は署名の添付を求めない。
8. 第1-6号の代表者の「○印」は PDF に出ない（既知の差。押印は原則として不要）。

## 定期面談報告書（第5-5号・第5-6号）と相談記録書（第5-4号）を作る（段階3。T35）

1. **定期面談報告書**: 面談の詳細の「定期面談報告書を作る（第5-5号・第5-6号）」で、本人用と監督者用をまとめて生成します。基準日は面談の日、作成年月日は生成した日です。署名の欄はありません。結果は帳票タブに出ます。
   - T35 より前に記録した面談（質問の回答が無い）は、質問・⑥・４ の欄が空のまま生成されます（警告）。回答を後から足すことはできません。
   - 問題の内容などの長い文は、欄の幅で改行し、字を小さくして入れます。小さくしても収まらないときは警告が出ます。超えた分は任意の様式の別紙に書きます。
   - 面談の対応者が支援責任者でも支援担当者でもないと警告が出ます（記載例 ★１）。
2. **相談記録書**: 受入れ機関の詳細の「相談記録書（第5-4号）」の「相談記録書を作る」で、期間（既定は今日を含む年度 4/1〜3/31）を入れて「検査する」で件数を確かめ、「生成する」。受付の日にその受入れ機関に雇用されていた外国人の相談が並びます。1 枚に 9 件まで入り、10 件目からは 2 枚目として別の帳票になります。機関の氏名又は名称は自機関の名称です。
   - 複数の外国人の個人情報を含むので、作る・見るには「帳票の生成」と「外国人の閲覧」の両方の権限が要ります。

## キャリアアッププラン・実務経験証明書を作る（段階3。T36）

1. **プランの登録**: 受入れ機関の詳細の「キャリアアッププラン」の「キャリアアッププランを作る」で、分野（事業所ごとに違う場合だけ事業所）・適用開始日・想定されるキャリアルート・レベル（レベルの名前・習熟の目安の年数・業務内容・必要な経験と資格・地位・処遇）を入れます。年数は「◯年目から」「◯年目まで」の 2 つの数字で入れます（「まで」が空なら「◯年目以降」）。変えるときは「新しい版を作る」（前の版が写ります。変更理由は必須）。版は消えずに残ります。
   - **下書きの版**（修正 1 回目 J1。ADR-0029）: まだ生成にも交付記録にも使っていない版は、詳細に「下書き（まだ使っていない）」と出て、「編集」で直せます（版は増えません）。一度生成するか交付記録を作ると「固定」になり、直すときは新しい版を作ります。
   - 移行で年数を数字に読み取れなかったレベルには「年数を数字で入れ直す」の印が出ます。生成もできますが、警告が出て元の文字のまま書かれます。
2. **生成**: 外国人の「契約」タブの「キャリアアッププランを作る」で、基準日（交付する日）を入れて生成します。契約の事業所・分野のプランの、その日に適用される版が使われます。プランが無いと生成できません。
3. **交付**: 生成物の画面の「写しの交付を記録する」で交付記録を作ります（契約が入っています）。雇用契約の締結の前に交付して説明し、本人の署名済みの控えを添付します。
4. **水産加工業の区分**（2027年4月1日から）: プランに「転職できる範囲」を書き、交付記録で「転職できる範囲を含むキャリアパスの説明に同意を得た」に印を付けます。無いと注意が出ます。
5. **実務経験証明書**: 本人から求められたら、「契約」タブの「実務経験証明書を作る」で生成し、交付記録（実務経験証明書。求められた日も）を作ります。期間は雇用契約上の期間で、休業等の期間を含みます。署名済みの控えは不要です。

## 中国語の様式を作る（段階3。T38）

1. 支援言語が中国語の外国人では、第1-5号（雇用契約書）・第1-6号（雇用条件書）・第5-8号・第5-9号（確認書）の生成の画面の「様式の言語」の初期値が「日本語と中国語（併記）」になります。入管が配布する日中併記の版を基本にします（ADR-0027 の追記）。日本語だけの版にしたいときは「日本語」を選びます。
   - **第1-6号**: 入管の併記の版は旧い版で、今の様式にある「Ⅸ４ 待遇の相違の説明を求めることができる窓口」がありません。生成すると、雇用条件書の末尾に**補足の頁**（自作の日中併記。窓口の欄と、番号・見出し・語の違いの注）が綴じられます（全部で 8 頁ほど）。署名は雇用条件書の受取人の欄と、補足の頁の署名の欄の両方にもらい、補足の頁も含めた署名済みのスキャンを添付します。補足の頁の訳は人の確認待ちです。
   - 第1-6号の自作の訳文（下の 2）も、「様式の言語」で選べます。
2. 第1-17号（支援計画書）は、入管の併記の版が現行の様式と違う所が多い（旧い版）ため使わず、入管が新しい版を出すまで自作の訳文を例外として使います。生成の画面に注意が出ます。
   - **中国語の訳文（自作。T43、ADR-0035）**: 日本語の版を作った後、同じ生成の画面の「様式の言語」で「中国語（簡体字）の訳文（自作）」を選び、「検査する」→「生成する」で、訳文を別の書類として作ります。様式の形は日本語の版と同じで、見出しに「（译文 / 翻訳文）」が入ります。字体は中国語の字体（Noto Serif CJK SC）なので、頁が日本語の版より増えることがあります。
   - 訳文に入る値は、訳を登録した文（標準の支援計画の実施予定の初期値・分野と業務区分・国名・締切日などの決まった形）だけが中国語になります。自由に書いた日本語の文は日本語のまま出て、生成前の検査に「訳が登録されていない値が n 件」と警告が出ます（氏名・住所などは訳さないので数えません）。
   - 署名は日本語の様式に行います（第1-17号の「翻訳文の言語」の欄は日本語の様式にあるため）。訳文には署名済みのスキャンを求めず、回収のタスクも作りません。提出用の PDF では、日本語の様式の直後に訳文が綴じられます。
   - 訳（固定の文と値の表）は人の確認待ちです。対照表は `docs/translations/` にあります。直すときは `tools/forms/translations/`（固定の文）・`backend/services/data/translations/zh-hans.json`（値）を直し、`python3 tools/forms/make_translation_templates.py` で作り直します。
3. 生成物の画面に「様式の言語」が出ます。生成物から交付記録を作ると、「書面の言語」に版の言語（併記の版なら日本語と中国語、訳文なら中国語）が入ります。

## 申請の書類をそろえる（段階3。T37）

1. **一覧**: 外国人の「帳票」タブの「申請の書類の一覧」で、申請の種類（認定・変更・更新）と基準日（申請の予定日）を選んで「表示」。入管の提出書類一覧・確認表の行ごとに、生成済み・未生成・添付済み・未添付・期限切れ・システムの外が出ます。当てはまらない行は下にまとめて出ます。在留期間更新のタスクの詳細からも開けます（更新で開きます）。
   - 状態は先頭の列です。赤は不足（未生成・未添付・期限切れ）、黄は確かめが要るもの、緑は済み、灰はシステムの外・判断しないもの・生成中です（修正 1 回目 B9）。
   - 「生成する」「添付」はモーダルで開き、終わると一覧に戻ります（B10）。生成の直後は「生成中」と出ることがあります。画面を読み直すと「生成済み」になります。
   - 健康診断の書類は、有無と受診日だけが出ます。認定は基準日から遡って 3 か月、変更は 1 年より前の受診なら「受診が古い」と出ます（運用要領 本体 印刷16頁。変更は日本の医療機関での受診に限られますが、システムでは確かめません）。受診日の無い古い添付は「受診日が未入力」と出ます。中身は基本情報の健康診断の書類から（担当者と管理者だけ）。
   - 「実績のある機関の書類」（第2表の1）は、システムでは当たるかを判断しません。当たる機関は第2表の2・3の代わりに使えます。
   - 第5-8号・5-9号（確認書）・第5-10号（支援委託契約書）は申請の添付ではないので、一覧に出ません（保存の書類。運用要領 本体 印刷87頁・第5-10号の記載例の注記）。
2. **分野の誓約書・説明書**: 外国人の「契約」タブの「第3-1号を作る」（工業）・「第13-1号を作る」「第13-2号を作る」（飲食）・「第1-25号を作る」で、基準日と作成責任者（初期値は代表者。第13-2号は自機関の代表者）を入れて生成します。誓約書の文と記録が食い違う（分野・業務区分・産業分類・加入の証明書）と生成できません。
3. **支援委託契約書（第5-10号）**: 受入れ機関の詳細の支援委託契約の「編集」を開き、委託料の欄の下の「内訳」で内訳（名目・金額・随時か定期か。10 行まで。合計は月額と同じ）を入れて「完了」、契約を保存してから、「契約」タブの「第5-10号を作る」で生成します（修正 1 回目 B11）。
   - 合計が委託料と合わないまま「完了」を押すと、「委託料を内訳の合計に直す」か「戻って内訳を直す」かを選びます。委託料が空なら、内訳の合計が入ります。
   - 内訳だけを変えても届出のタスクは作られません（月額が変わったときは、支援委託契約の編集で変更として登録します）。
4. **自機関の設定**: 「設定」の「自機関」に代表者の役職と、第5-10号 第8条の管轄裁判所（地名）を入れます。無いと警告が出て、空欄で出ます。
5. **不足の書類をまとめて生成する**（T42、ADR-0033）: 申請の書類の一覧で、未生成の行に「生成不可」「警告 n 件」「生成できる」が出ます。「不足の書類をまとめて生成」で、生成する行の検査の結果（生成不可の理由・警告）と不足の添付が一覧で出ます。
   - 生成不可の行は選べません（理由と直す画面へのリンクが出ます）。警告のある行を生成するときは「警告を確かめたうえで生成する」に印を付けます。第1-17号を含むときは、Ⅲ欄７の申告の印もここで付けます。
   - 作成責任者・様式の言語は、1 件ずつの生成の画面の初期値で生成します。変えたいときは、その様式の画面で生成してください。
6. **提出用の PDF を作る**（T42、ADR-0033）: 申請の書類の一覧の「提出用の PDF を作る」で、提出書類一覧表を先頭に一覧表の番号順に 1 つの PDF にまとめます（一覧表の表紙の留意事項３）。
   - 署名が要る様式は、署名済みのスキャンがあればそれを、無ければ署名の無い生成した PDF を綴じます（警告が出ます）。添付の行は添付のファイルを綴じます。
   - 提出書類一覧表・申請書・登記事項証明書など、システムの外で用意する書類は、その行の「綴じるファイル」で PDF・PNG・JPEG を足せます（透過のある PNG は綴じられません。JPEG か PDF にしてください）。足したファイルは統合 PDF の中にだけ残り、別の添付にはなりません。
   - 見積もりの大きさと上限（顔写真を含め 25MB。在留申請オンラインシステムの Q&A Q4-2）が出ます。超えそうなときは警告が出ます。超えたときは、添付できる分だけを添付し、残りは「資料添付に係る申告書（参考様式９）」とともに提出します。
   - 健康診断の書類を綴じられるのは、その外国人の担当者と管理者だけです。綴じた PDF は「要配慮の書類を含む」となり、ダウンロードも担当者と管理者だけです。
   - 作った PDF は一覧の下の「提出用の PDF」に残ります（作り直しは新しい行。消せません）。作成・ダウンロードは監査ログに残ります。
   - **提出書類一覧表**（追加。ADR-0033 の追記）: 「提出書類一覧表（表紙・第1〜3表）をシステムで作って先頭に綴じる」に印があると、入管の一覧表に申請人の氏名・所属機関の名称と、行ごとの提出確認欄（有・無）を書いて先頭に綴じます。提出確認欄の初期値は状態から入ります（綴じる書類がある行は「有」、当てはまるが無い行は「無」）。行ごとの「提出確認欄」で直せます。選んだ側に〇が付きます。
   - **システムの外の書類の保存**: 行ごとにファイルを選んで「ファイルを保存」（または「PDF を作る」）すると、その申請（外国人×申請の種類）の下書きに保存され、次に作り直すときもそのまま綴じられます。差し替えるときは、古いファイルの「取り除く」に印を付けて新しいファイルを足します（取り除いたファイルは取消として残ります）。
   - 透過のある PNG・CMYK の JPEG も綴じられます（白の地にした画像にします。画素の数は変えません）。
   - **第2表の書類**: 受入れ機関の「同一年度内に特定技能外国人を受け入れている」の印が有ると、第2表の書類は提出不要として扱います（初期値で印を付けない・綴じると警告）。印は受入れ機関の編集の画面で付けます。台帳に同じ受入れ機関の雇用契約があると、印が初期値として提案されます（台帳の外の外国人もいるので、確かめて保存してください）。
   - 申請人の写真は PDF に入れません（オンラインは JPEG で別に添付、窓口は申請書に貼る）。
7. **受入れ機関の書類を保管する**（追加。ADR-0033 の追記）: 受入れ機関の詳細の「受入れ機関の書類」→「書類を追加」。種類・事業所（協定書・カレンダーは事業所ごと）・対象期間（協定書・カレンダー）・発行日（第2表の証明書）・有効期限・言語（カレンダーは日本語と申請人の言語）・ファイルを入れます。
   - 申請の書類の一覧と提出用の PDF では、雇用契約の事業所と基準日から有効なものが自動で選ばれます（「受入れ機関の書類から」）。期間の外・発行後 3 か月を超える・カレンダーの言語が足りない・既に受け入れている機関の第2表の書類は、警告が出ます。
   - 雇用契約の版に付けた根拠資料（カレンダー・協定書）はそのまま使えます。新しく付けるときは、保管庫に付けてください。
   - 誤って足したら「取消」（理由は必須）。行とファイルは消えずに残ります。
8. **公的義務履行に関する誓約書（第1-26号）**: 申請人に住民税・国民健康保険・国民年金などの滞納がある場合だけ要ります（変更・更新。申請の書類の一覧では「該当するかを確かめてください」と出ます）。行の「生成する」で開き、作成日と理由（納付緩和措置などを申請した日、またはほかのやむを得ない理由）を入れて「検査する」→「生成する」。申請人が印刷したものに手で署名します。一括生成の対象にはなりません。
9. **雇用の経緯に係る説明書（第1-16号）**（段階4 T54。ADR-0043）: 行の「生成する」で開き、職業紹介事業者・取次機関・自国等の機関に支払った費用を入れます（台帳に無い項目。前に作ったときの値、無ければ事前ガイダンスで確かめた費用が初めに入っています）。作成責任者を入れて「検査する」→「生成する」。申請人が署名し、申請人が十分に理解できる言語での記載が要ります（訳を添えるかは人が判断します）。職業紹介事業者の「人材サービス総合サイト」の画面の写しは、システムの外で用意します。
10. **役員に関する誓約書（第1-23号）**（T54）: 受入れ機関の詳細の「役員」で、特定技能外国人の受入れ業務の執行に直接関与しない役員に「受入れ業務の執行に直接関与しない」の印を付けます。印の付いた役員がいると、申請の書類の一覧の行が当てはまり、「生成する」で作れます（印の付いた役員を 8 人まで載せます）。
11. **書類省略に当たっての誓約書（第1-29号）**（T54）: 実績のある機関の書類（第2表の1）の行から「生成する」で作れます（当たるかはシステムでは判断しません）。

## 署名済みの書類を添付する・回収する（段階3。T33）

1. 外国人詳細の「帳票」タブに、生成した帳票ごとの状態（署名待ち・署名済み）が出る。
2. 本人（や受入れ機関）の署名を受けたら、紙をスキャンし、「署名済みの書類を添付」から添付する（署名日は必須）。確認書（事前ガイダンス・生活オリエンテーション）は、記録の画面の確認書の添付にもなる。
3. 生成から一定日数（設定の「自機関」の「署名済み書類の回収のタスクを起票するまでの日数」。既定 14 日）を過ぎても署名済みが無いと、ダッシュボードに「署名済み書類の回収」が出る。添付すると自動で完了する。署名が要らなくなったときは「不要」にする（取消はしない）。
4. 誤って添付したスキャンは、帳票タブ（確認書は記録の画面）から理由をつけて取り消す。署名待ちに戻り、回収のタスクも未着手に戻る。
5. 帳票タブや生成物の画面に「時間がかかっています」と出たら、管理者がジョブの処理（qcluster）が動いているかを確かめる（`docker compose ps`・`make logs`）。必要なら生成し直す。

## 自機関の情報を更新する

- 登録支援機関の登録を更新したら、「設定」→「自機関」→「編集」で登録期限を直します。ダッシュボードの「自機関の登録更新」のタスクは、新しい期限から日次の起票で作られます。
- 食品産業特定技能協議会の構成員証明書を受け取ったら、「設定」→「自機関」→「差し替える」でファイルと有効期限を登録します。古い証明書は消えずに残ります。

## 受入れ機関を登録・更新する

受入れ機関は、左のナビの「受入れ機関」→「受入れ機関を登録」で登録し、詳細の画面の各欄の「追加」「編集」で更新します（担当者・管理者のどちらも行えます）。管理画面（admin）は使いません。

- **基本情報**: 名称・ふりがな（支援計画書に使います）・法人番号・代表者・本店の所在地・電話。法人番号は空白やハイフンつきでも入れられ、検査用数字を確かめます。同じ法人番号は 2 回登録できません。個人事業主には法人番号が無いので、「法人・個人の区別」で個人事業主を選ぶと入力できなくなります。
- **事業所**: 雇用契約の就業の場所です。分野・日本標準産業分類のコード・業務区分（複数）と、雇用条件書の就業の場所の連絡先にする電話番号を入れます。雇用契約が就業の場所にしている事業所は、分野を変えられません。今日有効な版と、これから適用される版（変更日が先の版）が使っている業務区分は外せず、それらの版が使っている間は事業所を無効にもできません（雇用契約を終了するか、別の事業所の版に替わってから行います）。
- **加入状況**: 登録法人（工業製品製造業分野）・協議会（飲食料品製造業分野）への加入を、分野ごとに 1 つ登録します。証明書（協議会の構成員証明書、または登録法人の会員名簿を印刷したもの）を一緒に付けられます。新しい証明書を受け取ったら、加入状況の行の「差し替える」でファイルと有効期限を入れます。古い証明書は残ります。
- **協力確認書**: 受入れ機関が事業所ごとに、事業所の所在地と外国人の住居地の市区町村に出します（同じ市区町村なら 1 通）。出したら「提出を登録」で、事業所・提出先の市区町村・提出日・控えを入れます。住居地の市区町村への提出も、事業所の行で登録します。
  - 有効期限はありません。事業所の所在地・住居地・担当者の連絡先が変わって出し直したら、新しい提出として登録します。前の提出は残ります。事業所の所在地を変えて保存すると、出し直しを促すお知らせが出ます。
  - 詳細の画面の「提出状況」に、事業所ごとの提出先と最新の提出日、または「未提出」が出ます。
- **支援委託契約**: 全部委託の契約を、1 行＝1 期間で登録します。委託料（1 名あたり月額）も入れます。同じ受入れ機関の契約は期間を重ねられません。
  - 契約書の第6条の自動更新で続いたときは、終了日を延ばさずに、更新後の期間を次の契約として登録します（前の期間の記録が残るようにするため。ADR-0015）。
  - 対象の外国人・委託料はまだ持っていません（段階3の T37 で見直します）。
  - **届出のタスク**（ADR-0017）: 支援委託契約の届出は所属機関が外国人ごとに出します（14 日以内）。その受入れ機関と雇用契約が有効な特定技能1号の外国人ごとに、タスクがダッシュボードに出ます。
    - 新しい契約を登録したとき（自社支援や他の登録支援機関からの切替）: 締結日に対象の外国人がいれば、第3-3-2号（締結）と第3-2号（支援計画変更）。最初の契約が在留申請の前なら、対象者がいないので出ません。
    - 次の期間の行（前の行の予定の終了日の翌日から始まる行）: 締結としては出ません。委託料が前の行と違うときだけ、第3-3-1号（変更）が出ます。
    - 同じ行の委託料・期間を直すとき: 実際に契約を変えたなら「契約の変更として届け出る」をチェックして変更日を入れると、第3-3-1号が出ます。入力の誤りの訂正なら、チェックしません。
    - 委託料・期間以外の変更（費用の負担など）は、必要なときに手で起票します。
  - **終了**: 実際に終わったときは、行の「終了を登録」で終了日と事由（大分類・小分類。その他は全角 20 文字以内）を入れます。外国人ごとに第3-3-2号（終了）と第3-2号が出ます。予定の終了日は残ります。
    - 外国人が退職して支援も終わる場合は、ここではなく雇用契約の終了を登録します（第3-1-2号の c 欄で兼ねます。雇用契約終了届出のタスクに c 欄の記入が要ることが出ます）。
    - 予定の終了日を過ぎても、次の期間も終了も登録していないと、「支援委託契約の更新」のタスクに「終了日を過ぎています：次の期間か終了を登録」と出ます。
  - **終了の取消**: 入力の誤りを直すときだけ、管理者が「終了を取り消す」で理由を入れます。未着手の届出タスクはその理由で取消になります。対応中のタスクは残り、「元の事由（支援委託契約の終了）が取り消されました」と表示されるので確かめます。提出済み・完了のタスクにはメモが付きます。
- **添付の取消**: 誤って付けたファイルは、各欄のファイルの横の「取り消す」で理由を入れて取り消します。ファイルは消えずに打ち消しで残ります。

**期限のタスク**
- 加入証明の有効期限（1 か月前から）と支援委託契約の終了日（3 か月前から）のタスクは、保存したときにダッシュボードに出ます（日次の起票と同じタスクで、二重にはなりません）。
  - それより前の期限は、ダッシュボードの「今後の予定（6 か月先まで）」に出ます（タスクになる前の期限。修正 1 回目 A3）。
  - この 2 つのタスクは担当者が空です。担当者で絞ったダッシュボード（自分の担当など）では、「担当者なし（受入れ機関の期限など）」の区分に出ます。
- 証明書を差し替えて有効期限が延びたとき、次の支援委託契約を登録したときは、前の期限のタスクが自動で「完了」になります。理由（例: 「証明書の差し替えにより期限を更新（…。自動）」）がタスクに残り、監査ログで人が完了にしたものと区別できます。
- 期限を早めたり消したりしたときは、未着手のタスクは自動で取消になります。対応中のタスクは動かさないので、保存後のお知らせに従ってダッシュボードで確かめます。
- 協力確認書には期限のタスクがありません。

## 雇用契約を登録・変更・終了する

雇用契約は、外国人詳細の **「契約」タブ** で扱います（担当者・管理者のどちらも行えます。終了の取消は管理者だけ）。管理画面（admin）は使いません。無効化した外国人の契約は見るだけです。

- **契約の登録**: 「雇用契約を登録」で、雇用条件書（参考様式第1-6号）の Ⅰ〜Ⅸ と別紙1（手当・控除）の順に入れます。
  - 事業所は受入れ機関ごとにまとめて出てきます。選んだ事業所の受入れ機関が雇用主になります（派遣は不可）。
  - 締結日はキャリアアッププランの交付の判定（雇用契約の前か）に使います。
  - **雇用条件のひな形を使う**（T41、ADR-0034）: 画面の上の「雇用条件のひな形」で選び、「ひな形から入れる」を押すと、ひな形の値が入ります。ひな形で「外国人ごとに入れる」の印の付いた項目（基本給・契約期間など）は空のまま、画面の先頭の「この外国人ごとに入れる項目」にまとめて出ます。そこだけを入れて保存します。ほかの項目も確かめて、必要なら直してください。保存のときの検査と届出の判定は、ひな形を使わないときと同じです。
- **雇用条件のひな形の登録**: 受入れ機関の詳細の「雇用条件のひな形」→「ひな形を追加」。項目は契約の登録と同じで、すべて任意です。項目ごとの「外国人ごとに入れる」に印を付けます（手当・控除・交代制の行にも付けられます）。賃金の締切日・支払日もひな形に入れられます。
  - ひな形を直しても、登録済みの契約の版は変わりません（値を写すだけです）。使わなくなったひな形は「使う」の印を外します（消しません）。2 版目以降（新しい版）は、ひな形ではなく前の版を写します。
- **条件の変更（新しい版）**: 「新しい版を追加」で、前の版の値と手当・控除・交代制が写った画面が開きます。
  - 変わった所だけを直し、変更日（変更の効力が生じる日）と変更理由を入れます。
  - 変更の無い版は保存できません。前の版は残り、契約タブで変更前・変更後を見比べられます。
  - 変更の内容から、雇用契約変更届出のタスクが起票されます。要否の確認が要るものは、その旨が出ます。
  - 雇用主（受入れ機関）が変わるときは、新しい版ではなく、今の契約の終了と新しい契約の登録で行います。新しい版では、ほかの受入れ機関の事業所は選べません。
- **窓口（Ⅸ４・５）**: 部署名・担当者職氏名・連絡先を分けて入れます（T34。第1-6号の欄どおり）。T34 より前に 1 つの文で入れた版は、新しい版の画面で部署名の欄に写るので、分けて直します。
- **根拠資料**: 「根拠資料を添付」で添付します。種別は、日本人と同等以上の報酬の根拠、変形労働時間制のカレンダー・協定書、別紙2（無期転換後の労働条件）です。
  - 根拠資料は新しい版に写りません。引き続き使う資料は、新しい版に付け直します。新しい版の画面に、前の版の資料が参考として出ます。
- **無期転換**: 同じ雇用主との有期の契約の通算期間が、その契約の期間中に 5 年を超えるときは、「本契約の期間中に無期転換の申込みができる」をチェックし、転換後の労働条件の変更の有無を選びます。
  - 転換の日は、契約の終了日の翌日として表示されます。
  - 変更が「有」なら、別紙2 を添付します。
  - 期間の定めの無い契約（終了日が空）では選べません。
  - システムに登録したこの受入れ機関との契約の合計が 5 年を超えるのにチェックが無いと、警告が出ます。この警告は目安です。技能実習などシステムの外の期間は数えておらず、契約の間の空白期間（クーリング）も判定していません。チェックを付けるかは人が確かめて決めます（ADR-0016）。
- **終了**: 「終了を登録」で、終了日と理由を入れます（その他のときはメモが必須）。雇用契約終了届出（14 日以内）のタスクが出ます。解雇・会社都合とその他の理由では、受入れ困難届出のタスクも出ます。
- **終了の取消**: 入力の誤りを直すときだけ、管理者が「終了を取り消す」で理由を入れて取り消します。起票済みのタスクは、未着手ならその理由で取消になります。対応中のタスクは残り、「元の事由（雇用契約の終了）が取り消されました」と表示されるので、確かめて状態を直します。提出済み・完了のタスクにはメモが付きます。

## 支援記録の運用（段階2）

支援計画と支援の記録は、外国人詳細の **「支援」タブ** にまとめています。タブの中は「計画」「記録」「交付」の 3 つに分かれます。担当者・管理者のどちらも記録できます。無効化した外国人には記録を足せません（見るだけ）。

- **支援計画**: 「計画」→「支援計画を作成」で、自機関の「標準の支援計画」（「設定」→「標準の支援計画」。管理者だけが編集）を写して作ります。受入れ機関ごとに 1 つです（先に雇用契約を登録します）。内容を変えるときは「新しい版を追加」で、変更理由と適用開始日を入れます。前の版は残り、版の一覧で変更前・変更後を見比べられます。
- **定期面談**: ダッシュボードの「定期面談（3か月ごと）」の行の「記録」から入れるのが基本です。1 つの画面で本人との面談・上司との面談の 2 行を入れて保存すると、開いている定期面談のタスクが完了になり、次回のタスクが作られます。次回の期限は「次回面談の予定日」を入れればその日、無ければ実施日から 3 か月後です（法定の 3 か月を超える予定日は入れられません）。方法は「対面」「オンライン」だけで、電話は選べません（オンラインは下の「定期面談のオンライン実施」）。通報の欄は「労働法令違反の疑い」が「あり」のときだけ、通報先・通報日は通報が「要」のときだけ入力できます。T35 からは、本人用・上司用の行それぞれで定期面談報告書の質問（18 問の「問題の有無」と「問題の内容」・⑦ 特筆事項。上司の行は役職・所属部署も）と、組の「⑥ 基準不適合等の有無」（「有り」なら ４ の発生年月日・内容・対応結果）を入れます。問題が無ければ「すべて『問題無』にする」を押してから、問題のある質問だけを直します。違反の疑いが「あり」なら ⑥ は「有り」です。
- **相談・苦情**: 「記録」→「記録する」→「相談・苦情への対応」で受け付けます。その後の対応は相談の画面の「経過を追記」で足し、追記のたびに対応状況（受付／対応中／解決／関係機関へ引継ぎ）を変えられます。相談の一覧（左のナビの「相談」）は、既定で未解決だけを出します。経過の通報先・通報日は「通報」を、相談日は「ハローワーク相談」をチェックしたときだけ入力できます。
- **事前ガイダンス・生活オリエンテーション**: 実施日時（複数回に分けたときは行を足す）・説明した項目のチェックリスト・署名済みの確認書を入れます。必須の項目が未チェックのとき、所要時間が目安（事前ガイダンスは 3 時間）を下回るとき、必要な時間（生活オリエンテーションは 8 時間以上）を満たさないときは警告が出ます。警告が出ても保存はできるので、理由をメモに残します。
- **そのほかの支援**（送迎・住居・公的手続の同行・日本語学習・交流促進・転職支援）: 「記録する」から種別を選んで入れます。方法は、送迎・公的手続の同行は「対面」で固定、ほかは「対面」「オンライン」「電話」から選びます（ADR-0014）。非自発的な離職の転職支援では「離職の区分」が必須です。帳簿（ADR-0036）のために、次の任意の欄があります: 住居の確保の「保証人契約の内容」、日本語学習の「委託先の講師」、交流促進の「実施場所」、転職支援の「実施場所」「転職先候補企業」「通訳人」、相談の受付の「通訳人」。記録の担当者の役職は、保存したときの値が記録に残ります。
- **一括申請の項目**（T46a、ADR-0038）: 外国人詳細の「基本」の「一括申請の項目」に、在日親族・同居者、技能水準・日本語能力（合格証明書を添付できる）、良好に修了した技能実習2号、職歴を「追加」で入れます。出生地・在日親族の有無・職歴の有無・台帳の外の特定技能1号の月数は「編集」で、在留期間（長さ）と技能実習のイ・ロは在留情報の追加で入れます。選択肢は在留申請オンラインの一括登録用ツールの表のとおりです。住所は保存のときに都道府県・市区町村に分けられ、分けられないと印が出ます（住所の書き方を確かめてください）。行の誤りは「履歴」タブで取り消して入れ直します。
- **受入れ機関の一括申請の項目**（T46b、ADR-0038）: 受入れ機関の詳細の「一括申請の項目」に、業種・資本金（「編集」）、申告の新しい版（区分V の (11)〜(32) と第1-11-1号 ３ の人数。前の版は残ります）、決算（年度ごと。誤りは取り消して入れ直す）、役員（退任したら退任日を入れる）、申請担当者（一括申請の代理人）を入れます。事業所の編集で、常勤職員数・雇用保険適用事業所番号・労働保険番号・保険の適用を入れます。自機関の法人番号・雇用保険適用事業所番号・役員は設定の「自機関」、取次者になる担当者の印とメールは設定の「担当者」で入れます。
- **第1-11-1号 特定技能所属機関概要書**: 申請の書類の一覧の第2表の行の「生成」から作ります。役員・決算・申告の人数は受入れ機関の台帳から入り、足りなければ警告が出ます（受入れ機関の詳細で入れてから作り直します）。役員が 5 人を超えるときは「別紙のとおり」と書いて一覧を添付します。
- **本人の申出で実施しなかった支援**: 本人から支援を受けない旨の申出があったときは、その種別の記録で「本人の申出により実施しなかった」にチェックし、申出の内容と理由を内容の欄に書きます（本体 印刷163「記録として保管しておく必要」）。この記録は定期届出の実施日には数えません（定期面談・相談の行では選べません）。
- **帳簿の保存義務の満了日（目安）**: 外国人詳細の「基本」に、最後の雇用契約の終了の日から 1 年の日が出ます（ADR-0036）。期間の定めの無い契約が続いているとき・契約が無いときは「まだ決まらない」です。システムは記録を消さないので、この日を過ぎても記録は残ります。
- **交付**: キャリアアッププラン（飲食料品製造業分野。雇用契約の前に交付）・実務経験証明書・支援計画書の写しなどを本人に渡したら、「交付」に交付日・方法と署名済みの控え（または受領の記録）を入れます。控えが無いもの、交付が遅れているものは一覧に印が出ます。
- **第4-3号（特異事案報告）のタスク**: 定期面談・相談の経過で「通報」を、定期面談で「⑥ 基準不適合等」を「有り」に、相談の経過で「ハローワーク相談」を、転職支援で「非自発的」を記録すると、第4-3号の届出タスクが期限（事由の日から 14 日）つきでダッシュボードに出ます。同じ日の事由（同じ面談の「通報」と「⑥」も）は 1 つのタスクにまとまります。タスクの詳細から元の面談と、その面談の報告書（第5-5号・第5-6号）へ辿れます。報告書は「紐づける」で添付のセットに入れます（別冊 34頁「問題の認められた報告書は写しを添付」）。
- 証跡（写真・署名の入った紙など）は、記録の詳細の「添付を追加」で PDF・PNG・JPEG（10 MB まで）を足します。健康診断の書類は、ここではなく下の「要配慮添付」の手順で入れます。

記録の閲覧・作成・取消はすべて監査ログに残ります（「支援」タブを開いたことも閲覧として残ります）。

## 支援記録の訂正の仕方

支援計画・支援の記録・交付記録は上書きしません。誤りは **取り消して、正しい内容で新しく記録** します。取消には理由が必須で、取り消した行は打ち消し線を付けて一覧に残り、集計には含めなくなります。取消は元に戻せません。

| 誤ったもの | 直し方 |
|---|---|
| 支援計画の内容 | 「新しい版を追加」（変更理由は必須）。版は削除・変更できません |
| 送迎・住居などの記録 | 記録の詳細 →「取り消す」（理由）→ 正しい内容で「記録する」 |
| 定期面談 | 記録の詳細の「面談を表示」→「取り消す」。本人用・上司用の 2 行がまとめて取り消されます。次回のタスクが未着手のまま、かつ完了にしたタスクが完了のままなら、完了にしたタスクは自動で未着手に戻り、次回のタスクは取り消されます。どちらかの状態を変えていればタスクは動かないので、画面の案内に従ってダッシュボードで手で直します。その後、面談を記録し直します |
| 相談の内容・対応状況 | 経過は追記だけです。誤りは「経過を追記」で訂正の旨を書き、正しい対応状況を選びます。受付そのものが誤り（別の人の相談だった等）のときだけ、相談の画面の「取り消す」で相談ごと取り消します（経過は残ります） |
| 事前ガイダンス・生活オリエンテーション | 詳細 →「取り消す」→ 新しく記録します。実施日時・チェックリスト・添付は取り消した記録に残ります。署名済みの確認書を後から受け取ったときは、取り消さずに「署名済みの確認書を添付」で足します |
| 交付記録 | 詳細 →「取り消す」→ 新しく記録します。控えを後から受け取ったときは、取り消さずに「添付を追加」で足します |
| 添付のファイル | 添付の「取り消す」。ファイルは削除せず、打ち消し線を付けて残し、証跡として扱わなくなります。正しいファイルを添付し直します |

- 通報・ハローワーク相談・非自発的な転職支援の記録を取り消すと、第4-3号のタスクからその記録への参照が外れます（監査ログに残ります）。ほかの記録の参照が残っていればタスクはそのまま、参照が無くなってタスクに手が付いていなければ自動で取消、手が付いていれば画面の案内に従って手で直します。
- 取消と記録し直しは、監査ログで「誰が・いつ・何を・理由」を追えます。

## 要配慮添付（健康診断の書類）の扱い

健康診断個人票（参考様式第1-3号。日本語訳を含む）・受診者の申告書・医師の意見書は **要配慮個人情報** です。ほかの添付より一段重く扱います（ADR-0011）。

1. **入れる場所**: 外国人詳細の「基本」タブ →「健康診断の書類」→「追加」（モーダルで開きます。申請の書類の一覧の健康診断の行の「添付」からも入れられます）。受診日は必須です（中身の所見は入れません）。種別を選ぶと要配慮の印が自動で付きます。健康診断の書類を、ほかの種別（支援の証跡・交付の控えなど）で添付しないでください（要配慮の印が付かず、誰でもダウンロードできてしまいます）。誤って入れたら、その添付を取り消し、管理者に連絡します。
2. **見られる人**: ダウンロードできるのは、その外国人の担当者（担当者のログインユーザー）と管理者だけです。ほかの人には種別と登録日だけが出て、ファイル名もリンクも出ません。URL を直接開いても 403 になり、監査ログに「ダウンロードの拒否」が残ります。
3. **担当者を替えたとき**: 判定はダウンロードの時点の担当者で行うので、前の担当者はダウンロードできなくなります。担当者にログインユーザーが無い外国人の書類は、管理者だけがダウンロードできます。
4. **ファイル名**: ファイル名は監査ログ・通知文・管理画面に出しません。ファイル名に病名や検査結果を入れないでください（ダウンロードした人の手元には残るため）。
5. **手元に残さない**: ダウンロードしたファイルは、申請に使ったら端末から消します。メールに添付して送らないでください。
6. **保持期限の目安**: 添付するときに「保持期限の目安」を入れておくと、過ぎたものに「目安を過ぎています」と出ます。自動では削除しません。削除の時期と手順は、運用で決めてから別のタスクにします（それまでは取消で残す）。
7. **管理画面**: 管理画面（admin）でも、要配慮の添付はファイル名とダウンロードのリンクを出しません。
8. **本番の保存先**: 保存時暗号化と、オブジェクトへの匿名のアクセスの拒否を、本番準備で確かめます（`docs/tasks-phase1.md` の本番準備）。

### システムでの記録の仕方

1. **本人の同意**: 支援計画の版の「定期面談の実施方法についての本人の希望」を「オンライン」にします（計画書のⅣ9 の欄に当たります）。署名済みの計画書は「交付」に「支援計画書の写し」として、交付日と署名済みの控えを入れます。この 2 つで「計画書の欄の記載と署名で確認した」ことを示します。実施中の計画をオンラインに切り替えるときも新しい版で希望を「オンライン」にします（入管への変更の届出は不要。変更理由に「本人の同意によりオンライン面談に切り替え」と書きます）。
2. **上司の同意**: 同意の書面（任意の様式）をスキャンし、その上司との最初のオンライン面談の画面の「上司のオンライン面談の同意の書面」に添付します（T44。添付の種別は「オンラインの定期面談の上司（監督者）の同意の書面」）。本文に「同意日・同意した人」を書きます。上司との面談をオンラインで記録して、その日までの上司との面談のどれにも同意の書面が無いと、面談の詳細に警告が出ます（2 回目からは添付しなくてよい）。紙の原本は帳簿書類として保存します。
3. **面談の記録**: ダッシュボードの「記録」から、本人・上司の行のそれぞれで方法「オンライン」を選び、「オンライン会議の URL」に使った会議の URL を入れます（電話は選べません）。本文には、第三者がいないことを確かめた方法（部屋全体を映した・イヤホン無し等）を書きます。
4. **対面に戻す**: 本人が対面を希望したら、計画の新しい版で希望を「対面」にし、次回から方法「対面」で記録します。問題や第三者の介入が疑われたときは、その面談を記録したうえで、すぐに対面の面談を行い、もう 1 組記録します（次回のタスクは後の面談の日から数え直されます）。
5. **録画**: 録画のファイルはシステムに添付できません（添付は PDF・PNG・JPEG の 10 MB まで）。自機関の管理する保存先に、外国人・面談の日が分かる名前で保存し、雇用契約の終了の日から 1 年以上残します。面談の詳細に、録画と同意の書面を保管する日（雇用契約の終了の日から 1 年。終了日が決まっていなければその旨）が出ます。T35 からは、オンラインの行の「録画の保存先」に保存先を入れます（必須）。支援計画の実施方法にオンラインが無いのにオンラインで記録すると、面談の詳細に注意が出ます。
6. **年 1 回の対面・初回の対面**: システムは警告を出しません。担当者が記録の一覧（方法の列）で確かめます。

録画を消してよい日の管理（削除の手順）は、社内規程の決定とあわせて行います（ADR-0036 の決定 5。本番準備か段階5）。

## 一括申請（在留申請オンラインの一括登録用ツール。段階4 T48）

在留申請オンラインの一括申請（認定・更新・変更）の Excel（入管のマクロつきのツールに値を入れたもの）を作ります。CSV は、ツールのマクロで作ります（システムは CSV を作りません。ツールが出した CSV 以外は使えない・CSV を編集しない）。

1. **前もって**: 取次者になる担当者に、設定の「担当者」で「在留申請オンラインシステムの利用者」の印と登録したメールアドレスを入れます。受入れ機関の詳細の「一括申請の項目」（業種・資本金・決算・申告の版・申請担当者）、事業所（常勤職員数・保険）、外国人詳細の「一括申請の項目」（出生地・在日親族・試験・職歴など）を入れておきます。
2. **作る**: ナビの「一括申請」→「一括申請を作る」で、手続（認定・更新・変更）・基準日・取次者を選びます。
3. **外国人を追加**: 「外国人を追加」で選びます（無効化していない・雇用契約のある人）。
4. **申請ごとの入力**: 行の「入力」で、配偶者・職業・希望する在留期間・理由・受領方法・主たる職種などを入れます。前の一括申請の答えが初めに入っています。犯罪を理由とする処分の欄は、その外国人の担当者と管理者にだけ出ます。
5. **検査**: 行ごとに、ツールのマクロの入力チェックを写した検査の結果が出ます。「不足 n 件」を開いて、台帳か入力を直します。
6. **作る**: 不足が無くなったら「Excel を作る」。300 人を超えると、300 人ごとのファイルに分かれます。
7. **CSV を作る**（Windows の Excel）: 「記入済み（編集用）」をダウンロードして開き、マクロを有効にします。メニューの在留資格には「特定技能」が入っています。「選択」を押してから「出力」を押すと CSV ができます（「選択」を押さないと「出力」できません）。エラーが出たら、エラーシートの内容をシステムの台帳か入力で直して、作り直します。
8. **上げる**: できた CSV を、編集せずに在留申請オンラインシステムにアップロードします。添付の書類は、外国人ごとの「提出用の PDF」を使います。一括申請の行の「申請の書類の一覧」「提出用の PDF を作る」から、同じ手続・基準日で開けます。外国人の申請の書類の一覧にも、その外国人を入れた一括申請が出ます（T49）。

## 一括届出（電子届出の一括申込用ツール。段階4 T50）

電子届出システムで、複数人の随時届出（雇用契約・支援計画変更・支援委託契約・受入れ困難・基準不適合・支援計画の実施困難）と特異事案報告（第4-3号）をまとめて出すための Excel（入管の一括申込用ツールに値を入れたもの）を作ります。CSV はツールのマクロで作ります（システムは CSV を作りません）。

1. **作る**: ナビの「一括届出」→「一括届出を作る」で、届出（第3-1号〜第4-3号）と受入れ機関を選びます（第4-3号は自機関の報告なので受入れ機関は選びません）。届出機関の欄（法人番号・名称・住所）は受入れ機関（第4-3号は自機関）の台帳から入ります。
2. **届出タスクを追加**: 「届出タスクを追加」で、その届出に当たる未着手・対応中の届出タスク（同じ受入れ機関のもの）を選びます。雇用契約の変更は、変更事項ごとに 1 行になります（同じ人を繰り返す）。
3. **届出の内容**: 行の「入力」で、届出の内容（事由・変更事項・変更後の内容・事案の概要・措置内容など）を確かめて直します。届出タスクの起算日・事由・終了理由から初めの値が入っています。「推定: 要確認」の印の値（第3-2号の中分類、第4-3号の区分）は必ず確かめます。外国人・届出機関・登録支援機関の欄は台帳から入るので、台帳で直します。見出しに「全角、２０文字以内」などとある欄は、超えると警告が出ます。
4. **検査**: 行ごとに、ツールのマクロの入力チェックを写した検査の結果が出ます。不足を直してから「Excel を作る」を押します。1 つのファイルには様式の番号の付いた行（20〜22 行）まで入り、超えるとファイルが分かれます。
5. **CSV を作る**（Windows の Excel）: 「記入済み（編集用）」をダウンロードして開き、マクロを有効にして「実行」を押し、出力先を選びます。マクロは、実行した日より後の日付をエラーにします。エラーが出たら「エラー箇所詳細情報」シートの内容を、システムの台帳か行の入力で直して作り直します（Excel で直したときは、システムにも同じ直しを入れます）。
6. **申し込む**: 電子届出システムに**受入れ機関の利用者 ID でログイン**し（第4-3号は自機関の ID）、手続を選び、「添付（複数人の場合）」を選んで、できた CSV を編集せずに専用の「添付ファイル」ボタンから添付します。届出機関の情報は、ログインした機関の登録の情報が出ます。登録支援機関の ID で所属機関の届出を代わりに出せるかは未確認です（ADR-0040 の未確認の点）。
7. **提出を記録する**: 申し込んだら、一括届出の画面の「提出」で申込の日と受理番号を入れて「提出を記録する」を押します。行のすべての届出タスクが提出済みになり、受理番号が入ります（記録した後は行を直せません）。
8. **届出タスクから始める**: 届出タスクの画面の「一括届出に入れる」でも、同じ受入れ機関・同じ届出の作成中の一括届出に入れられます（無ければ新しく作ります）。届出タスクの画面には、そのタスクを入れた一括届出が出ます。
9. **使い分け**: 届出が 1 人だけのときは、一括届出にせず、電子届出の画面で「画面入力」を選んで入力し、届出タスクの「状態を変える」で提出済みにします。2 人以上は一括届出の Excel を使います。定期届出は、届出タスク「定期届出（所属機関）」の画面から定期届出の様式の画面へ行けます。

## 定期届出の様式を作る（第3-6号・別紙1・別紙2。段階4 T51）

全部委託の受入れ機関の定期届出（毎年4月1日〜5月31日。前年度分）の添付書類を作ります。

1. **作る**: 受入れ機関の詳細の「定期届出（第3-6号）」→「定期届出の様式を作る」。年度（4月1日から翌年3月31日）を入れて「検査する」を押すと、期間中に支援した外国人・事業所・担当者が出ます。「推定: 要確認」（受入れ開始日を雇用契約の開始日で代えた・担当者の履歴の推定）を確かめます。
2. **第4-3号の候補**: 期間中の通報・ハローワーク相談・転職支援などの候補と、第4-3号の届出タスクとの照合の結果が出ます。必要な報告を出していない人がいれば、別紙1 の「随時届出（報告）の提出状況」に印を付け、理由書を添付します（システムは印を付けません）。
3. **生成する**: 第3-6号・別紙1（事業所ごと・5 人ごと）・別紙2 ができます。生成物の画面から PDF と「記入済み（編集用）」の xlsx をダウンロードできます（ダウンロードは監査ログに残ります）。
4. **受入れ機関に記入してもらう**: 記入済みの xlsx を受入れ機関に渡し、第3-6号の ４ 労働条件等（平均）・６ 備考・担当者、別紙1 の活動日数・報酬の支給総額・支払方法を記入してもらいます。報告対象の人数は、システムの台帳の外国人（自機関が支援した 1号）だけを数えています。ほかの外国人（自社支援・ほかの登録支援機関・2号）がいれば直してもらいます。
5. **署名**: 別紙2 に受入れ機関と自機関（登録支援機関）が署名し、スキャンします。
6. **提出**: 受入れ機関が自分の利用者 ID で電子届出システムにログインし、定期届出を画面で入力して、別紙1・別紙2 のスキャンなどを添付します。

## 一括の Excel を入管のツールで確かめる（価値検証。段階4）

段階4で作る一括申請・一括届出の Excel（値を入れた xlsm）は、入管のツール（マクロつきのブック）そのものです。CSV は、ツールのマクロで作ります（ツールが出した CSV 以外は使わない・CSV を編集しない。操作マニュアルの定め）。MVP 完成後の価値検証で、認定・変更・更新と随時届出の各 1 件を、次の手順で確かめます（`docs/tasks-phase4.md` の D2・D4）。細かな手順は、段階4の実装（T48・T50）で直します。

1. **Windows の Excel を用意する**: 入管は Microsoft 365 Apps を推奨しています。マクロは Windows の部品（ADODB・FileSystemObject など）を使うので、Mac の Excel では動かないことがあります。ファイルは OneDrive ではなく、パソコンのローカルディスクに保存します。
2. **開いてマクロを有効にする**: システムからダウンロードした xlsm を開き、上の黄色の帯の「コンテンツの有効化」（マクロの有効化）を押します。ダウンロードしたファイルでマクロが止められているときは、ファイルのプロパティで「許可する」に印を付けてから開き直します。
3. **数式を確かめる（在留申請）**: 入力シートの A 列（行の番号）が、値を入れた行だけに 1, 2, 3 … と出ていることを確かめます（開いたときに計算し直されて、システムが書いた結果と同じになること）。
4. **CSV を出す**:
   - 在留申請: メニューのシートで在留資格が「特定技能 Specified Skilled Worker」になっていることを確かめ、「選択」→ 入力シートの値を確かめる → メニューの「出力」（申請情報一括登録ファイル出力）。エラーがあれば「エラー」シートに出て、セルが赤くなります。
   - 電子届出: 入力シートの「実行」を押し、出力先のフォルダを選びます。エラーがあれば「エラー箇所詳細情報」シートに出て、セルが黄色になります。
5. **結果を記録する**: CSV が出たか、入力チェックのエラーの有無、A 列の数式の結果を、価値検証の記録に書きます。エラーがあれば、エラーのシートの内容を写して開発に渡します（CSV は直さない）。
6. **取り込む**: 在留申請オンラインシステムの一括申請、または電子届出システムの申込画面の「添付（複数人の場合）」に CSV を付けます（入管システムへの取込は、価値検証の中で行う）。
