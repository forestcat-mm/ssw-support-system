# 管理者向けの運用手順

日常の設定は、業務画面の左のナビの **「設定」**（管理者だけに表示）で行います。管理画面（admin）を開く必要はありません。

- どの操作も監査ログに残ります（「設定」→「監査ログ」で検索できます）。
- ユーザー・担当者・事務所・外国人は削除しません。やめるときは「無効化」「有効を外す」で残します。
- 本番では、ここに書いたコマンドはサーバーの管理者が実行します（`docker compose exec web ...`）。

## 管理者は 2 人以上置く

管理者が 1 人だけだと、その人が端末をなくしたり休んだりしたときに、ほかの人の MFA リセットやロック解除ができなくなります。

- 管理者ロールのユーザーを、常に 2 人以上にしておきます。
- 最後の管理者は無効化できないようになっています（「最後の管理者は無効化できません」と出ます）。

## 担当者を迎える（招待）

1. 「設定」→「担当者」→「担当者を追加」で、氏名・常勤区分・事務所・役割（支援責任者／支援担当者）・対応言語・養成講習修了日を入れて保存します。
2. 「設定」→「ユーザー」→「ユーザーを招待」で、ユーザー名・メールアドレス・氏名・ロールを入れます。「担当者」に 1. の人を選ぶと紐づきます。
3. 本人に招待メールが届きます。本人がリンクからパスワードを設定し、初回ログインで二要素認証（認証アプリ）と回復用コードを設定します。
4. 招待メールの期限が切れたときは、そのユーザーの画面の「招待の再送」で送り直します（前のリンクは使えなくなります）。

ロールを後から変えるときは、管理画面のユーザー（`/admin/core/user/`）で行います（開発者向けの操作。日常的には使いません）。

## 担当者が退職したとき

ユーザーと担当者は連動しないので、両方を行います。

1. 「設定」→「ユーザー」→ その人 →「ユーザーの無効化」。すぐにログアウトされ、ログインできなくなります。
2. 「設定」→「担当者」→ その人 →「有効」のチェックを外して保存します。
3. 引き継ぎ:
   - 外国人台帳で担当者をその人に絞り、各外国人の「編集」で担当者を替えます。
   - ダッシュボードで担当者をその人に絞り、各届出タスクの「担当者・メモ」で担当者を替えます。

## 端末（スマートフォン）をなくしたとき

1. **本人が回復用コードを持っている**: ログイン画面の「6 桁のコード または 回復用コード」の欄に回復用コードを入れてログインできます（1 つのコードは 1 回だけ）。新しい端末で認証アプリを使えるようにするには、2. の二要素認証のリセットを管理者に頼みます。
2. **回復用コードも無い**: 管理者が「設定」→「ユーザー」→ その人 →「二要素認証のリセット」を行います。本人は次のログインで二要素認証を設定し直します。
3. **管理者全員がログインできない（最後の手段）**: サーバーで次のコマンドを実行します。
   ```
   docker compose exec web python manage.py reset_mfa <ユーザー名>
   ```
   漏洩が疑われるときは、全員をリセットします（`reset_mfa --all --yes`）。

## ログインがロックされたとき

パスワードを続けて間違えると、そのユーザー名でのログインが一定時間止まります（既定は 5 回で 30 分。`AUTH_LOCKOUT_FAILURE_LIMIT`・`AUTH_LOCKOUT_MINUTES`）。

1. 「設定」→「ユーザー」で「ロック中」と出ているユーザーを開きます。
2. 「ロック解除」→「ロックを解除する」。すぐにもう一度ログインできます。
3. 本人がパスワードを忘れているときは、ログイン画面の「パスワードを忘れた場合」から本人が再設定します（T25）。
   - 登録しているメールアドレスにリンクが届きます（60 分以内に 1 回だけ使える）。二要素認証（認証アプリ・回復用コード）は変わりません。
   - 再設定してもロックは解除されません。ロック中なら、完了の画面に解けるまでの分が出ます。急ぐときは上の手順で解除します。
   - 再設定が終わると、本人に「パスワードが変更されました」のメールが届きます。心当たりのない変更の連絡を受けたら、監査ログの「パスワードの再設定」「パスワードの再設定の申請」を操作者・接続元 IP で確認します。
   - メールはジョブで送ります。届かないときは、`qcluster` が動いているか（`docker compose ps`）と、メールアドレスの登録を確認します。同じユーザーへのリンクは 10 分に 1 通まで、同じ接続元からの申請は 1 時間に 10 回までです。
   - それでも届かないときの予備として、サーバーの管理者が次のコマンドで仮のパスワードを設定し、本人に安全な方法で伝えることもできます。本人はログイン後、管理画面の右上の「パスワードの変更」（`/admin/password_change/`）で自分のパスワードに変えます。
   ```
   docker compose exec web python manage.py changepassword <ユーザー名>
   ```

心当たりのない失敗が続いているときは、監査ログと「設定」→「監査ログ」の操作者・期間で確認し、必要なら開発者に連絡します。

## 誤って無効化した外国人を戻す

1. 「外国人台帳」で「無効化済みを含む」にチェックを入れて絞り込み、その外国人を開きます。
2. 上部の無効化のお知らせにある「無効化を外す」を押し、理由を入れて実行します。監査ログには、元の無効化の理由と外した理由の両方が残ります。
3. 無効化のときに取り消された在留情報・旅券は戻りません。「基本」タブの各「追加」から、新しい行として登録し直します。
4. 取消になった届出タスクも戻りません。
   - 日付で起票されるもの（在留期間更新・旅券更新の確認・雇用契約の期間満了確認）は、翌朝 6:00 の日次の起票で起票し直されます。すぐに必要なら `make filings` を実行します。
   - それ以外（雇用契約の変更・終了の届出など）は、外国人詳細の「届出」タブの「届出を起票」で手で起票します。

## 年に 1 回（年末まで）: 祝日の更新

届出の期限は、行政機関の休日（土日・祝日・年末年始）に当たると翌開庁日に繰り延べます。祝日は jpholiday というライブラリから取るため、翌年の祝日が入った版に更新します。

1. jpholiday の新しい版を確認し、`backend/pyproject.toml` の `jpholiday==` を更新して `make lock` → `make build` を実行します。
2. 翌年の祝日の一覧を出し、内閣府の「国民の祝日について」と照らし合わせます（法改正や特例の祝日を含む）。
   ```
   docker compose exec web python -c "import jpholiday; [print(d, n) for d, n in jpholiday.year_holidays(2027)]"
   ```
3. `make test` を実行し、期限の計算のテストが通ることを確かめます。

## 自機関の情報を更新する

- 登録支援機関の登録を更新したら、「設定」→「自機関」→「編集」で登録期限を直します。ダッシュボードの「自機関の登録更新」のタスクは、新しい期限から日次の起票で作られます。
- 食品産業特定技能協議会の構成員証明書を受け取ったら、「設定」→「自機関」→「差し替える」でファイルと有効期限を登録します。古い証明書は消えずに残ります。

## 受入れ機関を登録・更新する

受入れ機関は、左のナビの「受入れ機関」→「受入れ機関を登録」で登録し、詳細の画面の各欄の「追加」「編集」で更新します（担当者・管理者のどちらも行えます）。管理画面（admin）は使いません。

- **基本情報**: 名称・ふりがな（支援計画書に使います）・法人番号・代表者・本店の所在地・電話。法人番号は空白やハイフンつきでも入れられ、検査用数字を確かめます。同じ法人番号は 2 回登録できません。個人事業主には法人番号が無いので、「法人・個人の区別」で個人事業主を選ぶと入力できなくなります。
- **事業所**: 雇用契約の就業の場所です。分野・日本標準産業分類のコード・業務区分（複数）を入れます。雇用契約が就業の場所にしている事業所は、分野を変えられません。今日有効な版と、これから適用される版（変更日が先の版）が使っている業務区分は外せず、それらの版が使っている間は事業所を無効にもできません（雇用契約を終了するか、別の事業所の版に替わってから行います）。
- **加入状況**: 登録法人（工業製品製造業分野）・協議会（飲食料品製造業分野）への加入を、分野ごとに 1 つ登録します。証明書（協議会の構成員証明書、または登録法人の会員名簿を印刷したもの）を一緒に付けられます。新しい証明書を受け取ったら、加入状況の行の「差し替える」でファイルと有効期限を入れます。古い証明書は残ります。
- **協力確認書**: 受入れ機関が事業所ごとに、事業所の所在地と外国人の住居地の市区町村に出します（同じ市区町村なら 1 通）。出したら「提出を登録」で、事業所・提出先の市区町村・提出日・控えを入れます。住居地の市区町村への提出も、事業所の行で登録します。
  - 有効期限はありません。事業所の所在地・住居地・担当者の連絡先が変わって出し直したら、新しい提出として登録します。前の提出は残ります。事業所の所在地を変えて保存すると、出し直しを促すお知らせが出ます。
  - 詳細の画面の「提出状況」に、事業所ごとの提出先と最新の提出日、または「未提出」が出ます。
- **支援委託契約**: 全部委託の契約を、1 行＝1 期間で登録します。同じ受入れ機関の契約は期間を重ねられません。
  - 契約書の第6条の自動更新で続いたときは、終了日を延ばさずに、更新後の期間を次の契約として登録します（前の期間の記録が残るようにするため。ADR-0015）。
  - 対象の外国人・委託料はまだ持っていません（段階3の T37 で見直します）。
  - 支援委託契約の締結・変更・終了の届出（第3-3-1号・3-3-2号）のタスクは、まだ自動では作られません（T28c）。必要なときは届出タスクを手で起票します。
- **添付の取消**: 誤って付けたファイルは、各欄のファイルの横の「取り消す」で理由を入れて取り消します。ファイルは消えずに打ち消しで残ります。

**期限のタスク**
- 加入証明の有効期限（1 か月前から）と支援委託契約の終了日（3 か月前から）のタスクは、保存したときにダッシュボードに出ます（日次の起票と同じタスクで、二重にはなりません）。
- 証明書を差し替えて有効期限が延びたとき、次の支援委託契約を登録したときは、前の期限のタスクが自動で「完了」になります。理由（例: 「証明書の差し替えにより期限を更新（…。自動）」）がタスクに残り、監査ログで人が完了にしたものと区別できます。
- 期限を早めたり消したりしたときは、未着手のタスクは自動で取消になります。対応中のタスクは動かさないので、保存後のお知らせに従ってダッシュボードで確かめます。
- 協力確認書には期限のタスクがありません。

## 支援記録の運用（段階2）

支援計画と支援の記録は、外国人詳細の **「支援」タブ** にまとめています。タブの中は「計画」「記録」「交付」の 3 つに分かれます。担当者・管理者のどちらも記録できます。無効化した外国人には記録を足せません（見るだけ）。

- **支援計画**: 「計画」→「支援計画を作成」で、自機関の「標準の支援計画」（「設定」→「標準の支援計画」。管理者だけが編集）を写して作ります。受入れ機関ごとに 1 つです（先に雇用契約を登録します）。内容を変えるときは「新しい版を追加」で、変更理由と適用開始日を入れます。前の版は残り、版の一覧で変更前・変更後を見比べられます。
- **定期面談**: ダッシュボードの「定期面談（3か月ごと）」の行の「記録」から入れるのが基本です。1 つの画面で本人との面談・上司との面談の 2 行を入れて保存すると、開いている定期面談のタスクが完了になり、次回のタスクが作られます。次回の期限は「次回面談の予定日」を入れればその日、無ければ実施日から 3 か月後です（法定の 3 か月を超える予定日は入れられません）。方法は「対面」「オンライン」だけで、電話は選べません（オンラインは下の「定期面談のオンライン実施」）。通報の欄は「労働法令違反の疑い」が「あり」のときだけ、通報先・通報日は通報が「要」のときだけ入力できます。
- **相談・苦情**: 「記録」→「記録する」→「相談・苦情への対応」で受け付けます。その後の対応は相談の画面の「経過を追記」で足し、追記のたびに対応状況（受付／対応中／解決／関係機関へ引継ぎ）を変えられます。相談の一覧（左のナビの「相談」）は、既定で未解決だけを出します。経過の通報先・通報日は「通報」を、相談日は「ハローワーク相談」をチェックしたときだけ入力できます。
- **事前ガイダンス・生活オリエンテーション**: 実施日時（複数回に分けたときは行を足す）・説明した項目のチェックリスト・署名済みの確認書を入れます。必須の項目が未チェックのとき、所要時間が目安（事前ガイダンスは 3 時間）を下回るとき、必要な時間（生活オリエンテーションは 8 時間以上）を満たさないときは警告が出ます。警告が出ても保存はできるので、理由をメモに残します。
- **そのほかの支援**（送迎・住居・公的手続の同行・日本語学習・交流促進・転職支援）: 「記録する」から種別を選んで入れます。方法は、送迎・公的手続の同行は「対面」で固定、ほかは「対面」「オンライン」「電話」から選びます（ADR-0014）。非自発的な離職の転職支援では「離職の区分」が必須です。
- **交付**: キャリアアッププラン（飲食料品製造業分野。雇用契約の前に交付）・実務経験証明書・支援計画書の写しなどを本人に渡したら、「交付」に交付日・方法と署名済みの控え（または受領の記録）を入れます。控えが無いもの、交付が遅れているものは一覧に印が出ます。
- **第4-3号（特異事案報告）のタスク**: 定期面談・相談の経過で「通報」を、相談の経過で「ハローワーク相談」を、転職支援で「非自発的」を記録すると、第4-3号の届出タスクが期限（事由の日から 14 日）つきでダッシュボードに出ます。同じ日の事由は 1 つのタスクにまとまります。
- 証跡（写真・署名の入った紙など）は、記録の詳細の「添付を追加」で PDF・PNG・JPEG（10 MB まで）を足します。健康診断の書類は、ここではなく下の「要配慮添付」の手順で入れます。

記録の閲覧・作成・取消はすべて監査ログに残ります（「支援」タブを開いたことも閲覧として残ります）。

## 支援記録の訂正の仕方

支援計画・支援の記録・交付記録は上書きしません。誤りは **取り消して、正しい内容で新しく記録** します。取消には理由が必須で、取り消した行は打ち消し線を付けて一覧に残り、集計には含めなくなります。取消は元に戻せません。

| 誤ったもの | 直し方 |
|---|---|
| 支援計画の内容 | 「新しい版を追加」（変更理由は必須）。版は削除・変更できません |
| 送迎・住居などの記録 | 記録の詳細 →「取り消す」（理由）→ 正しい内容で「記録する」 |
| 定期面談 | 記録の詳細の「面談を表示」→「取り消す」。本人用・上司用の 2 行がまとめて取り消されます。次回のタスクが未着手のまま、かつ完了にしたタスクが完了のままなら、完了にしたタスクは自動で未着手に戻り、次回のタスクは取り消されます。どちらかの状態を変えていればタスクは動かないので、画面の案内に従ってダッシュボードで手で直します。その後、面談を記録し直します |
| 相談の内容・対応状況 | 経過は追記だけです。誤りは「経過を追記」で訂正の旨を書き、正しい対応状況を選びます。受付そのものが誤り（別の人の相談だった等）のときだけ、相談の画面の「取り消す」で相談ごと取り消します（経過は残ります） |
| 事前ガイダンス・生活オリエンテーション | 詳細 →「取り消す」→ 新しく記録します。実施日時・チェックリスト・添付は取り消した記録に残ります。署名済みの確認書を後から受け取ったときは、取り消さずに「署名済みの確認書を添付」で足します |
| 交付記録 | 詳細 →「取り消す」→ 新しく記録します。控えを後から受け取ったときは、取り消さずに「添付を追加」で足します |
| 添付のファイル | 添付の「取り消す」。ファイルは削除せず、打ち消し線を付けて残し、証跡として扱わなくなります。正しいファイルを添付し直します |

- 通報・ハローワーク相談・非自発的な転職支援の記録を取り消すと、第4-3号のタスクからその記録への参照が外れます（監査ログに残ります）。ほかの記録の参照が残っていればタスクはそのまま、参照が無くなってタスクに手が付いていなければ自動で取消、手が付いていれば画面の案内に従って手で直します。
- 取消と記録し直しは、監査ログで「誰が・いつ・何を・理由」を追えます。

## 要配慮添付（健康診断の書類）の扱い

健康診断個人票（参考様式第1-3号。日本語訳を含む）・受診者の申告書・医師の意見書は **要配慮個人情報** です。ほかの添付より一段重く扱います（ADR-0011）。

1. **入れる場所**: 外国人詳細の「基本」タブ →「健康診断の書類」→「健康診断の書類を添付」。種別を選ぶと要配慮の印が自動で付きます。健康診断の書類を、ほかの種別（支援の証跡・交付の控えなど）で添付しないでください（要配慮の印が付かず、誰でもダウンロードできてしまいます）。誤って入れたら、その添付を取り消し、管理者に連絡します。
2. **見られる人**: ダウンロードできるのは、その外国人の担当者（担当者のログインユーザー）と管理者だけです。ほかの人には種別と登録日だけが出て、ファイル名もリンクも出ません。URL を直接開いても 403 になり、監査ログに「ダウンロードの拒否」が残ります。
3. **担当者を替えたとき**: 判定はダウンロードの時点の担当者で行うので、前の担当者はダウンロードできなくなります。担当者にログインユーザーが無い外国人の書類は、管理者だけがダウンロードできます。
4. **ファイル名**: ファイル名は監査ログ・通知文・管理画面に出しません。ファイル名に病名や検査結果を入れないでください（ダウンロードした人の手元には残るため）。
5. **手元に残さない**: ダウンロードしたファイルは、申請に使ったら端末から消します。メールに添付して送らないでください。
6. **保持期限の目安**: 添付するときに「保持期限の目安」を入れておくと、過ぎたものに「目安を過ぎています」と出ます。自動では削除しません。削除の時期と手順は、運用で決めてから別のタスクにします（それまでは取消で残す）。
7. **管理画面**: 管理画面（admin）でも、要配慮の添付はファイル名とダウンロードのリンクを出しません。
8. **本番の保存先**: 保存時暗号化と、オブジェクトへの匿名のアクセスの拒否を、本番準備で確かめます（`docs/tasks-phase1.md` の本番準備）。

### システムでの記録の仕方

1. **本人の同意**: 支援計画の版の「定期面談の実施方法についての本人の希望」を「オンライン」にします（計画書のⅣ9 の欄に当たります）。署名済みの計画書は「交付」に「支援計画書の写し」として、交付日と署名済みの控えを入れます。この 2 つで「計画書の欄の記載と署名で確認した」ことを示します。実施中の計画をオンラインに切り替えるときも新しい版で希望を「オンライン」にします（入管への変更の届出は不要。変更理由に「本人の同意によりオンライン面談に切り替え」と書きます）。
2. **上司の同意**: システムに専用の欄はありません。当面は、同意の書面（任意の様式）をスキャンし、その上司との最初のオンライン面談の「上司との面談」の行に添付し（種別は支援の証跡）、本文に「同意日・同意した人」を書きます。紙の原本は帳簿書類として保存します。
3. **面談の記録**: ダッシュボードの「記録」から、本人・上司の行のそれぞれで方法「オンライン」を選び、「オンライン会議の URL」に使った会議の URL を入れます（電話は選べません）。本文には、第三者がいないことを確かめた方法（部屋全体を映した・イヤホン無し等）を書きます。
4. **対面に戻す**: 本人が対面を希望したら、計画の新しい版で希望を「対面」にし、次回から方法「対面」で記録します。問題や第三者の介入が疑われたときは、その面談を記録したうえで、すぐに対面の面談を行い、もう 1 組記録します（次回のタスクは後の面談の日から数え直されます）。
5. **録画**: 録画のファイルはシステムに添付できません（添付は PDF・PNG・JPEG の 10 MB まで）。自機関の管理する保存先に、外国人・面談の日が分かる名前で保存し、雇用契約の終了の日から 1 年以上残します。保存先は面談の本文に書きます。
6. **年 1 回の対面・初回の対面**: システムは警告を出しません。担当者が記録の一覧（方法の列）で確かめます。

同意・録画を記録する専用の欄を足すかは、`docs/tasks-phase2.md` の「段階2の完了確認」の「残っている事項」に書いています。
