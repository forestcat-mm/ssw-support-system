# 段階2（支援記録）タスク一覧

各タスクは「計画 → 確認 → 実装 → 報告」で進め、1 タスク 1 コミット（`feat:` と `docs:` は分ける）。順序どおりに進める。
各タスクで `make test`・`make lint`・`make e2e` を通す。業務画面・サービス・監査ログ・権限・e2e は段階1の作法を踏襲する。

ゴール: 義務的支援10項目の実施記録がシステム上に残り、定期届出で問われる項目（支援の実施状況、相談の内容と対応、通報の有無）を後から集計できる状態。
ゲート: 「30人分の面談・相談を記録して回せるか」をダミーデータで確かめる（「段階2の完了条件（T27）」の A）。実データでの運用（B）は段階2の条件に含めず、MVP 完了（段階4）後の価値検証で行う（末尾の節）。

参照: 仕様書 第3章（義務的支援10項目）、第5章 F04・F05・F06・F14、第6章「署名を要する書類の扱い」「要配慮個人情報を含む添付」、第7章 support\_plans / support\_plan\_items / support\_records / attachments / filings。

## 段階1から持ち越した項目

- パスワードの再設定画面 → T25 で行う。
- 外国人の状態を離職・帰国に変えるときの日付の必須化 → 運用後の判断として据え置く（段階1の tasks-phase1.md の段階2の見出しのまま）。
- 外国人詳細の履歴行の「全桁を表示」 → 据え置く。

## 共通の方針

- **持ち方**: 義務的支援10項目は法定の固定の一覧なのでコードの選択肢にする（表示名は翻訳ファイル）。支援計画は雇用契約（T09）と同じく見出し＋変更しない版＋版ごとの10行。支援実績は共通の表 `support_records` に、定期面談・相談・ガイダンスの専用の表を 1 対 1 で足す（集計の条件にそのまま使える）。相談の経過は追記専用の表。

- **支援記録の本文の言語**: 記録ごとに「本文の言語」（日本語／中国語〔簡体字〕）を持ち、初期値はその外国人の支援言語。表示と入力欄に `lang` 属性（`ja` / `zh-Hans`）を付ける。日本語と中国語が混ざる本文は、主な言語を選ぶ（字形はフォントの代替で表示される）。氏名と同じく、中国語の字形を正しく出すため。
- **訂正の仕方**: 支援記録・交付記録は上書きしない。誤りは取消（理由必須）＋新しい行。相談の対応の経過は追記のみ。
- **監査ログ**: 支援計画・支援実績・交付記録は作成・更新・取消を記録し、外国人詳細の「支援」タブの表示は閲覧として記録する（段階1と同じ 1 回 1 件）。
- **権限**: `support.view` / `support.manage` を両ロールに付ける。標準の支援計画の編集は管理者（`organization.manage`）。要配慮添付のダウンロードは担当者と管理者だけ。
- **無効化した外国人**: 定期面談の起票の対象から外す（`active_workers()`）。記録の追加もさせない（段階1の編集と同じ）。
- **ダミーデータ**: 各タスクで作った記録は、T26 でまとめて seed\_dummy に入れる。それまでの確認は画面からの入力とテストのデータで行う。

## 段階2の完了条件（T27）

「30人分の面談・相談を記録して回せた」と判断する基準。段階2の完了条件は、次の A（ダミーデータでの確認）だけとする。

**A. ダミーデータでの確認（開発環境）**

| 項目 | 基準 |
|---|---|
| 記録の量 | 30人分の定期面談（本人用・上司用で 60 行）と、相談 5 件以上（うち 2 件以上を経過の追記を経て解決まで）を、担当者 2 人で記録できる |
| 手間 | 定期面談 1 回分（本人用・上司用の 2 行）の記録が、平均 10 分以内 |
| admin | 記録の作業中に admin を開いた回数が 0 回 |
| 集計 | T24 の関数で取り出した「外国人×10項目の実施有無」「相談の一覧」「通報の有無」が、記録した内容と 100% 一致する |
| 期限 | 記録した面談の「定期面談」タスクがすべて完了になり、次回のタスクが起票されている（漏れ 0 件） |

## A の確かめ方（T27）

1. `make seed-reset` で、計画と実績の入ったダミーデータ（30人）を作る。
2. 担当者 2 人分（`dummy_tanto` と、もう 1 人）でログインし、ダッシュボードの「定期面談」から 30 人分の面談を記録する（本人用・上司用）。うち数人は相談として受け付け、経過を追記して解決まで進める。
3. 次を記録する: 1 人あたりの記録にかかった時間（目安）、迷った画面・項目、足りない項目。
4. T24 の関数で、外国人×10項目の実施有無・相談の一覧・通報の有無を取り出し、記録した内容と一致することを確かめる。
5. 結果を本ファイルの「段階2の完了確認」に書く。

## MVP 完了（段階4）後の価値検証

段階2の完了条件には含めない。MVP（段階1〜4）が完了した後、本番サーバーの準備（`docs/tasks-phase1.md` の「MVP 完了後の価値検証の直前にやること」）と実データの投入を済ませてから行う。判断基準は次のとおり。

**B. 実データでの運用**

| 項目 | 基準 |
|---|---|
| 期間と人数 | 担当者 2 人が、連続する 2 週間（10 営業日）運用する |
| 記録の網羅 | その期間に実施した定期面談・相談が、すべて（100%）システムに記録されている。紙・Excel への二重記録をしていない |
| admin | 運用中に admin を開く必要があった回数が 0 回 |
| 期限 | ダッシュボードの「定期面談」の超過が、期間の終わりに 0 件 |
| 訂正 | 記録の誤りの訂正が、すべて取消＋新しい行（または相談の経過の追記）で済んでいる |
