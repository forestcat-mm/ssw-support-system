# ダミーデータ（seed_dummy）

開発・動作確認用のダミーデータを作る管理コマンド `seed_dummy` の内容と使い方。
本物の外国人情報は開発環境に入れない（CLAUDE.md 制約10）。確認はすべてこのダミーデータで行う。

> **注記**: 法人番号・氏名・住所・電話番号・在留カード番号・旅券番号などはすべて架空です。
> 実在の法人・人物・番号と一致しても偶然です。氏名は一般的な姓と名の文字の組み合わせで作るため、
> 同姓同名の実在の人物はあり得ますが、特定の人物を表すものではありません。

## 使い方

```
make env          # .env に ALLOW_DUMMY_DATA=true が無ければ追加される
make seed         # 作る（作成済みなら何もしない）
make seed-reset   # ダミーだけを消して作り直す
make seed DATE=2026-10-16   # 基準日を指定する（同じ基準日なら同じ内容）
```

- **安全装置**: `DEBUG=True` かつ `ALLOW_DUMMY_DATA=true` のときだけ動く。どちらかが欠けていれば何も書き込まずに終了する。本番の環境変数に `ALLOW_DUMMY_DATA` は入れない。
- **再現性**: 乱数の種は固定。日付は基準日（既定は実行した日）からの相対なので、同じ基準日なら同じ内容になる。
- **作り直し**: `--reset` は、台帳（`seed.SeedObject`）に載っている行と、それに紐づく届出タスクだけを消す。手入力したデータは消さない。監査ログは追記専用なので残る（作成・削除の記録も残る）。
- **自機関**: 未登録のときだけ「（ダミー）サンプル登録支援機関」を作る。登録済みの自機関には触らない。
- **担当者でログインする**: `docker compose exec web python manage.py changepassword dummy_tanto` でパスワードを設定し、http://localhost:8000/accounts/login/ から支援担当者「佐藤 花子（ダミー）」としてログインして業務画面を試す（初回は TOTP の設定から始まる）。`dummy_tanto` は `--reset` でも消えない。

## 作る内容（基準日を D とする）

| 区分 | 件数 | 内容 |
|---|---|---|
| 自機関 | 0〜1 | 未登録なら作成。登録期限は D の 5 か月後（登録更新の受付期間中になる）。食品産業特定技能協議会の加入日と構成員証明書（ダミー PDF） |
| 事務所 | 1 | 本社（ダミー） |
| 担当者 | 3 | 支援責任者 1（山田 一郎）、支援担当者 2（佐藤 花子＝ログインユーザー `dummy_tanto`、鈴木 次郎）。外国人は支援担当者 2 人に振り分け |
| 受入れ機関 | 2 | （ダミー）サンプル精機工業株式会社（工業製品製造業分野、事業所 2）、（ダミー）サンプル食品株式会社（飲食料品製造業分野、事業所 1）。法人番号は検査用数字の合った 99 始まり |
| 加入状況 | 2 | 各社 1（証明書はダミー PDF）。食品の会社は有効期限が D+25 日 |
| 協力確認書 | 3 | 工業 1 市、食品 2 市町 |
| 支援委託契約 | 2 | 工業は D+60 日に終了、食品は期限なし |
| 外国人 | 30 | 中国 25（支援言語: 中国語）、ベトナム 3、インドネシア 2（支援言語: 日本語）。1 人は入国前 |
| 在留情報 | 37 行 | 在留カード番号は形式の検査を通るダミー。6 人は履歴が 2 行以上（技能実習3号→特定技能1号、更新、再交付） |
| 旅券・住所・連絡先 | 各 30 | 全員に 1 行。住所は架空の地名、電話は `000-` 始まり、メールは `example.invalid` |
| 雇用契約 | 30 | 月給 26、時間給 4。手当（住宅・皆勤）と控除（居住費・食費）あり |

### 在留期限の分布（入国前の 1 人を除く 29 人）

| 期限 | 人数 |
|---|---|
| 超過（D−5 日） | 1 |
| 7 日以内 | 1 |
| 14 日以内 | 1 |
| 3 か月以内（それ以外） | 3 |
| 6 か月以内 | 6 |
| 1 年以上 | 17 |

旅券の有効期限が 6 か月以内の人は 3 人。

### 雇用契約のパターン

| パターン | 人数 | 届出タスク |
|---|---|---|
| 版が 2 つ（昇給のみ） | 3 | 起票されない（昇給は届出不要） |
| 版が 2 つ（減給） | 2 | 雇用契約変更届出 |
| 終了済み（自己都合退職、D−4 日） | 1 | 雇用契約終了届出 |
| 終了済み（会社都合、D−9 日） | 1 | 雇用契約終了届出＋受入れ困難届出 |
| 終了が未登録のまま D+20 日に満了 | 1 | 雇用契約の期間満了確認 |

終了済みの 2 人は状態を「離職」にしている。

## 作られる届出タスク（基準日 2026-10-16 の例）

最後に日次の起票（`create_scheduled_filings` と同じ処理）を 1 回実行する。

| 種別 | 件数 |
|---|---|
| 在留期間更新許可申請 | 4（3 か月以内の 6 人のうち、離職の 2 人を除く） |
| 雇用契約終了届出 | 2 |
| 受入れ困難届出 | 1 |
| 雇用契約変更届出 | 2 |
| 旅券更新の確認 | 3 |
| 自機関の登録更新 | 1（自機関を seed が作った場合） |
| 加入証明・協力確認書の更新 | 1 |
| 支援委託契約の更新 | 1 |
| 雇用契約の期間満了確認 | 1 |

警告レベルは、超過・7 日以内・14 日以内・対応期間中が混ざる（T14 の色分けの確認用）。
