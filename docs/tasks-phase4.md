## 進め方（段階3の後半と同じ）

T44〜T56 を 4 つのブロックで進める。ブロックごとに「計画 → 確認 → 実装 → 検査 → 報告」。push は報告の後に指示を受ける。

| ブロック | タスク | 中身 |
|---|---|---|
| A（前提と台帳） | T44・T45・T46 | 帳簿の確定、担当者の履歴、一括申請の欄から逆算した台帳の項目 |
| B（一括申請 F09） | T47・T48・T49 | xlsm への書き込みの基盤と入力チェックの写し、認定・変更・更新の生成、申請の書類との合わせ |
| C（一括届出 F10） | T50・T51・T52 | 随時届出 7 本、定期届出の添付（D6）、届出タスクとの合わせ |
| D（様式マスタと仕上げ） | T53・T54・T55・T56 | 様式マスタの管理（F13）、参考様式の残り、ダミーデータと gate4、仕上げ |

決めてほしい点は、ブロックの計画でまとめて出す（番号はタスクつき。例: T44-D1）。

1. **計画はブロックで 1 回出す**。タスクごとの節（照合・出典・項目の対応・決めてほしい点）。決めてほしい点の番号はタスクの番号つき（例: T47-D1）。
2. **実装はタスクの順**。コミットはタスクごとに `feat:` と `docs:` を分ける。
3. **検査**: 直すたびに `make check-quick`、タスクのコミットのたびに `make test`、push の前に `make checks`（GATE3=1。gate4 ができた後は gate4 も）。
4. **報告はブロックの終わりに 1 回**（タスクごとの実装・決めたこと・画面での確かめ方・満たしたゲートの項目）。
5. **途中で止まる条件**: 決めた点と違う実装が要る・制度の判断が要る・既存のデータを壊すモデルの変更が要る・直せない検査の失敗がある。
