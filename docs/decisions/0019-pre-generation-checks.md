# ADR-0019: 帳票の生成前の検査。規則はマッピングとは別の規則のファイルに持ち、「生成不可」と「警告付きで生成」に分け、不足ごとに直す画面の行き先を持つ

- 状態: 採用
- 日付: 2026-10-18
- 関連: 仕様書 第4章「システムへの反映」（バリデーション）、第5章 F11、第6章「生成前バリデーション」「様式のバージョン管理」、制約5・6・8、ADR-0004、ADR-0009、ADR-0010、ADR-0018、T21、T22、T30、T31〜T34、T39

## 背景

仕様書 第6章は、様式ごとに必須・形式・整合性の規則を定め、違反を「警告付きで生成」と「生成不可」に分けて不足の一覧を出すこと、規則をマッピング定義と同じくデータとして持ち、様式の版に紐づけることを求めている。
第4章は「加入証明の添付が無ければ生成不可」「飲食料品製造業分野でキャリアアッププランが未交付なら警告」を求めている。
T29（ADR-0018）では、マッピング定義の JSON に空の `rules` を置き、生成履歴がある版のマッピングは置き換えないことにした。

## 確かめたこと（2026-10-18、ダミーデータ）

- 入国前の人（25 番）の在留情報の `expires_on` は、在留期限ではなく在留資格認定証明書の有効期間（3 か月）である。在留期限の検査で、そのまま比べてはいけない。
- ガイダンス・オリエンテーションの記録の注意（T21）のうち「署名済みの確認書が添付されていません」（`unsigned`）は、確認書を生成する時点では必ず出る（署名は生成の後）。
- `career_plan_findings`（ADR-0010）は、外国人の飲食料品製造業分野のすべての契約を返す。生成では、基準日の契約だけが関係する（転籍の前の契約は数えない）。
- 加入証明が無い場面は、ダミーデータに無い（3 社とも証明書あり）。生成不可になる場面は、在留期限の超過（1 番）と、離職で契約が無い人（4・6 番）。

## 決定

### 1. 規則はマッピングとは別の規則のファイルに持つ

- 規則は `mappings/<様式ID>/<適用開始日>.rules.json` に置く（`form_id`・`valid_from`・`rules`）。欄の対応（`fields`）は今のとおり `mappings/<様式ID>/<適用開始日>.json` で、生成履歴がある版では置き換えない（ADR-0018）。
- **規則のファイルは、生成履歴があっても置き換えてよい**。規則は出力の中身を変えず、運用の中で重さや規則を直したいため。
  - 読み込み（`make forms`）で、パス・SHA-256・中身を `FormMapping`（`rules_path`・`rules_sha256`・`rules`）に記録する。変わったら `FormMapping` の更新として監査ログに残る（変更の前後の SHA-256 を含む）。
  - 規則のファイルは版ごとに必須にする（規則が無い版は `"rules": []`）。
  - マッピングの JSON の `rules` は空のままにし、中身があれば読み込みで止める（置き場所を 1 つにするため）。T29 の生成履歴がある版のマッピングの SHA-256 を変えないよう、空の `rules` は消さない。
- 生成履歴（`GeneratedDocument`）に、検査に使った規則のファイルの SHA-256（`rules_sha256`）と、確かめて生成した警告（`findings`）を残す。

### 2. 規則の形

| 種類 | 中身 | 項目 |
|---|---|---|
| `required` | データの値が空でない（空白だけも空） | `key`・`label` |
| `date` | データの値が日付（日付の型か ISO の文字列） | `key`・`label` |
| `width` | 半角だけ（`unicodedata.east_asian_width` が Na・H）／全角だけ（F・W・A） | `key`・`label`・`width`（`half`／`full`） |
| `max_length` | 文字数が上限以下（文字の数で数える） | `key`・`label`・`max_length` |
| `check` | 名前で登録した判定の関数を呼ぶ（`services/form_checks.py` の `@check`） | `name`・`params` |

- すべての規則に `id`（版の中で一意）と `severity`（`block` = 生成不可、`warn` = 警告付きで生成）を持つ。
- データの規則（`required` など）の空の値は、`required` だけが見る。`label` は様式の欄の名前（様式の文言をそのまま。データなので訳さない）で、文言の型（「「%(label)s」が空です。」など）はコードの UI 文言（英語の msgid と日本語の訳）。
- `requires` に前の規則の `id` を書くと、その規則で不足が出なかったときだけ評価する。事前ガイダンスの記録が無い人には「事前ガイダンスの記録がありません」の 1 件だけを出し、実施日時などの欄ごとの不足を重ねない。
- 読み込みで次を止める（`FormTemplateError`）: 種類・重さが分からない、`id` の重複、`requires` が前の規則を指さない、判定の名前が登録されていない、判定が受け付けない `params`、データの規則の `key` がその版の `fields` に無い、`label` が無い、`fix` の URL が引けない。

### 3. 判定の関数（`services/form_checks.py`）

検査の文脈は、外国人・生成の対象（外国人、またはガイダンスの記録）・基準日（申請日・届出日）・様式に入れるデータ。基準日の契約は `contracts.contract_on`（その日に始まっていて終了していない契約。無ければ、その後に始まる予定の契約）、版は `contracts.version_on`。

| 名前 | 判定 | 見本の規則での重さ |
|---|---|---|
| `employment_contract_on_basis` | 基準日の契約がある | 生成不可（1-17） |
| `residence_valid_on_basis` | 在留期限が基準日より後（仕様書 第6章）。在留資格認定証明書の行は見ない。在留情報が無ければ不足 | 生成不可（1-17） |
| `membership_certificate` | 基準日の契約の事業所の、受入れ機関×分野の加入があり、取り消していない証明書が付いている（ADR-0004） | 生成不可（1-17） |
| `career_plan_delivered` | 基準日の契約について `career_plan_findings`（未交付・締結の後の交付。ADR-0010） | 警告（1-17） |
| `support_language_staff` | 外国人の担当者の対応言語に支援言語がある。担当者がいなければ不足 | 警告（1-17） |
| `briefing_record_exists` | 生成の対象が、その種類（`params.kind`）の取り消していない記録 | 生成不可（5-9） |
| `briefing_warnings` | 記録の注意（T21。所要時間・費用・細目・行数など）。`params.exclude` のコードは出さない | 警告（5-9。`unsigned` は除く） |
| `delivery_warnings` | その種別（`params.kind`）の交付記録の注意（T22） | 登録だけ（付けるのは T31・T33） |

- **加入証明の有効期限（仕様書 第4章からの変更）**: 第4章は「加入証明の添付がない場合は生成不可」とだけ書く。**有効期限を過ぎた証明書は無いものとみなし、生成不可にする**（期限の切れた証明書は申請の添付書類にならないため）。有効期限の当日は有効。有効期限が空の加入（工業の会員名簿の登録など）は、期限切れとして扱わない。加入日が基準日より後の加入は「加入なし」とする。
- **ガイダンスの強い注意**（下限の時間に満たない・保証金の契約・費用に同意していない）も警告のまま（強い注意の印を残す）。確認書は実施した事実の記録で、生成を止めると記録が残らないため。止めたいときは規則のデータで重さを変える。
- **担当者の言語**の警告には「通訳の手配がある場合は問題ありません」の趣旨を入れる（通訳を手配して支援する場合があるため、生成を止めない。通訳の手配の記録は持たない）。
- 「報酬が契約と一致」と F11 の「報酬根拠未入力」は、報酬の欄を持つ雇用条件書（第1-6号）の T34 で足す。今の見本の様式には報酬の欄が無く、データも契約から作るため、比べるものが無い。

### 4. 結果と生成の流れ（`services/form_generation.py`）

- `check(form_id, target=, data=, basis_on=)` が、基準日に適用される版の規則で検査し、`CheckResult`（生成不可・警告）を返す。生成の画面（T31〜）と `request()` が使う。
- `request()` は、生成不可が 1 件でもあれば `GenerationBlocked` にし、**生成履歴も監査ログも作らない**（何も生成せず、個人情報も出していないため）。
- 警告があるときは `accept_warnings=True`（警告を確かめた印）が無ければ `WarningsNotAccepted` にする。確かめて生成したときは、その警告を生成履歴の `findings` に残す。
- `findings` の 1 件は、規則の `id`・コード・重さ・文言・強い注意の印・行き先。文言には外国人の値（氏名など）を入れない（受入れ機関名・担当者名・日付は入る）。

### 5. 不足ごとの行き先

不足の 1 件ごとに、直す画面の URL の名前と対象の ID を持つ（`Destination`）。表示は T31 の生成の画面で作る。T30 では、行き先が正しく、その画面が開けることをテストで確かめる。

| 不足 | 行き先 |
|---|---|
| 加入・証明書 | 受入れ機関の詳細（`hosts:detail`） |
| 在留期限・在留情報 | 外国人の履歴（在留情報。`workers:history`） |
| 雇用契約 | 外国人の契約タブ（`workers:contracts`） |
| キャリアアッププラン | 外国人の交付記録（`workers:support_deliveries`） |
| ガイダンスの記録が無い | ガイダンスの記録の追加（`workers:support_briefing_create`） |
| ガイダンスの記録の注意 | その記録（`workers:support_briefing`） |
| 交付記録の注意 | その交付記録（`workers:support_delivery`） |
| 担当者の言語 | 設定の担当者（`settings:staff_edit`） |
| 担当者がいない | 外国人の編集（`workers:edit`） |
| データの規則 | 規則の `fix`（`object` は worker・briefing・host・staff・organization のいずれか、`url` は URL の名前） |

### 6. 確かめる道具

- `python manage.py check_form <様式ID> --worker <ID> [--basis 日付]`: 見本の対象とデータで検査し、生成不可・警告と行き先を表示する（生成はしない）。
- `generate_sample_form` も検査を通す（生成不可なら止める。警告は `--accept-warnings`）。第5-9号の見本の対象は、最新の事前ガイダンスの記録にした。

## 影響

- ダミーデータ（基準日 D）での見本の規則の結果（`tests/forms_engine/test_checks.py` で固定。`docs/dummy-data.md`）:
  - 第1-17号: 生成不可は 1 番（在留期限の超過）・4・6 番（離職で契約が無い）、警告は 9・15 番（キャリアアッププランが未交付）。
  - 第5-9号: 警告は 10 番（目安の 3 時間を下回る）、25 番は不足なし。事前ガイダンスの記録が無い人は生成不可（1 件）。
- 加入証明が無い場面はダミーデータに無い。T39 でダミーデータに足す（`docs/tasks-phase3.md`）。それまでは、テストで seed の証明書を取り消して確かめる。
- T31 の生成の画面で、不足の一覧（生成不可・警告、強い注意の印、行き先のリンク）と、警告を確かめる印を作る。
- 規則のファイルを置き換えると、同じ版でも過去の生成と今の検査の規則が違うことがある。どの規則で検査したかは、生成履歴の `rules_sha256` と監査ログ（`FormMapping` の更新）でたどる。

## 検討した代替案

- **規則をマッピングの JSON に入れる（T29 の形）**: 生成履歴がある版ではマッピングを置き換えないため、規則の調整のたびに新しい版（適用開始日）が要る。出力が同じ版が増え、版の選び方の意味が崩れる。
- **生成不可の試みも生成履歴に残す**: 何も生成していない行が履歴に混ざり、「このファイルがどのデータから作られたか」（第6章）の一覧が読みにくくなる。
- **ガイダンスの強い注意を生成不可にする**: 実施の事実の記録（確認書）が作れなくなる。規則のデータで選べるので、既定は警告にした。
- **支援計画の 10 項目の担当者の言語で見る**: 計画の中身を様式に入れるのは T31 から。T30 では外国人の担当者で見る。

## 未確認の点

- 在留期限を過ぎた後の特例期間中（期限の前に申請していた場合）に生成するときの扱い。段階4の申請の様式で、要領を読んで確かめる。T30 では仕様書 第6章のとおり「在留期限が基準日より後」を求める。
- 在留期限の当日に申請する場合（「より後」の当日の扱い）。同じく段階4で確かめる。
- 加入証明の検査を、どの申請の様式に付けるか。T30 では、読み込み済みの申請の添付書類である第1-17号に付けた。申請の添付のセット（T37・段階4）でも付ける。
- 自機関の食品産業特定技能協議会の構成員証明書（仕様書 第4章）の検査は、申請の添付のセット（T37）で決める。
