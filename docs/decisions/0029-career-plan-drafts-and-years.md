# ADR-0029: キャリアアッププランの版は生成・交付に使うまで下書きとして直せ、習熟の目安の年数は 2 つの数字で持つ

- 状態: 採用
- 日付: 2026-10-19
- 関連: ADR-0025（キャリアアッププラン・実務経験証明書）、ADR-0010（交付記録）、CLAUDE.md「記録は上書きしない」、修正 1 回目 J1・J6（計画 `.checks/plan-fix1.md`）

## 背景

- **J1**: キャリアアッププランの版とレベルは、作った後に変えられなかった（T36。`CareerPlanImmutableError`）。直すには新しい版を作るしかなく、打ち間違いでも版が増える。交付したものを再現できればよいので、まだ誰にも渡していない版まで固定する必要は無い。
- **J6**: 習熟の目安の年数は、文字の 1 欄だった（T36-D4。例「1〜2年目」）。書き方がそろわず、並べ方や検査に使えない。

## 決定

### 1. 下書きの版（J1）
- 版に「初めて使った日時」（`CareerPlanVersion.used_at`）を足す。空の版は下書きで、版とレベルを直せる。日時が入った版は固定する。版とレベルの保存・削除は、モデルで断る（`_CareerPlanRow.is_locked`）。
- 使った日時を入れるのは、次の 2 つのとき（`services.career_plans.mark_used`。初めてのときだけ入れる）。
  - **生成の依頼**: キャリアアッププランの様式を生成するとき。スナップショットの `p.plan_version_id` の版に入れる（`services.form_generation.request`）。
  - **交付記録の作成**: キャリアアッププランの交付記録を作るとき。交付日に適用されていた版に入れる（`services.deliveries.create_delivery`）。
- 直すのは「版を直す」の画面で行う（`hosts:career_plan_version_edit`）。版の番号は変えず、レベルは置き換える。
  - 適用開始日は、前の版の日以後で、次の版の日以前にする。
  - 第 1 版は変更理由が要らない。2 版目からは要る。
- 直したことは監査ログに残る。版は更新、レベルは削除と作成として、モデルの保存のシグナルで記録する。
- 詳細の画面には「下書き（まだ使っていない）」か「固定（◯◯ に使用）」を出す。下書きのときだけ「編集」を出す。

### 2. ほかの版つきの記録には当てはめない
| 記録 | 当てはめるか | 理由 |
|---|---|---|
| 支援計画の版 | 当てはめない | 版を作ると第3-2号の届出（差分）を起票し、支援の記録が版を参照する。下書きを直すと、起票した届出の中身と食い違う |
| 雇用契約の版 | 当てはめない | 版の差分で変更の届出を判定する（T28b）。報酬の説明は、今も版と別の表で直せる |
| 在留情報・住所・連絡先・旅券 | 当てはめない | 履歴の行で、誤りは取消と新しい行で直す（業務画面の作法）。生成物は参照しない |

### 3. 習熟の目安の年数（J6）
- 「◯年目から」（`years_from`。必須。1 以上）と「◯年目まで」（`years_to`。任意）の 2 つの数字で持つ。
  - 終わりが空なら「◯年目以降」とする。
  - 終わりは始めと同じか後でなければならない。
- 帳票と画面には、次のように書く（`career_plans.years_text`）。
  - 「1〜2年目」
  - 「5年目以降」
  - 始めと終わりが同じなら「3年目」
- 移行（hosts 0009）では、元の文字の欄を `years_legacy` に名前を変えて残し、次の形を読み取る（`parse_years`。全角の数字も読む）。
  - 「1〜2年目」「1～2年目」「1-2年目」「1年目から2年目まで」「1年目〜2年目」
  - 「5年目以降」「5年目～」
  - 「3年目」
- 読み取れた行は数字を入れて、元の文字を空にする。読み取れない行は元の文字を残す。
  - 帳票には元の文字をそのまま書き、生成前の検査で警告する（`career_plan_years_numeric`）。
  - 画面には「年数を数字で入れ直す」の印を出す。
  - 版を直すとき（新しい版も）は数字が要る。入力の欄の説明に、元の文字を出す。
- 版の行は固定の行だが、移行では DB を直接書く。監査ログには、移行として 1 行ずつ残す（`context.migration = "hosts.0009"`）。

### 4. 既存のデータの使った日時（移行 hosts 0009）
- **生成物**: キャリアアッププランの様式の生成物のスナップショットにある版の ID から入れる。日時は生成の依頼の日時にする。
- **交付記録**: キャリアアッププランの交付記録からも入れる。ただし、交付日に適用されていた版を、移行の中で正確には探さない。
  - その受入れ機関のプランの版のうち、交付日までに適用が始まった版と、各プランの最も古い版を、すべて使ったものとする。
  - 多めに固定することになるが、固定は今までの扱いと同じなので、失うものは無い。
- 入れた行ごとに、監査ログに移行として残す。

## 影響

- 生成も交付もしていない版の打ち間違いは、版を増やさずに直せる。
- 年数の欄が 2 つの数字の欄になる。e2e とテストの入力を直した。
- ダミーデータのプランの年数は数字で入れる。交付記録がある版は、seed のときに固定になる（seed も `create_delivery` を通るため）。

## 未確認の点

- 別冊（飲食料品製造業分野）18頁の例は、年数の書き方を定めていない（「習熟の目安」としか書いていない）。数字 2 つで足りない書き方（「入社後すぐ」など）は、元の文字として残る形にした。
