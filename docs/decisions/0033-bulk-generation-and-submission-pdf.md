# ADR-0033: 不足の書類の一括生成と提出用の統合 PDF

- 状態: 採用（T42。不在の間の指示により、決めてほしい点はおすすめ (a) で決めた。人の確認待ちの点がある）
- 日付: 2026-10-19
- 関連: 仕様書 第5章 F08・F12、第6章「生成履歴」、第7章 generated_documents。ADR-0011（要配慮添付）・0018・0019・0022・0026・0031。計画 `.checks/plan-T42.md`、記録 `.checks/decisions-phase3-rest.md`

## 背景

申請の書類の一覧（ADR-0026）は、行ごとに生成の有無・添付の有無を出すが、生成は様式ごとの画面で 1 件ずつだった。生成前の検査（ADR-0019）は生成の画面だけで流し、一覧では生成不可も未生成と同じ赤にしていた（ADR-0031）。提出する書類をまとめる手段は無かった。

## 決定

1. **一覧の行ごとの検査の結果**: 当てはまる行のうち、生成する様式で未生成か、ほかの契約・版の生成物しか無い行は、一覧を開いたときに生成前の検査を流し、「生成不可」「警告 n 件」「生成できる」を出す（`application_bulk.row_checks`）。生成の画面で入れる申告（第1-17号Ⅲ欄７）の警告は、一覧の数に入れない。
2. **一括生成**（`application_bulk`、画面 `workers:application_bulk`）:
   - 対象は 1. の行（T42-D8）。判断できない行・システムの外の行・添付の行は生成しない。添付の不足は「不足の添付」として同じ画面に出す。
   - 入力は 1 件ずつの画面の初期値と同じ（T42-D9）。基準日は一覧の基準日、作成責任者は既定、言語は契約の版の様式だけ支援言語から。第1-17号の申告は一括の画面の印。
   - 生成不可の行は選べず、選んだ行が生成の時点で生成不可になっていれば飛ばして知らせる。警告のある行を選んだときは「警告を確かめた」の印が要る。同じ様式の行（第1-6号と別紙）は 1 回だけ生成する。
3. **提出用の統合 PDF**（`submission_bundles`、画面 `workers:submission_bundle_create`）:
   - 順（T42-D2）: 提出書類一覧表の行を先頭に、続いて一覧の定義の順（表の順・番号順・行の順）。
   - 中身（T42-D3・D5）:
     - 生成の行は、署名済みのスキャンが要る様式で署名済みならそのスキャン（最新の署名日のもの）、ほかは生成した PDF。署名待ちは警告。
     - 添付の行は添付のファイル（健康診断の書類・構成員の証明書・協議会の証明書は最新の 1 件、版の根拠資料は全部）。
     - システムの外の行（提出書類一覧表・申請書・登記事項証明書など）は、その画面でアップロードしたファイルを綴じる。別の添付としては保存しない。返信用封筒の行にはアップロードの欄を出さない。
     - 同じ生成物は 1 回だけ綴じる。
   - 画像（T42-D7）: JPEG はそのまま、PNG は IDAT をそのまま埋め込んで A4 の 1 頁にする（圧縮し直さない。Pillow を入れない）。透過・インターレースの PNG、CMYK の JPEG は綴じない。
   - 読めないファイル（壊れている・パスワード付き）は綴じずに警告（T42-D11）。その場でアップロードしたものは、欄のエラーにして作らない。
   - 容量（T42-D6）: 設定 `SUBMISSION_PDF_MAX_MB`（既定 25。MB は 1,000,000 バイト）。元のファイルの合計で見積もり、超えそうなら作る前に警告する。作った後も超えたら生成履歴の警告に残し、参考様式９の案内を出す。作るのは止めない（窓口の印刷にも使う）。`SUBMISSION_MAX_FILES`（既定 20）は画面の案内に出す。
   - 作る処理は画面の依頼の中で行う（T42-D10。変換が要らない）。しおりに表・番号・書類の名前の 1 行目を入れる。暗号化・印刷禁止は付けない。
4. **生成履歴**（T42-D1）: 新しいモデル `SubmissionBundle`（テーブル submission_bundles）。追記だけで、変更・削除はモデルが拒否する。
   - 持つもの: 外国人・申請の種類・一覧の版・基準日・PDF・SHA-256・大きさ・頁数・要配慮を含むか・中身・作ったときの警告。
   - 中身（items）は綴じた順に、行・表・番号・種類・元の ID・頁数・SHA-256 を持つ。ファイル名は持たない。
   - 監査ログ: 作成を GENERATE（イベント 1 件）、ダウンロードを DOWNLOAD、画面の表示を外国人の閲覧として残す。
5. **権限**（T42-D12）:
   - 作る・見る: forms.generate と、その外国人を見る権限。無効化した外国人には作らせない。
   - 綴じる人が開けない添付は綴じない。要配慮の添付は担当者か workers.sensitive_documents を持つ人だけで、ほかの人には「綴じない」の警告を出す。
   - 要配慮を綴じたら `contains_sensitive` を付け、ダウンロードも担当者と workers.sensitive_documents を持つ人に限る（`submission_bundles.can_download`）。
6. **ダミーデータ**（T42-D13）: seed の添付のダミーの PDF を、読める空白の 1 頁の PDF にした（綴じる場面を画面で確かめるため）。作成済みの行のファイルは変えない。

## 仕様書との関係

- 仕様書第7章に submission_bundles のテーブルは無い。generated_documents は様式の版（form_templates）への参照が必須で、様式の無い統合 PDF には合わないので、別のテーブルにした（人の確認待ち）。
- 提出書類一覧表そのもの（表紙・提出確認欄の〇）は、システムで記入しない（T42-D4）。アップロードしたものを先頭に綴じる。記入して出すのは段階4以降の候補。

## 未確認の点（人の確認待ち）

- オンラインの申請で、提出書類一覧表そのものを PDF で添付するか、添付の順の定めがあるかは、Q&A・操作説明書・案内のページに見当たらなかった。窓口の定め（留意事項３）をオンラインにもあてはめた。
- 留意事項３の「提出書類一覧表を先頭に」が、第1〜3表の一覧表をまとめて先頭に置くのか、表ごとに一覧表とその書類を並べるのかは、文から決めきれない。まとめて先頭とした（T42-D2）。
- 申請書（別記第6号の3様式）は、オンラインでは入力の画面で作り、PDF の添付は要らないとみられるが、明記を確かめられなかった。システムの外の行として、アップロードしたときだけ綴じる。
- 「25MB」が 25,000,000 バイトか 26,214,400 バイトかは書かれていない。小さい方で判定する（設定で変えられる）。
- 綴じた PDF（pypdf の出力）が ISO 32000-1 に準拠しているかは、オンラインのシステムに添付して確かめていない（外部に送らないため）。
