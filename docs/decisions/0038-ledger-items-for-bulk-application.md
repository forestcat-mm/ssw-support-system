# ADR-0038: 一括申請の欄から逆算した台帳の項目

- 状態: 採用（T46a 外国人の項目、T46b 受入れ機関・事業所・自機関の項目と第1-11-1号）。ブロック A の計画で、決めてほしい点 T46-D1〜D11 はおすすめのとおりに決めた。D1 は指示で補った
- 日付: 2026-10-20
- 関連: ADR-0018（Excel の書き方）・0026（申請の書類の一覧）・0036（帳簿）・0037（担当者の履歴）、`docs/tasks-phase4.md` の D3。計画 `.checks/plan-blockA.md`、調べ `.checks/blockA/t46-fields.md`（全部の欄は `.checks/blockA/t46/fields_grouped.tsv`）

## 背景

段階4の一括申請（T47・T48）は、在留申請オンラインの一括登録用ツール（認定・更新・変更の 3 本の xlsm）の欄に値を書く。必須と条件つき必須の欄だけでも 1 人あたり約 200 あり、今の台帳に無い項目がある。台帳に足すもの・申請ごとに入れるもの・計算で出すものに分けて、台帳に足すものを T46 で足す。

## 決定（T46a 外国人の項目）

1. **選択肢はツールのコード**（T46-D3）: 新しい選択肢（続柄・国籍〔日本を含む〕・評価区分・試験名・受験地・職種・作業・証明・在留期間・都道府県・市区町村）は、ツールのコードをそのまま値として持つ。表示名は、ツールの版ごとのデータ `backend/services/data/immigration_codes.json` から出す（`services/immigration_codes.py`）。データは道具 `tools/forms/extract_tool_codes.py` が 3 本の xlsm の名前定義（`_<コード>_C` と連動の `_<コード>_<親の値>_C`）から作る。手で直さない。3 本で同じ表は 1 つ、手続で違う表（申請の意思の確認の文・受領方法など）は手続ごとに持つ。ふりがな（rPh）の文字は入れない。画面には表示名の日本語の部分を出す。
2. **外国人に足した項目**（どれも任意。足りないものは T47 の生成前の検査が知らせる）:
   | 項目 | 置き場 | ツールの欄 |
   |---|---|---|
   | 出生地（40 字） | ForeignWorker.birthplace | 共通 出生地（認定・変更） |
   | 在日親族・同居者の有無 | ForeignWorker.has_relatives_in_japan（未入力・有・無） | 共通 在日親族及び同居者 有無 |
   | 職歴の有無 | ForeignWorker.has_work_history | 区分V 職歴の有無 |
   | 台帳の外の特定技能1号の在留期間（月数） | ForeignWorker.ssw_months_outside_ledger | 区分V 通算在留期間（台帳の期間と足して T47 で年・月にする） |
   | 在日親族・同居者（6 人まで） | WorkerRelative（続柄 CB06_2・氏名 26 字・生年月日・国籍 CB79・同居・勤務先等 60 字・在留カード番号〔列暗号化〕。T46-D2） | 共通 在日親族及び同居者 1〜6 |
   | 技能水準・日本語能力 | WorkerQualification（区分・評価区分 CC06・試験 CC09／CC10・受験地 CB79・合格日・レベル・その他の証明 60 字・合格証明書の添付。T46-D7） | 区分V B〜Q |
   | 良好に修了した技能実習2号 | InternshipCompletion（職種 CC02_3・作業 CB30〔職種ごとの表にあるものだけ〕・証明 CC07・修了日・証明の添付） | 区分V R〜W |
   | 職歴（10 件まで） | WorkHistory（入社・退社の年月〔月の 1 日で持つ〕・勤務先 60 字） | 区分V AJ〜BN |
   | 在留期間（長さ） | ResidenceRecord.period_of_stay（CB20。新しい行から） | 共通 在留期間（更新・変更） |
   | 技能実習のイ・ロ | ResidenceRecord.technical_intern_type（技能実習2号・3号の行だけ。新しい行から。T46-D8） | 共通 現に有する在留資格（CB19 がイ・ロで分かれる） |
   | 住所の分割 | WorkerAddress.prefecture_code・municipality_code・address_rest（T46-D4） | 共通 住居地（都道府県 CA69_1・市区町村 CA69・以降） |
3. **行の持ち方**: 在日親族・試験・技能実習・職歴は履歴行（取消〔理由は必須〕して新しい行。制約7の作法）。外国人詳細の「基本」の「一括申請の項目」に今の行を出し、「追加」で足す。取消は「履歴」タブ。合格証明書・修了の証明は行に添付する（添付の種別を 2 つ足した。要配慮ではない）。
4. **住所の分割**（T46-D4）: 保存のときに、住所の文字列をツールの都道府県・市区町村の名前と最長一致で照合して分ける（`services/addresses.py`）。ツールの市区町村の名前には郡が付いているので、郡の付いた町村は郡を除いた名前でも照合する（「大和郡山市」のような市の「郡」は外さない）。同じ長さで 2 つ以上当たれば分けない。分けられなければ空にし、外国人詳細の住所に「分けられませんでした」の印を出す。今の行は、マイグレーション（`workers/0009`）で同じように分けて空の列を埋めた（監査ログには残らない）。
5. **個人情報**: 在日親族の在留カード番号は列暗号化（監査ログは `***`）。画面には先頭・末尾 2 文字だけ出す。新しい表は監査の対象（作成・更新・取消）。閲覧は外国人詳細の 1 回 1 件の記録に、表示した行の ID を入れる。
6. **申請ごとに入れるもの**（T46-D1。T47・T48 で作る）: 申告（出入国歴・申請歴・犯罪・退去強制）・配偶者の有無・職業・希望する在留期間・理由・ED番号・受領方法など。犯罪の内容は要配慮の扱いにする: 入れた値を見られるのは要配慮添付と同じ担当者と管理者だけで、一覧・詳細の画面に出さない。生成した xlsm のダウンロードと生成のスナップショットも同じ扱い。監査ログに値を残さない。

## 決定（T46b 受入れ機関・事業所・自機関の項目と第1-11-1号）

7. **受入れ機関に足した項目**:
   | 項目 | 置き場 | ツールの欄 |
   |---|---|---|
   | 業種（主たる業種・他業種 2 つ。「その他の製造業」のときの内容） | HostOrganization.industry_1〜3・industry_1〜3_other（CC13 のコード） | 区分V (4) |
   | 資本金 | HostOrganization.capital（円） | 区分V (6) |
   | 決算（年度ごと） | HostFinancialYear（決算期末・売上高・経常損益・純損益・純資産〔個人は元入金〕。取消して入れ直す） | 区分V (7) 年間売上金額、第1-11-1号 2 |
   | 申告 (11)〜(32) と 3 の人数 | HostDeclaration（申告日ごとの版。答えは項目ごとの有無と内容 200 字。離職者数 4・行方不明者数 2・責めに帰すべき事由の有無。T46-D5） | 区分V (11)〜(32)、第1-11-1号 3 |
   | 役員 | HostOfficer（氏名・ふりがな・役職・住所・就任日・退任日。T46-D10） | 第1-11-1号 1、第1-23号 |
   | 申請担当者（代理人） | HostApplicantContact（氏名・申請人との関係・住所〔空なら受入れ機関〕・電話・携帯・有効。T46-D9） | 区分V 代理人 |
8. **事業所に足した項目**（T46-D6。説明文が「主に勤務させる事業所について」）: 常勤職員数・雇用保険適用事業所番号（11 桁）・労働保険番号（14 桁）・健康保険と厚生年金保険の適用・労災保険と雇用保険の適用（未入力・有・無）。番号はハイフンを除いて持つ。
9. **自機関に足した項目**: 法人番号（検査数字を確かめる）・雇用保険適用事業所番号（区分V 登録支援機関 (2)(3)）、役員（OrganizationOfficer。帳簿①。ADR-0036）。担当者に「在留申請オンラインシステムの利用者」の印と登録したメールアドレス（取次者。T46-D9）。
10. **申告の項目はデータ**: `backend/services/data/host_declarations.json`（ツールの列 FJ〜HB の 22 項目。通常の答え・内容の欄の有無・必須）。新しい版の画面は前の版の答えを初期値にし、前の版が無ければ通常の答えを選んでおく。通常と違う答えで内容の欄がある項目は、内容が要る。受入れ機関の詳細に、最新の版の日・未回答の必須の数・通常と違う答えの項目を出す。(27)(28)（労働者派遣）は通常の答えを決めない（直接雇用だけなので空でよい）。
11. **第1-11-1号 特定技能所属機関概要書**（D10）: 公式の docx（https://www.moj.go.jp/isa/content/001338980.docx、取得 2026-10-20、Last-Modified 2024-04-01、SHA-256 05f0e9516cabda90dcc30ec11eecb73812ac64722398641d72a7ed23e16e5fc0、改正日の記載なし）の写しに、道具 `tools/forms/make_application_templates.py 1-11-1` で差込タグを置いた（ADR-0026 と同じ作り）。
    - 1 所属役員: 基準日に在任の役員（取り消していない・就任日が基準日以前・退任日が基準日より後か空）を登録の順に 5 人まで。5 人を超えると警告（「別紙のとおり」と書いて別紙を添付する）。
    - 2 決算状況: 決算期末が基準日以前の、新しい 3 年度（前年度・前々年度・前々々年度）。損益のマイナスは「－」。
    - 3 基準適合性: 基準日までの最新の申告の版の人数。行方不明者が 0 人なら「該当なし」、1 人以上なら責めに帰すべき事由の有無で印を付ける（有無が未入力なら印を付けない）。
    - 4・5: 支援計画の全部を委託するので記載不要（空のまま）。
    - 作成年月日（基準日）・受入れ機関の名称・作成責任者（初期値は受入れ機関の代表者の役職・氏名）。作成責任者が無ければ生成不可。役員・決算・人数が無ければ警告（受入れ機関の詳細へ）。
    - 申請の書類の一覧（第2表の 1・2・3 の行）から、雇用契約を対象に生成する（`application_sets` の行を「生成」にした。一括生成の対象）。署名は要らない（作成責任者の記名だけ）。
12. **雇用契約・支援計画の項目**（主たる職種・同等の有無・(6)(7)(9)(10)・支援計画 (15) など）は T46 では足さない。T47 の対応表で、版に足すか申請ごとに入れるかを決める（計画の T46 の表では「足す（台帳）」としていたが、ブロック A の分け方〔T46-D11〕の外だった）。

## 影響

- seed_dummy の住所は架空の市（「サンプル市」）なので、分けられない印が出る（T55 でダミーの台帳に T46 の項目を足すときに直す）。
- ツールの新しい版が出たら、道具で JSON を作り直し、テストで使う表がそろっていることを確かめる（T53 の様式マスタの版と一緒に）。
