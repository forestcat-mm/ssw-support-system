## 決定

### 文言（A1・A2・D2）
- 画面の文言に、開発中のタスク番号（T35 など）を出さない。`tests/test_i18n.py` で、訳とテンプレートの直書きを確かめる。
- 表の行を足すボタンは「〜を追加」にそろえる。
- 同じ英語の文言で意味が違うものは、文脈（pgettext）で訳を分ける。
  - `level`: キャリアアッププランは「レベルの名前」、期限は「警告レベル」
  - `basis date`: 届出と生成物
  - `required`: 届出と申請の書類の一覧
  - `attached`・`not attached`: 申請の書類の一覧と交付の控え
- 分けた msgid は `AMBIGUOUS_MSGIDS` に載せ、文脈なしで使ったらテストで落とす。同じ英語の使い回しは、ほとんどが同じ意味なので、全部の msgid は検査しない（載せた表だけを検査する）。

### ダッシュボード（A3。A3-D2 は人の補足のとおり）
- 加入の更新・支援委託契約の更新は、受付の日（有効期限の 1 か月前・終了日の 3 か月前）に起票する（今のとおり）。
- 「今後の予定」の区分を足す。中身は、今日から 6 か月先までの期限のうち、まだタスクになっていないもの。期限は起票と同じ規則で計算する（`filings.deadline_candidates`。タスクの行は作らない）。
- 担当者の無いタスク（受入れ機関・自機関の期限など）は、担当者で絞った一覧に混ぜない。「担当者なし（受入れ機関の期限など）」の別の区分にして、全員に出す。

### 雇用契約・事業所の入力（B1〜B4）
- 業務区分のチェックボックスを絞る。事業所の画面は分野で、雇用契約の版の画面は事業所の業務区分で絞る。保存の検査はサーバーで行う。
- 所定労働時間（日・週・月・年、勤務の形の 1 日）は「時間」と「分」の 2 つの欄で入れる。保存は分のまま。休憩は分。
- 賃金の締切日・支払日は定番の選択肢（毎月末日・5 日〜25 日。支払日は当月・翌月）と「その他（自由入力）」にする。

### 在留情報・住所・連絡先（B5・B6）
- 新規登録の任意の区画の印は「入れる場合は必須」にする。入国前の外国人には注記を出す。
- 最新の在留情報が在留資格認定証明書の行なら、在留期限としては扱わない（期限の印を出さない）。詳細には証明書の有効期限として出す。
- 連絡先の適用開始日は任意にし、欄の最後に置く。空なら登録日の順に並べる。

### 事前ガイダンス・生活オリエンテーション（B7）
- 記録の担当者の欄の名前を「説明した担当者」にする。確認書の「説明者の氏名」は、今のとおりこの担当者。
- 通訳は「通訳なし・説明した担当者が通訳した・別の人が通訳した」から選ぶ。「別の人」のときは、通訳した人の氏名・所属と言語（支援言語）を必須にする。
- 既存の記録は、行を書き換えない。表示のときに、通訳の欄に字があれば「別の人」、無ければ「なし」とみなす。

### 健康診断の受診日と時期（B8。B8-D1 は (a)、時期は人の補足のとおり申請の種類で分ける）
- 健康診断の 3 種類の添付に「受診日」を持つ（`Attachment.examined_on`）。新しい添付では必須で、未来の日は入れられない。所見などの中身は持たない。既存の添付は空のままにし、「受診日が未入力」と出す。
- 申請の書類の一覧の健康診断の行では、基準日（申請の予定日）から遡って時期を確かめる（`HEALTH_CHECK_MONTHS`）。外れていれば「受診が古い」の警告にする。
  - 認定: 3 か月
  - 変更: 1 年
  - 更新: 一覧に健康診断の行が無い
- 変更の「日本の医療機関で」は、システムでは確かめない。
- 添付は、申請の書類の一覧の行と、基本タブの健康診断の書類の欄から、モーダルで行う。

### 申請の書類の一覧（B9・B10）とモーダルの部品
- 状態を先頭の列にする。行の左の線と地の色で分け、状態の文字も必ず出す（色だけに頼らない）。
  - 不足（未生成・未添付・期限切れ）: 赤
  - 確かめが要る（ほかの版・受診が古い・受診日が未入力）: 黄
  - 済み: 緑
  - システムの外・判断しない・生成中: 灰
- 一覧では生成前の検査を流さないので、「生成不可」は一覧には出さない。未生成と同じ赤になり、生成のモーダルの中で検査の結果として出る。
- モーダルの部品（forms.js の `initModal`）:
  - `a[data-modal]` は、リンク先の画面の `[data-modal-content]` を `<dialog>` に読み込む。中のフォームは fetch で送る。
  - 保存して移るときは、サーバーが 204 と `X-Modal-Location` を返す（`ModalRedirectMiddleware`）。`data-modal-return` があれば今の画面を読み直し、無ければ移り先を開く。
  - JS が無いときは、ふつうのリンクとして動く。外部のライブラリは使わない。
- 生成はモーダルで行い、一覧に戻る。生成を依頼した後、ジョブが終わる前は「生成中」と出す。

### 委託料の内訳（B11）
- 内訳は、支援委託契約の画面の委託料の欄の「内訳」から、モーダルで入れる。行はフォームの中に置いたままにし、契約と一緒に 1 回で保存する（`host_records.save_support_contract(fees=...)`）。
  - 入力中に合計を出し、委託料と合わないときは知らせる。
  - 合わないまま閉じると、「委託料を内訳の合計に直す」か「戻って内訳を直す」かを選ぶ。
  - 委託料が空なら、内訳の合計を入れる。
- 行を全部消すと「内訳なし」。内訳の行を送らない保存（内訳の欄の無い送信）では、内訳を変えない。内訳が変わっていなければ、行を作り直さない（監査ログに同じ行の削除と作成を残さない）。
- 内訳の別の画面は外す。その URL（生成前の検査の「直す」が指す）は、契約の画面に移って内訳を開く。
- 保存の検査（合計＝月額）と、第3-3-1号の判定（月額で判定）は今のとおり。内訳だけの変更では届出を起票しない。

### 報酬の説明（B12。B12-D1 は (a)）
- 「台帳と契約から入れる」で、次を入れる。保存はせず、入れた後も人が直せる。
  - 申請人の職務内容: 契約の版の従事する業務
  - 報酬の単位: 時間給なら時間給、ほかは月給（日給は第1-4号に書けないので、月給の換算額にする）
  - 経験年数の目安: 在留情報（取消を除く）に技能実習3号の行があれば 5、2号の行だけなら 3
- 技能実習の修了は台帳に無いので、在留情報からの目安とし、修了の確認は人が行う注記を出す。
- 画面の上に、生成のときに台帳と契約から入る項目（氏名・年齢・性別・報酬）を見せる。

### 入力の補助（B13・B14・B17。B13-D1 は (a)）
- 番号（法人番号・在留カード番号・旅券番号）・郵便番号・電話番号・メール・金額は、欄を離れたときに同じ規則で直して、欄の下に知らせる。形式が合わないときも知らせる。
  - 規則は `services/normalize.py` と forms.js の `NORMALIZERS`。保存のときもフォームで同じ規則で直す（`StyledFormMixin._clean_fields`）。サーバーの形式の検査は今のとおり。
  - 郵便番号は 7 桁なら 000-0000 にする。電話番号はハイフンの仲間を「-」にそろえる。金額はカンマ・円・空白を外す。
  - 金額の欄は、全角とカンマを受けるために文字の欄（数字の入力）にする。
  - カナは、外国人の氏名のカナだけを直す。ほかのカナの欄は、ふりがなをひらがなで入れることがあるため。
  - 押している間に欄を離れたとき（保存のボタンを押したとき）は、知らせを離した後に出す。先に出すと下の部品がずれて、クリックにならないため。
- 必須の欄のラベルは太字にする（「必須」の印も残す）。「入れる場合は必須」も同じ。
- 入力のフォーム（`form.form` の POST）の欄が変わったら、保存していない変更の印を付ける。
  - 画面の中のリンクで移るときは「保存せずに移動しますか」のダイアログを出す。
  - 閉じる・再読み込み・戻るときは、ブラウザの確かめ（beforeunload）を出す。
  - 保存のボタンでの送信では出さない。
  - e2e では、ブラウザの確かめを「移動する」で閉じる（`e2e/conftest.py`）。

### 帳票の字の高さ（A6 の仕組み・A8）
- 字を小さくする処理（fit）は、欄の幅だけでなく高さ（行の高さ、または `fit_area` の結合範囲）にも収める（`form_xlsx.height_limit`）。全欄の高さのテストを足した。
- 第1-17号の O44・AO371 は、人が案 (e) を選んだ。PDF の一時の写しでだけ結合し、字は小さくしない（ADR-0032）。
- Excel の構造の比べで styles.xml も比べる。書き込みは styles.xml を変えないため、外す理由が無かった（C-6 の取り消し）。

### 操作の見せ方（B15。人が案2 を選んだ。2026-10-19 追記）
- 画面の幅にかかわらず、主な操作 1 つのボタンと「…」のメニューにそろえる。危ない操作（終了の登録・終了の取消・記録の取消）は、メニューの中の赤字にする。
  - 対象: 受入れ機関の詳細の表（支援委託契約・加入・協力確認書。事業所は編集のボタンだけ）、外国人の契約タブ、記録の詳細（ガイダンス・相談・面談・交付・そのほかの記録）。
  - 添付の行ごとの「取消」のボタンは、操作の並びではないので今のまま。
- メニューは `<details class="menu">` で作る。
  - JS が無くても開け閉めでき、開くと下に並ぶ。
  - JS があれば、ボタンの下に浮かせる。表の横の送りに切られず、画面の端からはみ出さない。
  - メニューの外を押す・Esc・ほかのメニューを開くと閉じる（Esc のあとはボタンにフォーカスを戻す）。
- 390px で、どの画面も右にはみ出さないことを、通しのテストで確かめる（`e2e/test_page_widths.py`）。ダミーデータで画面の中のリンクを URL の形ごとにたどり、114 の形を見る。表は表の中で横に送る。報告の見本（B15-2-sp.png）で表がはみ出していたのは、見本のページの作り（メニューを見せるために表の送りを外した）のためで、業務画面では起きていなかった。

### 日付と時刻の入力（B16。人が案2 を選んだ。2026-10-19 追記）
- **日付**: 文字の欄にする。
  - 欄を離れると、次の形を 2026-07-10 の形に直して、曜日を出す: 「20260710」「2026/7/10」「2026年7月10日」「R8.7.10」「令和8年7月10日」（令和・平成・昭和。元年も受ける）。
  - 横の「カレンダー」で、年・月を選べて「今日」があるカレンダーを浮かせる。日を押すと入り、Esc・外を押す・「閉じる」で閉じる。「今日」はサーバーの今日。
  - 保存のときも、サーバーで同じ規則で直す（`services/normalize.py` の `date`）。
- **生年月日**: 年・月・日の選択（`DateSelectWidget`。今年から 80 年前まで）。
- **年月だけの欄**: 今のところ無い。出てきたら、年・月の選択にする。
- **時刻**: 1 つの文字の欄にまとめる。
  - 直接入れても（「930」「9:30」「9時30分」→ 09:30）、5 分刻みの選択（datalist）から選んでもよい。
  - 保存のときもサーバーで直す（`time`）。

## 未確認の点

- 健康診断の時期は、申請の日から数える。申請の日はシステムに無いので、一覧の基準日で数える。基準日を申請の予定日にするのは、人の運用とする。
- 提出書類一覧・確認表（ADR-0026 の版）には健康診断の時期の定めが無く、時期は運用要領の留意事項だけによる。一覧や運用要領が改正されたときは見直す。
