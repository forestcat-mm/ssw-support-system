# ADR-0039: 在留申請オンラインの一括登録用ツールへの書き込み（一括申請）

- 状態: 採用（T47 書き込みの基盤・T48 生成・T49 申請の書類との合わせ）。不在の間の指示（2026-10-20）により、決めてほしい点はおすすめで決めた（`.checks/phase4/blockB/plan.md`・`.checks/phase4/decisions-blockBCD.md`）
- 日付: 2026-10-20
- 関連: ADR-0018（Excel の書き方）・0038（台帳の項目）、`docs/tasks-phase4.md` の D1〜D4

## 背景

在留申請オンラインの一括申請（認定・更新・変更）は、入管の配るマクロつきのブック（xlsm）で行う。担当者が入力シートに 1 人 1 行で値を入れ、マクロ（「選択」→「出力」）が入力チェックをして CSV を作り、その CSV を在留申請オンラインシステムに上げる。ツールが出した CSV 以外は使えない（操作マニュアル 001369283.pdf 53 頁）。システムは値を入れた xlsm までを作る（D1）。

## 決定（T47）

1. **様式マスタへの登録**（T47-D1）: 様式 ID `bulk-coe`（認定）・`bulk-ext`（更新）・`bulk-chg`（変更）、適用開始日 2026-06-04、方式 `xlsm-rows`（新しい方式）。配布の xlsm をそのまま `templates/forms/bulk-*/2026-06-04/original.xlsm` に置く。
2. **列の表**: 道具 `tools/forms/extract_bulk_columns.py` が、ブックの隠しシート「列項目TBL」から、特定技能で使うシート（共通シート・区分V・更新と変更は同時申請）の欄（シート・列・項目名・チェック種別・桁数・桁数一致・必須・業務コード・区切り・改行・特定技能の CSV 列・リスト連動の親・チェック親列と値・CSV ヘッダ名）を `mappings/bulk-*/2026-06-04.columns.json` に書き出す。表示シート制御マスタから特定技能の非表示の列（無い）も読む。表はブックの SHA-256 つきで、読み込み（`make forms`）のときにブックと合っているかを確かめる。欄の対応（データのキー→列）は `2026-06-04.json`（T48）。
3. **選択肢の表**: ADR-0038 の `services/data/immigration_codes.json`（3 本の名前定義から）。手続で違う表は手続ごとに引く。
4. **書き方**（T47-D2。`services/form_xlsm.py`）: 入力シートの 8〜307 行に、表示名をインライン文字列で書く。セルの書式は残す。A 列（行の番号の数式 `IF(COUNTBLANK(…)<>…,ROW()-7,"")`）は数式を残し、計算の結果（人の番号）をキャッシュとして書く（D2）。メニューの在留資格（D15）に「特定技能 Specified Skilled Worker」を書く。ほかのファイル（vbaProject.bin・ActiveX・ブックの構成の保護・シートの保護・隠しの状態・入力規則・名前定義・計算の設定）は 1 バイトも変えない。書く行は 1 回の走査で見つけて組み立て直す（区分V のシートは 3MB、300 人×285 列）。
   - VBA を読んで確かめたこと: 「出力」は、「選択」を押したときの D15・D17 と今の値が同じかを確かめる（Select_Click・output。9656 対応）。そのため担当者はブックを開いた後に必ず「選択」→「出力」を押す。D15 を変えたときのイベントは「主たる活動内容」（D17）を消すだけなので、D15 を書いておいてよい。
5. **入力チェックの写し**（T47-D3。`services/bulk_checks.py`）: 列の表を使い、VBA（mdlChk・mdMain）と同じ条件で確かめる。
   - チェック親列があり、親の値がチェック親値に当たらない列は確かめない（頭の「在」は共通シートの列。親値「｜」で複数、親列「,」で複数、親値が空なら「親が空のとき」）。
   - 文字種（removeChr と同じ文字の範囲）・桁数（桁数一致）・必須（特定技能の CSV 列があるものだけ）・業務コード（表示名がツールの表にある。リスト連動の子は親の値の連動の表）。
   - リスト連動の子に値があり親が空ならエラー（chkParentForChild）。
   - 同時申請は、再入国・資格外活動・就労資格証明の「有」の範囲だけ確かめ、どれも無ければ必須だけ。認定のブックの同時申請は特定技能の CSV に出ないので確かめない。
   - 生年月日の欄は文字種が「半角数字」で、日付としては確かめない（ツールも不詳の 99999999 を受ける）。
6. **元のブックとの一致**（T47-D4）: テストで、書いたブックの中のファイルの名前と順、書いたシート以外のすべてのファイル、書いたシートの書いた行以外の XML が、元のブックと同じことを確かめる。openpyxl は読み戻しの確かめにだけ使う。
7. **300 人を超えるとき**（T47-D5）: 300 人ごとにファイルを分ける（T48）。

## 決定（T48 認定・変更・更新の生成）

8. **欄の対応**: 道具 `tools/forms/make_bulk_mappings.py` が、列の表の項目名を正規化した名前（空白・括弧の番号を除き、全角数字を半角に）と同じ名前の何番目かで、データのキーを当てる（3 つの手続で列の位置・項目名の番号が違っても同じ表で当たる）。出力 `mappings/bulk-*/2026-06-04.json`。コードの欄は format=code（業務コードを表示名にして書く。リスト連動の子は親の値の連動の表）。必須（条件なし・特定技能の CSV 列あり）なのにキーが無い欄があれば道具が止まる（T46 の完了条件。今は 0 件。当てていないのは任意の欄と条件つきの欄: 派遣先・職業紹介事業者・取次機関・(27)(28) 労働者派遣・(33)〜(41) 自社で支援する体制〔全部委託なので空〕・告示の基準の任意の欄）。
9. **値**（`services/bulk_application_data.py`）: 台帳（ADR-0038 の項目・雇用契約の基準日の版・支援計画の基準日の版・担当者と支援責任者の基準日の履歴〔ADR-0037〕・受入れ機関の最新の申告と決算・事業所）と申請ごとの入力から作る。主なきまり:
   - 国籍・分野は日本語の名前でツールの表に当てる。業務区分は表示名の頭で当て、飲食料品製造業分野はツールに「飲食料品製造業全般」しか無いのでそれに当てる。
   - 現に有する在留資格は、特定技能１号・技能実習（イ・ロ。T46-D8）・留学・特定活動をツールの表に当てる。技能実習のイ・ロが空なら空（検査が知らせる）。
   - 所定労働時間は分を時間にして整数（ツールは半角数字 4 桁）。基本給の時間換算額は版の値、無ければ月額 ÷ 月の所定労働時間（切り捨て）。
   - 登録番号は「１９登０００１２３」（漢字と全角数字の 9 字）。全角だけの欄（住所の以降・氏名以外の名前など）は全角にする。
   - 通算在留期間は、台帳の特定技能1号の在留情報の行の期間（許可日から次の行の許可日か満了日・基準日）と台帳の外の申告の月数を足す（未確認の点）。
   - 保証金と費用は、事前ガイダンスの記録があればそれ、無ければ申請ごとの入力。
   - 同時申請（更新・変更）は「無」にする。
10. **申請ごとの入力**（T48-D1・D2）: 一括申請（BulkApplication: 手続・基準日・表題・取次者）と外国人ごとの行（BulkApplicationEntry: 代理人〔受入れ機関の申請担当者〕・入力・犯罪の申告）。入力は、配偶者・職業・認定の入国の項目と申告（出入国歴・申請歴・退去強制）・希望する在留期間・理由・ED 番号・受領方法・通知のメール・フリー欄、雇用契約の主たる職種・他職種・同等の有無・(6)(7)(9)(10)、支援計画 (15)、保証金と費用（記録が無いとき）。同じ外国人の前の行の答えを初期値にする。雇用契約・支援計画の項目は契約の版に足さない（ブロック A の確かめてほしい点。後から版に移せる）。
11. **犯罪の申告**（T48-D3。ADR-0038 決定 6）: 有無と内容は暗号化の列（監査ログは `***`）。入力の画面に出すのは、その外国人の担当者と管理者（workers.sensitive_documents）だけ。一覧には有無も出さない。犯罪の申告が「有」の行を含む xlsm は、管理者と、その行すべての外国人の担当者だけがダウンロードできる。生成のスナップショットでは犯罪の欄を `***` にする。
12. **画面**（T48-D4）: ナビの「一括申請」→ 作る（手続・基準日・取次者）→ 外国人を追加（無効化していない・雇用契約のある人）→ 行ごとの「入力」→ 外国人ごとの検査の結果（ツールの入力チェックの写し）→ 不足が無ければ「Excel を作る」→「記入済み（編集用）」をダウンロード（監査ログ）。
13. **生成の記録**（T48-D5）: 作った xlsm は一括申請の行に持つ（BulkApplicationFile。追記だけ。様式の版・SHA-256・外国人・要配慮を含むか・スナップショット）。生成は監査ログに GENERATE（一括申請が対象。値は残さない）、ダウンロードは DOWNLOAD。300 人ごとにファイルを分ける。
14. **申告の内容の欄**: ツールの申告の内容の欄の条件はすべて「有 Yes」のときなので、受入れ機関の申告の画面（ADR-0038 決定 10）も「有」のときに内容を必須にした（(29) 労災保険加入等の措置は「有」が通常の答えで、内容が要る）。

## 決定（T49 申請の書類との合わせ）

15. **つなぎ方**（T49-D1）: 一括申請の行ごとに、同じ手続・基準日の申請の書類の一覧（`set_id`・`basis_on`）と「提出用の PDF を作る」へのリンク、同じ手続の最新の統合 PDF を出す。外国人の申請の書類の一覧には、その外国人を入れた一括申請（手続・基準日・作ったファイルの数）を出し、一括申請の画面へ戻れる。一括申請の xlsm と外国人ごとの統合 PDF（添付）を、同じ画面から作れる。
16. **持ち越しの書類**（T49-D2）: 申請人名簿・補助用紙・申請書（省令様式）・複数人の統合 PDF は作らない（D7）。

## 未確認の点

- 2026/06/04 の更新の中身（案内のページ・更新情報・ツールのどこにも書かれていない。前の版を持っていない）。
- 値を XML で書いたブックで、マクロの「選択」「出力」が動き、A 列の数式が同じ結果になるか（Windows の Excel で、MVP 完成後の価値検証で人が確かめる。D4）。
- Mac の Excel でマクロが動くか（ADODB.Stream などを使う）。
- 特定技能1号の通算在留期間の数え方（決定 9 の数え方は仮）。
- 所定労働時間の端数の扱い（整数にした）。
- 同時申請のシートで、どれも「無」のとき、種別（B〜D 列）だけを必須にする VBA（更新・変更の版）が、認定の VBA には無い（認定は同時申請のシートを表示しないので確かめない）。
