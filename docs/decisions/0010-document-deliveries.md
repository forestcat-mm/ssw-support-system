# ADR-0010: 本人への書類の交付は「交付記録」として持ち、キャリアアッププランの未交付は雇用契約ごとに判定する

- 状態: 採用
- 日付: 2026-10-17
- 関連: 仕様書 第4章（分野別の「システムへの反映」）、第6章「署名を要する書類の扱い」、第7章 attachments、ADR-0009、T22、段階3（書類の生成・生成履歴・署名済み書類の回収）

## 背景

受入れ機関（所属機関）には、本人に書類を交付する義務がいくつかある。登録支援機関（自機関）は全部委託を受けて、
その交付を手伝ったり証跡を預かったりする。交付の義務を果たしたことを後から示せるように、
「いつ・どの書類を・どの方法で・誰が交付したか」と、署名済みの控えを記録する。
仕様書 第4章は、書類の種別に「キャリアアッププラン」「実務経験証明書」を持つこと、
飲食料品製造業分野でキャリアアッププランが未交付なら警告することを求めている。

- 1号の実務経験証明書とキャリアアッププランには参考様式が無い（工業の分野参考様式第3-2号は 2号の申請に使う「実務経験に係る証明書」で、別の書類）。
- 令和8年の改正（工業 6/25・飲食 8/28）で、上の 2 つの義務の中身は変わらず、書面に電磁的記録を含むことが明記された（新旧対照表で確認）。

### 未確認の点

- 雇用条件書の写しを交付する義務の根拠（労働基準法第15条・同施行規則第5条の書面の交付）は e-Gov の条文と照合していない。運用要領が明記しているのは署名。
- 経済産業省・農林水産省・協議会の独自のページ（協議会が定めるキャリアアッププランの様式の有無など）は確かめていない。
- 工業の分野参考様式第3-2号（2号）は対象外とし、取得していない。

## 決定

### 交付記録（`DocumentDelivery`）

- 種別は 5 つ: キャリアアッププラン／実務経験証明書／支援計画書の写し／雇用契約書・雇用条件書の写し／その他（書類名を記入。受入れ機関固有の誓約書・社宅契約など）。
- 事前ガイダンス・生活オリエンテーションの確認書（第5-9号・5-8号）は種別にしない。記載例 ★1 のとおり「署名を得て事務所で保管」する書類で、本人に交付する義務が見当たらない（署名済みの確認書は ADR-0009・T21 で扱う）。
- 上書きしない。誤りは取消（理由必須）＋新しい行。変わるのは取消と添付の追加だけ。

| 要領・仕様書の項目 | 保存先 | 備考 |
|---|---|---|
| 書類の種別・書類名 | `kind`・`title`（「その他」は必須） | |
| 交付日 | `delivered_on` | 未来の日は不可 |
| 交付方法（書面を交付／電磁的記録を提供） | `method`：手渡し／郵送／電磁的記録の提供（電子メール等）／その他（`method_note`） | 告示の「交付し、又は提供」 |
| 交付した機関・人 | `delivered_by`（受入れ機関／自機関）・`delivered_by_name` | 義務を負うのは所属機関。手渡しは自機関のこともある |
| 説明 | `explained` | キャリアアッププラン・支援計画書の写しでは必須の扱い（無いと警告） |
| 当該契約 | `contract`（雇用契約） | キャリアアッププラン・実務経験証明書・雇用契約書の写しでは必須 |
| 求めを受けた日 | `requested_on`（任意） | 実務経験証明書だけ。交付日より後は不可 |
| 支援計画の版 | `plan_version` | 支援計画書の写しだけ。交付日から自動で決める（T18 の `plan_version_for`）。交付日に適用されていた版が無ければ保存できない（写しの対象が特定できないため） |
| 書面の言語 | `languages` | |
| 署名済みの控え・受領の記録 | 添付の種別 `delivered_document` | 生成履歴（generated\_documents）との紐づけは段階3 |

- 実務経験証明書の中身（対象の期間・業務）は持たない。任意様式なので、書類の生成（段階3）で決める。
- 置き場所は外国人詳細の「支援」タブの小区分「交付」（「計画」「記録」の横）。第6章が段階3で作るとしている「帳票」タブとは別にする。

### キャリアアッププランの未交付は雇用契約ごとに判定する

- 対象の契約: いずれかの版の就業の場所（事業所）の**分野**が飲食料品製造業分野（`food_manufacturing`）の契約。
  **業務区分では判定しない**（2027-04-01 に「飲食料品製造業」と「水産加工業」に区分が分かれても、両方とも同じ分野のため対象のまま）。
- 対象の契約ごとに、その契約に紐づく取り消していないキャリアアッププランの交付記録が無ければ「未交付」の警告を出す。
  前の契約（転籍前の受入れ機関）の交付記録は、新しい契約の交付に数えない。
- 契約前の交付の判定は、契約の第1版の締結日（`signed_on`）と比べる。
  - 交付日が締結日より後: 「雇用契約の締結より後に交付されています」（強い警告）。**同じ日は警告しない。**
  - 締結日が未入力: 「締結日が未入力のため、契約前の交付か確かめられません」。開始日で代わりに判定しない（締結日より遅いのが普通で、甘く判定してしまうため）。
- 同じ判定の関数（`services.deliveries.career_plan_findings`）を、段階3の生成の検査（仕様書 第4章「未交付の場合は警告」）でも使う。

### 署名済みの控え

- 控えの有無は「取り消していない添付（種別 `delivered_document`）があるか」で判定する（ADR-0009・T21 で揃えた規則と同じ）。
  一覧と詳細で同じ関数（`services.deliveries.has_receipt`）を使う。
- 控えが無いときに警告する種別: キャリアアッププラン・支援計画書の写し・雇用契約書の写し（第6章で署名を要する書類）。

## 影響

- 権限は既存の `support.view` / `support.manage` を使う。監査ログは作成・取消・添付と、閲覧（支援タブの閲覧として 1 件）を残す。
- 段階3で書類を生成するときは、生成履歴から交付記録を作れるようにする（今回の交付記録の列はそのまま使う）。
- 要領が改正されて交付の義務が変わったら、この ADR に追記し、種別を足す（既存の記録の種別は書き換えない）。
