# ADR-0011: 要配慮添付（健康診断の書類）は、担当者と管理者だけが認可つきのダウンロードでだけ取り出せる

- 状態: 採用
- 日付: 2026-10-17
- 関連: 仕様書 第6章「要配慮個人情報を含む添付」、第7章 attachments、第8章、T05（添付のダウンロード）、T23、段階4（在留申請の添付セット）

## 背景

在留申請には健康診断個人票と受診者の申告書（参考様式第1-3号）を添付する。健康診断の結果は要配慮個人情報で、
在留カード番号より一段重く扱う（仕様書 第6章）。これまでの添付は「添付の対象の閲覧権限」で誰でもダウンロードできた。
要配慮の添付は、見られる人をさらに絞り、ファイルの中身・ファイル名が認可の外へ出る経路を塞ぐ。

参照した箇所:

- 様式: 健康診断個人票（検査の結果・医師の診断・医師の署名）、別紙「受診者の申告書」（通院歴・入院歴・手術歴・投薬歴を医師に申告した旨と本人の署名）。
  留意点: 外国語の箇所は日本語の訳文を添付する。「医師の診断」に異常がある場合などは、稼働に問題がない旨の医師の意見書も出す。
- 本体 第4章第1節（2）健康状態に関するもの（印刷の頁 16頁）: 確認対象の書類は健康診断個人票と受診者の申告書。
  受診の時期（認定は申請日から 3 か月以内、変更は 1 年以内）、個人票は本人が理解できる言語で作成し日本語訳も出す。
- 個人情報保護法 第2条第3項（要配慮個人情報。病歴等）、同施行令 第2条第2号（健康診断等の結果）・第3号（健康診断等の結果に基づく指導・診療）。

### 未確認の点

- 受診者の申告書の文面は「申告した」事実で健康診断の結果そのものではない。受診の事実を示すため、仕様書 第6章のとおり要配慮として扱う（法令上の区分の判断ではない）。
- 個人情報保護委員会のガイドラインは読んでいない。
- 本番の S3 互換ストレージの事業者は未定。「公開アクセスの遮断」「保存時暗号化」の設定方法と、その確かめ方は事業者を決めたときに本番準備で確かめる。

## 決定

### 要配慮の種別と印

- 種別: 健康診断個人票（日本語訳を含む）／受診者の申告書／医師の意見書（稼働に問題がない旨）。外国人（`ForeignWorker`）にだけ添付できる。
- 添付に `is_sensitive` の列を持つ。値は保存のたびに種別から決め（手で付け外ししない）、DB の制約で「要配慮の種別 ⇔ 印あり」を保証する。
- 保持期限の目安 `retention_until`（任意の日付）を持つ。過ぎたら一覧で印を付ける。自動では削除しない（削除の時期と手順は運用で決めてから別のタスクにする）。

### ダウンロードの判定（`services.attachments.can_download`）

1. 添付の対象の閲覧権限（これまでどおり。`<app>.view_<model>` を操作に読み替える）。
2. 要配慮の添付は、さらに次のどちらか:
   - その外国人の担当者（`ForeignWorker.assigned_staff.user` がそのユーザー）
   - 操作 `workers.sensitive_documents` を持つ人（管理者ロールだけに付ける）
3. 成功したダウンロードは監査ログ `download` に 1 件。要配慮の添付を拒否（403）したときは `download_denied` を 1 件残す。

### ファイルは認可つきのダウンロードからしか取り出せない

| 経路 | 保証のしかた |
|---|---|
| アプリが URL を作る | 添付の `file` 列は URL を返さない（`PrivateFieldFile.url` は例外を投げる）。公開 URL も署名付き URL も作れない。ファイルは `AttachmentDownloadView` が `can_download()` を通してから中身を流して返す |
| 開発環境（`FileSystemStorage`、`/app/media`） | `MEDIA_URL` の配信を URL 設定に置かない（`runserver` は静的ファイルしか配らない）。保存先はコンテナの中で、Web サーバーの公開ディレクトリの外。テストで `/media/...` が 404 であることを確かめる |
| 本番（django-storages の `S3Storage`） | バケットは非公開（公開アクセスの遮断・公開読み取りのバケットポリシーなし）。システムチェックで `DJANGO_STORAGE_OPTIONS` の `default_acl` が `private` か未設定であること、`custom_domain` が無いこと、`querystring_auth` を false にしていないことを強制する（違えば起動時のチェックで止まる）。アプリは上のとおり URL を作らないので、署名付き URL も発行しない。本番準備で、オブジェクトの URL への匿名のアクセスが拒否されることと、保存時暗号化が有効なことを確かめる |
| Django admin | 添付の一覧・詳細・インラインで、要配慮の添付はファイル名とダウンロードのリンクを出さない（「要配慮」と種別・ID だけ） |

### ファイル名を記録・表示に出さない

- 要配慮の添付の `original_filename` は監査ログの差分で `***` にする（作成・更新・取消のすべて）。保存先のパスは元から UUID でファイル名を含まない。
- 要配慮の添付の表示名（`str()`。監査ログの対象の表示・admin で使う）は「種別 #ID」にする。
- 画面の通知文（「添付を追加しました」など）にはファイル名を入れない（今までどおり）。
- 業務画面の一覧では、ダウンロードできない人にファイル名とリンクを出さず、種別・アップロード日だけを出す。

## 影響

- 担当者が変わると、前の担当者はダウンロードできなくなる（判定はダウンロードの時点の担当者）。
- 担当者がログインユーザーを持たない（`Staff.user` が空）外国人の要配慮の添付は、管理者だけがダウンロードできる。
- 段階4の在留申請の添付セットに健康診断の書類を含めるときも `can_download()` を通す（一括の出力もこの判定に従う）。受診の時期（3 か月・1 年以内）の検査は段階4で行い、検診日を持つかもそのときに決める。
