# ADR-0012: 定期届出の元データは現行の様式（参考様式第3-6号・別紙1）から逆算し、特異事案報告（第4-3号）の候補と照合する

- 状態: 提案（仕様書の用語集・F14 の訂正を含む）
- 日付: 2026-10-17
- 関連: 仕様書 第2章（用語集「定期届出」）、第5章 F06・F14、T10、T19、T20、T18、T24、T24a、T27、ADR-0007、ADR-0008

## 背景

タスク表の T24 は「外国人×10項目の実施有無（と実施日）」「相談の一覧（分類・対応状況・通報の有無）」「通報の有無（面談・相談）」を
返す関数としていた。現行の公式様式から逆算すると、この 3 つはどれも定期届出の欄に無い。
旧様式（四半期ごとの支援実施状況の届出）の考え方が残ったものと考えられる。

参照した箇所:

- 本体 第9章第2節 第4（1）支援実施状況の届出（印刷の頁 161〜162頁）: 登録支援機関は、毎年5月31日までに、前年4月1日〜当年3月31日の期間に係る事項を、
  全部委託をした所属機関を経由して（連名で）届け出る（入管法 第19条の30第2項、施行規則 第19条の24）。省令で定める事項は
  外国人の氏名・生年月日・性別・国籍・在留カード番号と、所属機関の名称・住所。確認対象の書類は第3-6号と別紙1。
  実施予定の支援を実施しなかった場合、通報・ハローワーク相談をした場合、非自発的離職者の転職支援をした場合は、特異事案報告で報告する。
- 本体 同 第4（2）特異事案報告（印刷の頁 162〜163頁）: 該当することとなった日から 14 日以内（施行規則 第19条の24の2）。
  想定される内容: 計画の支援を実施できなかった、行方不明・死亡、行政機関等の他機関への相談等（ハローワークへの相談などの転職支援を含む）、所属機関の基準不適合の把握。
- 別紙1: 事業所ごとに作成。期間中の在籍者（期間中に受入れを終了した者は終了まで）。「支援の形態」「支援担当者名・電話番号」は 3月31日時点。
  「随時届出（報告）の提出状況」は、義務的支援の実施が困難になる事由が発生したのに随時届出（報告）を出していない場合だけ印を付け、理由書を添付する。
- 第4-3号: 報告の事由は A 支援の実施困難（対象の支援項目 11 種）／B その他の特異事案（職業生活・日常生活・社会生活の問題の把握、所属機関の基準不適合、その他）。

### 未確認の点

- 施行規則 第19条の24・第19条の24の2 は本体の引用で読み、e-Gov とは照合していない。
- 作成要領の別紙1 の頁（14〜15頁）は図で、PDF から文字を取り出せなかった。欄の意味は別紙1 の注意書きで確かめた。
- 第4-3号の記載例の本文は読んでいない。通報・ハローワーク相談・転職支援が A と B のどちらに当たるかは、元データの側では決めない（候補の種類だけを返す）。
- 支援担当者の履歴（いつから誰が担当か）を持っていないため、3月31日時点の担当者は「元データを作った時点の担当者」で代える。担当者が年度をまたいで替わった場合は人が直す。

## 決定

### 用語と期間（仕様書の訂正の提案）

- 用語集「定期届出」は「毎年4月1日時点の状況を…」ではなく、
  **「前年4月1日〜当年3月31日（届出対象期間）について、当年4月1日〜5月31日に提出する年1回の届出。支援の形態・担当者は3月31日時点」** とする。
- F14 の「4月1日時点の受入れ・支援実施状況」も同じく「届出対象期間の受入れ・支援実施状況（3月31日時点の支援の形態・担当者）」とする。
- 仕様書（Claude Docs）の更新は人が行う。コードとテストは上の定義で作る。

### T24 の元データ（`services/periodic_report.py`、画面は作らない）

1. **別紙1 の支援の欄**（`support_rows`）: 届出対象期間中に 1 日でも自機関が全部委託を受けていた 1号の外国人について、雇用契約ごとに 1 行。
   事業所（3月31日時点、期間中に終了した契約は終了時点）、受入れ開始日・終了日、支援の形態（全部委託・機関名）、
   支援担当者と電話番号（担当者の所属事務所の電話）、在留情報の最新行の ID（番号は復号しない。復号と監査ログは段階4の書き出しで行う）。
   無効化した外国人は含めない。3月31日に在籍していれば（契約の満了日がちょうど 3月31日でも）受入れ終了日は書かない。
2. **特異事案の候補**（`special_events`）と、第4-3号の届出タスクとの照合。
   - 候補: 定期面談の通報（T19）、相談の経過の通報・ハローワーク相談（T20）、非自発的離職時の転職支援（T18）、
     計画で実施予定「有」の行の記録が無いもの・定期面談の期限の超過（「要確認」。断定しない）。
   - 候補の日付: 通報日・相談日が入っていればその日、無ければ記録の日。
   - 照合: 同じ外国人の第4-3号の届出タスク（取消を除く）のうち、事由発生日が候補の日付の前後 14 日以内のもの。
     結果は「一致（同日）」「近い日付のタスクあり」「該当なし」の 3 段階で、タスクの ID とあわせて返す。**「報告済み」とは断定しない。**
   - 照合の方法は差し替えられるようにする（T24a で起票の元の記録への参照が付いたら、参照による一致に置き換える）。
3. **社内の確認・帳簿用の集計**（`support_overview`）: タスク表の元の 3 項目（外国人×10項目の実施有無と実施日、相談の一覧、通報の有無）。
   定期届出の欄ではないが、帳簿（支援の実施に関する管理簿）と社内の確認、T27 の完了条件 A に使う。

### T24a の追加（第4-3号の届出タスクの自動の起票）

- 通報（T19 の定期面談・T20 の相談の経過）、ハローワーク相談（T20）、非自発的離職時の転職支援（T18）を記録したときに、
  第4-3号の届出タスクを自動で起票する（期限は事由発生日から 14 日。T10・ADR-0008 と同じ数え方）。記録の取消での巻き戻しは T19 に合わせる。
- 理由:
  - 第4-3号は 14 日以内の報告で、出し忘れると定期届出の別紙1 で「提出していない」に印を付け、理由書を出すことになる。
    記録の時点でタスクにすれば、期限ダッシュボード（F06）で漏れを防げる。
  - 起票のときに元の記録への参照（`trigger_details`）を付ければ、T24 の照合を日付の近さではなく参照で確定できる。
  - T24 は元データを返すだけ（services のみ）にし、記録の画面とタスクの起票を変える変更は 1 タスクに分ける（1 依頼 1 機能）。

## 影響

- タスク表（`docs/tasks-phase2.md`）の T24 の文言、T27 の完了条件 A の「集計」の行を直し、T25 の前に T24a を足す。
- 既存の届出タスクの種別 `support_difficulty` は、登録支援機関の特異事案報告（第4-3号）として扱う（表示名は fix のコミット `cdeef7b` で修正済み）。
- 段階4の定期届出の Excel（別紙1）の生成は、`support_rows` と照合の結果を使い、「随時届出（報告）の提出状況」の印は人が確かめて付ける。
