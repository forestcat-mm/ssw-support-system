# ADR-0007: 支援実績の種別ごとの選択肢は、参考様式第1-17号の細目の符号で保存する

- 状態: 採用
- 日付: 2026-10-17
- 関連: 仕様書 第5章 F05、第7章 support\_records、ADR-0006、T18、T24（計画と実績の突き合わせ）

## 背景

T18 の支援実績は、種別ごとの最小限の欄を `SupportRecord.details`（JSON）に持つ。そのうち「何をしたか」の
選択肢（例: 住居確保の「口座開設」）は、T24 で支援計画の行（ADR-0006 の `SupportPlanActivity`）と突き合わせる。
画面の表示名は短くするため様式の文言と違う。表示名を変えても過去の記録と計画の対応が崩れないように、
保存する値と様式の項目の対応を固定しておく必要がある。

## 基準にした様式

| 項目 | 値 |
|---|---|
| 様式 | 出入国在留管理庁 参考様式第1-17号「1号特定技能外国人支援計画書」（EXCEL） |
| URL | https://www.moj.go.jp/isa/content/001459168.xlsx （掲載ページ: https://www.moj.go.jp/isa/applications/ssw/10_00020.html ） |
| 取得日 | 2026-10-17 |
| SHA-256 | `e5d6e4a65a6117b7bb8a1668d56712b3119e74baf19e150d253a8a7e79e68c81` |
| 改正日 | **未確認**。ファイル（文書のプロパティ・ヘッダー・本文）にも、掲載ページ（10\_00020.html・01\_00120.html）にも、この様式の改正日の記載が無い。版は上の URL・取得日・SHA-256 で特定する。改正日が分かったらこの表に追記する |

細目の文言は `backend/services/data/support_plan_1-17.json`（同じ URL・取得日・SHA-256 つき）に持つ。
支援計画（ADR-0006）と同じファイルから逆算している。

## 決定

- 選択肢の値は、様式のⅣ欄の細目の符号（`<区分>.<細目>`。区分 3 はア＝`3a`・イ＝`3b`）にする。
  文言は `support_plan_1-17.json` の `labels` のキーと同じ。
- 様式に対応する細目の無い「その他」は `other` にする（計画の自由記入の行 `<区分>.free` と突き合わせる）。
- 種別「公的手続への同行」は選択肢を持たない（様式では生活オリエンテーション 4 の b に含まれ、計画の行は `4.main`）。
  手続の名前と窓口を文字で持つ。
- 住居確保の「物件の種類」は、計画の住居の概要（3アｄ）と同じ値（`owned`／`leased`、`PropertyType`）。
- 種別「日本人との交流促進」の `7.a`・`7.b` は、計画では 1 つの行（`7.main`）が両方を受け持つ。
- 対応は `services/support_records.DETAIL_FIELDS` に持ち、テスト（`tests/support/test_support_records.py`）で
  「符号が様式の細目に存在し、種別の区分と一致する」ことを固定する。

## 影響

- T24 は、記録の `details` の符号から計画の行（上表の右端）を引き、計画で「実施予定 有」の行に記録があるかを見る。
- 画面の表示名は変えてよい（保存する値は変えない）。
- 様式が改正されて細目の符号が変わったら、新しい様式の版で ADR を足し、旧符号の記録は旧版の対応で読む
  （保存済みの記録は書き換えない）。
