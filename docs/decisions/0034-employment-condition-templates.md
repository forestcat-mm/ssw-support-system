# ADR-0034: 雇用条件のひな形

- 状態: 採用（T41。不在の間の指示により、決めてほしい点はおすすめ (a) で決めた）
- 日付: 2026-10-19
- 関連: 仕様書 第5章 F03、第7章 employment_contracts・host_organizations。ADR-0016（雇用契約の版）・0023・0031（修正 1 回目 B2〜B4）。計画 `.checks/phase3/T41-T43/plan-T41.md`、記録 `.checks/phase3/T41-T43/decisions.md`

## 背景

同じ受入れ機関の外国人の雇用条件は、給与や契約期間などを除いて同じことが多い。契約の登録は、第1-6号の Ⅰ〜Ⅸ と別紙1 の全部の欄を毎回入れていた。

## 決定

1. **ひな形は受入れ機関ごと**（新しいモデル `EmploymentConditionTemplate`、テーブル employment_condition_templates。追加だけ）。
   - 版の入力（`VersionForm` の欄）と同じ項目の値を JSON で持つ（T41-D1）。日付は ISO、時刻は HH:MM、数は文字、事業所・業務区分は ID。
   - 交代制・手当・控除の行も持つ。賃金の締切日・支払日は版の項目なので、そのまま持つ。
   - 変更日・変更理由・締結日は契約ごとの値なので持たない。
2. **外国人ごとに入れる項目に印**（marked）を付ける。明細の行は種類（交代制・手当・控除）ごとに付ける。
3. **契約の登録**: 画面の上でひな形を選び、「ひな形から入れる」で読み直す（T41-D6。JS が無くても動く）。
   - 印の無い項目に値が入る。印の付いた項目は空のまま、画面の先頭の「この外国人ごとに入れる項目」にまとめて出す（T41-D2）。印の付いた行の種類は、下の欄で入れるよう知らせる。
   - 保存は今までどおり `contracts.create_version`（検査・届出の判定を変えない）。
   - 2 版目以降はひな形を使わず、前の版を写す（T41-D7）。
4. **ひな形と版を結ばない**（T41-D3）。値を写すだけで、どのひな形から作ったかは版に持たない。ひな形を直しても作成済みの版は変わらない（版は作った後に変えない。ADR-0016）。
5. **ひな形は上書きで直す**（T41-D4）。契約の記録ではないので版を持たない。作成・更新は監査ログに残し（AUDITED_MODELS）、報酬の値を含むので編集の画面の表示も閲覧として残す（VIEW_AUDITED_MODELS）。消さずに「使わない」にする。
6. **権限**（T41-D5）: 作る・直すのは受入れ機関を管理できる人（hosts.manage）。報酬などの契約の値を含むので、契約を見る権限（contracts.view）も要る。受入れ機関の詳細の一覧も、契約を見る権限のある人だけに出す。
7. **事業所はそのひな形の受入れ機関のもの**だけを選べる（サービスでも確かめる）。印は版の項目と明細の行の種類だけ。
8. **ダミーデータ**（T41-D8）: 1 社目（サンプル精機工業）の本社工場に 1 件。値は契約の版と同じ作り方（乱数は別の文脈のものを使い、後の場面の値を変えない）。外国人・契約・届出は作らないので、ほかの場面と gate2 の期待結果は変わらない。

## 仕様書との関係

仕様書第7章に employment_condition_templates のテーブルは無い。受入れ機関の付帯の設定の値として足した。
