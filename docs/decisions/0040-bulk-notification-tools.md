# ADR-0040: 電子届出の一括申込用ツールへの書き込み（一括届出）

- 状態: 採用（T50 書き込み・検査・生成、T52 届出タスクとの合わせ）。不在の間の指示（2026-10-20・21）により、決めてほしい点はおすすめで決めた（`.checks/phase4/blockC/plan.md`・`docs/decisions/log/phase4-blockBCD.md` の T50-D1〜D11）
- 日付: 2026-10-21
- 関連: ADR-0017（支援委託契約の届出）・0012（定期届出と第4-3号）・0018（Excel の書き方）・0039（一括申請）、`docs/tasks-phase4.md` の D1・D3・D4・D5

## 背景

電子届出システムで複数人の届出（所属機関の随時届出 6 種と、登録支援機関の特異事案報告）を一度に出すときは、入管の配る一括申込用 Excel ツール（xlsm。7 本）に 1 行 1 人で入れ、マクロ（「実行」）で CSV を作り、申込の画面の「添付（複数人の場合）」に添付する。ツールが出した CSV 以外は添付しない・CSV を編集しない（一括申込用 Excel ツール利用マニュアル 001346468.pdf 印刷 4〜5 頁）。システムは値を入れた xlsm までを作る（D1）。

## 決定（T50）

1. **様式マスタへの登録**（T50-D1）: 様式 ID `efile-3-1`〜`efile-4-3`（分野参考様式の `3-1` と分ける）、適用開始日 2026-04-01、改正日は不明（`revision_date_unknown`）。方式 `xlsm-efile`（新しい方式）。zip の中の xlsm をそのまま `templates/forms/efile-*/2026-04-01/original.xlsm` に置き、manifest に zip の SHA-256 と中のファイル名を書く。
2. **列の表**（T50-D2）: 道具 `tools/forms/extract_efile_columns.py` が、入力シートの名前・データの開始行・様式の行数（A 列の番号）・届出機関の欄のセル（4〜6 行の結合の左上）、隠しシート「列項目TBL」（列・項目名・チェック種別・桁数・桁数チェック種別・必須・業務コード種別・区切り・改行）、「業務コードTBL」（種別ごとの表示内容漢字と業務コード）、入力シートのリストの入力規則（静的な範囲の値、または INDIRECT の親の列。親は相対参照のずれで決める）と「連動リスト」のテーブル（INDIRECT が引く名前 → 値）を `mappings/efile-*/2026-04-01.columns.json` に書き出す。VBA の個別のチェック（CheckKobetsuKoumoku・GetValidRec の個別実装箇所）は、VBA を読んで道具の中の表（データ）に書き、同じファイルに出す。読み込み（`make forms`）のときにブックの SHA-256 と合っているかを確かめる。欄の対応（データのキー → 列）は道具 `tools/forms/make_efile_mappings.py` の出力 `2026-04-01.json`（列項目TBL のすべての列にキーが当たらなければ道具が止まる）。
3. **書き方**（T50-D3）: `services/form_xlsm.write_rows` で、入力シートの開始行から詰めて書く（「一覧部は、詰めて入力してください」001346468.pdf 印刷 4 頁）。表示名はインライン文字列（セルの書式は元のまま）。日付は年・月・日の 3 セルに、年 4 桁・月日 2 桁の文字で書く（マクロは 3 セルの `.Text` を「/」でつなぎ、10 桁で確かめる。セルの書式が「00」でも「@」でも `.Text` が同じになる）。届出機関の欄（法人番号・名称・「〒xxx-xxxx」＋改行＋住所）は届出機関の 3 つのセルに書く（CSV には入らない。電子届出の画面ではログインした機関の情報が出る。001344694.pdf 印刷 10 頁）。マクロ・ActiveX・隠しシート・テーブル・入力規則は 1 バイトも変えない。**1 ファイルは様式の行数（20〜22 行）まで**にし、超えたらファイルを分ける（様式の行の外は罫線・入力規則が無く、シートの構造を変えない〔制約3〕。一括届出の上限 300 人〔001452966.pdf 4 頁 Q15〕より小さい）。
4. **入力チェックの写し**（T50-D4。`services/efile_checks.py`）: VBA の CreateCSV・checkValue・GetGyoumuCd と同じ条件で、書く行のセルの文字を確かめる。
   - 業務コード種別のある列: 表示名が業務コードTBL と完全一致（末尾の空白まで。例「特定技能雇用契約の変更 」）。種別が複数でも最初の種別だけ引く（VBA のとおり）。
   - checkValue: 必須／全角文字混在は文字のチェックなし／半角数字のみ（カンマを除き trim）／半角英数字のみ／日付(未来日不可) は yyyy/m/d・日付として正しい・年 1900〜2099・未来日でない／桁数（カンマを除き trim、改行は 2 字）と桁数一致。文言は VBA の定数と同じ。
   - 個別のチェック: 3-1（事由ごとの必須）、3-3（事由ごとの必須・小分類「その他」の理由・登録番号の前 2 桁と後 6 桁）、3-4（事由の区分は必須で、届出の事由の名前で A036／A037 の表から引く）、3-7・4-3（事由があれば区分〔A170／A172〕・発生日・概要・措置内容〔A171／A173〕、区分「その他」の内容、措置「困難」「不可能」の理由）。
   - 足した検査: 入力規則のリスト（静的な値と、連動リストの親子の組み合わせ）。XML で書くと入力規則は効かないため。見出しの字数（「全角、２０文字以内」など）を超えた値は警告（生成は止めない。T50-D9）。
   - 未来日は生成の日で確かめる。マクロは実行した日で確かめるので、画面にそう書く。
5. **一括届出の持ち方**（T50-D5）: 一括届出（`BulkFiling`: 様式 ID・届出機関〔受入れ機関／自機関〕・表題・提出の記録）、行（`BulkFilingRow`: 届出タスク・外国人・順・届出の内容の値 JSON）、作ったファイル（`BulkFilingFile`: 追記だけ。様式の版・SHA-256・行・外国人・スナップショット〔暗号化〕）。同じツール・同じ届出機関の届出タスクを 1 つにまとめる。届出タスクは未着手・対応中で外国人のあるものだけ入れられる。
6. **届出機関**（T50-D6。D5 の確かめ）: 第3-x号は受入れ機関、第4-3号は自機関（報告機関）。
   - 制度編 Q&A（001344706.pdf PDF 2 頁 Q1）は、利用できるのを「特定技能所属機関の職員」と「登録支援機関の職員」とし、Q3 の一覧で登録支援機関が出すのは自分の随時届出と定期届出（支援実施状況）だけ。所属機関の届出を登録支援機関の利用者 ID で代わりに出せるとは書かれていない。
   - 操作 Q&A（001452966.pdf 2 頁 Q6）: 利用者 ID は 1 つの所属機関につき 1 つ。定期届出の作成要領（001454514.pdf PDF 2 頁 ②・13 頁 7）は「提出を行う特定技能所属機関のアカウントでシステムにログインしてデータ提出」とする。
   - → 届出機関の欄は受入れ機関にし、受入れ機関の利用者 ID で申し込む前提で作る。登録支援機関が代わりに出せるかは**未確認**（人の確認待ち）。
7. **届出タスクの種別**（T50-D7）: 手で起票する種別に「基準不適合に係る届出（第3-5号）」「支援計画の実施困難に係る届出（第3-7号）」を足す（所属機関・14 日。選択肢を足すだけで既存の行は変えない）。第3-7号は所属機関が自ら支援を実施する場合で、全部委託なら登録支援機関の第4-3号が通常（第3-6号別紙1 の裏面の※）であることを、起票の画面に書く。届出タスク → ツール: 雇用契約の変更・終了・新たな締結 → 3-1、支援計画の変更 → 3-2、支援委託契約の変更・終了又は締結 → 3-3、受入れ困難・行方不明 → 3-4、基準不適合 → 3-5、支援計画の実施困難 → 3-7、特異事案報告 → 4-3。
8. **値**（T50-D8。`services/efile_data.py`）: 本人の欄は台帳（ローマ字氏名を大文字・性別・国籍〔A103 の表示名と同じ国名だけ〕・生年月日・在留情報の最新行の在留カード番号・基準日の雇用契約の版の分野と業務区分〔表示名の頭で当てる。飲食料品製造業分野は「飲食料品製造業全般」〕）。届出の内容は届出タスクから既定値を作り、行の画面で直せる。
   - 3-1: 事由（変更 01・終了 02・締結 03）、発生日 ＝ 起算日。変更は変更の判定（雇用条件書の項番Ⅰ〜Ⅸ → 大分類、判定のコード → 小分類）。終了は終了理由（満了 → 期間満了、自己都合・転職 → 外国人の都合 自己都合退職、会社都合 → 所属機関の都合 経営上の都合。その他は空）とメモ（その他の理由）。締結は雇用契約期間。
   - 3-2: 支援委託契約の締結・終了に伴う変更（別表Ⅲ⑥⑦）は、大分類「登録支援機関」・中分類「33.10～18 全ての変更」（**推定**。画面に「推定: 要確認」）。締結なら変更後の内容に自機関の名称。
   - 3-3: 変更（委託料 → 「02.委託料」と月額、期間 → 「05.契約期間等」）・締結（契約の内容「支援計画の全部の実施の委託」）・終了（終了の区分と事由の対応表。ADR-0017）。登録支援機関の欄は自機関（登録番号の前 2 桁・後 6 桁、法人番号、名称、郵便番号、住所を都道府県・市区町村・以下に分ける）。
   - 3-4: 行方不明 → 外国人の都合・行方不明・連絡不可能。会社都合の終了 → 所属機関の都合・経営上の都合。
   - 3-5・3-7: 発生日（知った日）だけ。4-3: 定期面談の「基準不適合」の元があれば、その他の特異事案・所属機関における基準不適合等の問題を把握（**推定**）。
9. **見出しの字数とマクロの上限**（T50-D9）: 見出しの字数（20・30 字）を超えたら警告、マクロの桁数（300 など）を超えたらエラー。
10. **1 人に複数の変更**（T50-D10）: 雇用契約の変更の届出タスクは、変更事項（大分類・小分類）ごとに 1 行（同じ人を繰り返す）。
11. **個人情報**（T50-D11）: 在留カード番号を書くので、生成（GENERATE。一括届出が対象。様式の版・外国人・何枚目か）とダウンロード（DOWNLOAD）を監査ログに残す（値は残さない）。ダウンロードは forms.generate と、行のすべての外国人を見られる人だけ。スナップショットは暗号化の列。ファイル名は「一括届出_第3-1号_YYYYMMDD_<番号>[_1of2].xlsm」。
12. **画面**: ナビの「一括届出」→ 作る（届出・受入れ機関）→ 届出タスクを追加 → 行ごとの「入力」（届出の内容）→ 行ごとの検査の結果 → 「Excel を作る」→「記入済み（編集用）」をダウンロード。

## 決定（T52 届出タスクとの合わせ）

13. **届出タスクから作る**（T52-D1）: 一括申込用ツールに当たる種別の届出タスク（外国人あり・未着手か対応中）の画面に「一括届出に入れる」。同じツール・同じ届出機関で提出を記録していない一括届出があればそこへ、無ければ新しく作り、行を足して一括届出の画面へ移る。届出タスクの画面には、そのタスクを入れた一括届出（提出の日・受理番号）を出し、一括届出の画面の行から届出タスクへ戻れる。
14. **提出の記録**（T52-D2）: 一括届出の画面の「提出を記録する」で、電子届出の申込の日と受理番号を一括届出に持ち、行のすべての届出タスク（未着手・対応中のもの）を、届出タスクの状態の変更（提出済み）と同じ処理で 1 件ずつ変える（監査ログに 1 件ずつ。一括届出の番号を残す）。Excel を作る前と未来の日付は記録できない。記録した後は行を足す・直す・外すことはできない（作り直すときは新しい一括届出）。
15. **使い分け**（T52-D3）: 1 人の届出は電子届出の画面で入力し（「画面入力」）、2 人以上は一括届出の Excel。定期届出（定期届出（所属機関）の届出タスク）は、タスクの画面から受入れ機関の定期届出の様式の画面（ADR-0041）へ行ける（年度は起算日の前の年）。

## 未確認の点

- 所属機関の届出を、登録支援機関の利用者 ID で代わりに出せるか（決定 6。人の確認待ち。入管への問い合わせの一覧に入れる）。
- ツール 7 本の版（ページ・ツールに版の記載が無い。docProps の更新日で特定した）。
- 値を XML で書いたブックで、マクロの「実行」が動き、CSV が出るか（Windows の Excel で、MVP 完成後の価値検証で人が確かめる。D4）。Mac の Excel でマクロが動くか（ADODB.Stream・FileSystemObject を使う）。
- 同じ人の複数の行（変更事項ごと）を電子届出システムが受け付けるか（決定 10）。
- 見出しの字数とマクロの桁数のどちらが受付側の上限か（決定 9）。
- 3-2 の「登録支援機関の事項がすべて変わる」の中分類（決定 8 の推定）と、4-3 の区分の推定。
- 様式の行数を超える行を書いても受け付けられるか（決定 3 は行数で分けた）。
