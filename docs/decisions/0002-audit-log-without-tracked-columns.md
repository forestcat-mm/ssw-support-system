# ADR-0002: 監査ログに更新日時・更新者の列を持たせない

- 状態: 採用
- 日付: 2026-10-16
- 関連: 仕様書 第7章（共通列・audit_logs）、第8章（監査）、T05、ADR-0001

## 背景

第7章は、すべてのテーブルに作成/更新日時と作成/更新者（`TrackedModel` の 4 列）を持つことを求めている。
一方、監査ログ（`core_auditlog`）は追記専用で、モデル・DB トリガーの両方で更新と削除を禁止している（T05）。

## 決定

`AuditLog` は `TrackedModel` を継承せず、第7章の共通列の例外とする。

- 作成日時は `occurred_at`、作成者は `actor`（とその時点のユーザー名 `actor_username`）が担う。
- 更新日時・更新者は持たない。行は作成後に変わらないため、値は常に作成時と同じで意味がない。

## 影響

- 監査ログを「作成者・更新者を持つテーブル」として機械的に扱う処理（共通の admin mixin など）は、AuditLog を対象外にする。
- `actor` は User を削除防止付きで参照する。操作したユーザーは削除できなくなるが、ユーザーは削除せず無効化する運用（T04）なので問題ない。

## 検討した代替案

- **TrackedModel を継承して 4 列を持つ**: `created_*` は `occurred_at`・`actor` と重複し、`updated_*` は常に作成時と同じ値になる。列を足すだけで情報が増えない。
