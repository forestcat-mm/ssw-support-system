# ADR-0046: 画面デザインの見直し（2026-10）。トークン・同梱の字体・部品

- 状態: 採用（U1。U2・U3 で骨組みと外国人の詳細を足す）
- 日付: 2026-10-21
- 関連: `docs/design/design-2026-10/design-spec.md`（仕様）と `mock/`（見本）、計画 `.checks/ui-redesign/plan.md`・決めた点 `.checks/ui-redesign/decisions.md`。前の決定は `docs/design/README.md`（Officevibe の読み替え）

## 背景

業務画面のデザインを Claude Design のキャンバスで見直し、仕様と見本の画面 8 つを決めた（2026-10）。前のトークン（濃紺のナビ・明るいコバルトのリンク・ピルの太枠のボタン・クリームの罫線・角 12px）をやめ、白い面と細い枠・藍の強調の 1 色・状態は「色の点＋文字」にする。字体は Noto Sans JP にし、本番は閉じた網で使うので外から読まずに同梱する。

## 決定

1. **トークン**（`backend/apps/core/static/ui/tokens.css`）: 仕様 1〜3 の色・文字の大きさ・余白・角（入力とボタン 6px・パネル 8px・札 999px）にする。役割の変数の名前は残し（`--button-primary-bg` など）、値を入れ替える。`base.css`・`components.css` は役割の変数だけを参照する決まりのまま（`tests/ui/test_layout.py`）。
   - 文字と背景の対比は、使う組み合わせをすべて 4.5:1 以上にし、テストで計算して確かめる（`tests/ui/test_tokens.py`）。
   - 期限のレベル（超過・7日以内・14日以内・対応期間中・受付前）は、塗りの札をやめて「色の点＋文字」（danger・caution・ok・neutral）にする。クラスの名前（`badge--overdue` など）は変えない。
   - 分野の色（工業製品＝ラベンダー・飲食料品＝薄い緑）はやめ、状態の札と同じ細い枠の札にする（U1-D3。色だけで区別しない決まりにも合う）。
   - 影は浮く部品（「…」のメニュー・カレンダー・モーダル・自動ログアウトの知らせ）だけに残す（U1-D4）。
   - 等幅の字体（`--font-mono`）は本文と同じ字体にし、日付・金額・番号は `tabular-nums` で桁をそろえる（仕様 2）。
2. **字体の同梱**（U1-D1・D2 と補い）:
   - Noto Sans JP（400・500・700）: JIS X 0208 の字（第1・第2水準の漢字・かな・記号）と、ASCII・Latin-1・Latin Extended-A・よく使う記号の区画、業務画面の文言（.po とテンプレート）に出る字のサブセット。woff2 で 1 つ約 1.1MB。
   - Noto Sans SC（400・700）: GB 2312 の漢字のサブセット（約 0.95MB）。`unicode-range` を漢字の区画に絞り、JP の字体に無い字（母国語の氏名の簡体字など）だけに当てる。字体の並びは「Noto Sans JP → 端末の和文 → Noto Sans SC → PingFang SC・Microsoft YaHei」。`lang="zh-Hans"` の所は SC を先にする。
   - 置き場所は `static/ui/fonts/`（`fonts.css` の `@font-face`、`font-display: swap`）。ライセンス（SIL Open Font License 1.1）の文 `OFL.txt` と説明 `README.txt` を同じ所に置く。
   - 作り方は `tools/fonts/make_web_fonts.py`（fonttools で可変の TTF から静的な太さを作り、サブセットにする。開発のときだけ使う）。
3. **部品**（`components.css`）: 主ボタン（accent の塗り）・副ボタン（白地・枠。`button--neutral`）・行の中の操作（白地・accent の細い枠。`button--ghost`）・軽い操作（枠なし。新しい `button--light`）・危ない操作（`button--danger`。ふつうは「…」の中）・状態の札（`chip`。`tag`・`status` も同じ形）・状態の表示（`status-dot`）・件数の札（`count`）・タブ（下線 2px）・表（白いパネル・見出しの行・区切りの行 `table__group`）・入力の欄（「必須」の札は danger の小さな札）・セクション（`doc`・`doc-section`・`section-head`・`section-notice`）・項目の並び（`pairs`。横に 2 組、狭い幅で 1 組）・行の並び（`item-row`）。
4. **部品の見本**（`/ui/`）を新しい部品に合わせる。

## 影響

- 画面の見た目が変わる（業務の動き・URL・権限・監査ログ・データは変えない）。e2e は、主ボタンの色を見ていた 1 か所（`test_sign_in`）を直した。
- 静的ファイルが約 5.2MB 増える（字体）。ブラウザは使う太さだけを読み、SC は簡体字を出す画面でだけ読む。

## 未確認の点

- JIS X 0208 に無い人名の漢字（JIS 第3・第4水準など）は、端末の字体に落ちるので字の形が少し変わる（読めなくはならない）。実データで目立つ字があれば、サブセットに足す。

## 追記（U2: 画面の骨組みと一覧の画面。2026-10-21）

1. **骨組み**（`ui/base.html`・`base.css`）: 白いサイドバー（上に機関名、項目、下に設定・ユーザー名・ログアウト）を画面の高さに留める。右の上に白い帯（全体の検索）。前の上のバー（機関名・ユーザー名・ログアウト）はやめた。960px 未満は、サイドバーを上の「メニュー」の折りたたみにする（JS なし。今の形のまま）。
2. **ナビ**（`context_processors.NAV_ITEMS`）: ダッシュボード・外国人台帳・受入れ機関台帳・一括申請・一括届出・相談、下に設定（U2-D2）。管理画面（admin）へのリンクはどこにも出さない（管理者は `/admin/` を直接開く）。部品の見本は DEBUG のときだけナビに出し、`/ui/` は今の権限（SYSTEM_MANAGE）のまま開ける（U2-D3）。
3. **全体の検索**（U2-D1）: 上の帯の検索は外国人台帳の `q`（氏名・在留カード番号・旅券番号）に送る。外国人を見る権限のある人だけに出す。
4. **一覧の画面の型**: 見出しと主ボタン（1 つ）→ 期限のタブ（件数の札。`ui/components/list_tabs.html`・`apps/core/list_tabs.py`）→ 1 行の絞り込み（`ui/components/filter_bar.html`）→ 表のパネル。
   - 期限のタブ（U2-D5）: ダッシュボードは「すべて・期限超過・7日以内・14日以内・受理待ち」、外国人台帳は「すべて・期限超過・7日以内・14日以内」。「対応期間中」は「すべて」に含める。タブはリンクで、URL の `level`・`status` は今のまま。件数の「すべて」はレベルで絞る前の件数（`services` の結果に `total` を足した。業務の判定は変えない）。
   - 絞り込み（U2-D4）: select の最初の選択肢を「担当者: すべて」の形にし（`web_forms.label_inside`）、項目名は `aria-label` に残す。選ぶ・チェックを変える・日付を選ぶとそのまま送る（`form[data-auto-submit]`）。検索の欄は Enter で送る。JS が動かないときだけ「絞り込む」ボタンが出る（`.js .js-hidden`）。
   - ダッシュボードの「担当者なし」「今後の予定」は表の下に残す（U2-D6）。
5. **届出タスクの表**（ダッシュボードと外国人の届出のタブで共通）: 見本 01 の並び（期限の状態〔点＋文字。受付前は「受付前」〕・期限・種別・対象・届出主体・状態・担当者・行の右端に「記録」）にした。「記録」は主ボタンから行の中の操作にした（主ボタンは 1 画面に 1 つ）。
6. 表の行の上下の余白を 10px にし、行の高さを 46px にそろえた（文字の種類や札で高さを変えない）。表の中の見えない見出し（絶対位置）が横に送る枠の外へはみ出さないよう、表の枠を `position: relative` にした。

## 追記（U3: 外国人の詳細の上の帯・目次・タブ・概要。2026-10-21）

1. **上の帯（ふだん）**（`workers/detail_base.html`）: 戻るリンク（「← 外国人台帳」）、写真の枠（U4 までは頭文字の丸）、氏名とローマ字、状態の札（状態・在留資格）、在留期限の面（レベルの色の面と枠で日付と残り日数）、受入れ機関・分野・担当（「変更」）・支援言語、右に「編集」「…」。その下にタブ。この画面では全体の検索の帯は出さない（見本 03）。
2. **「…」の中の操作**（U3-D1）: 無効化・無効化の取消。概要の健康診断の書類の取消も「…」の中に移した。
3. **細い帯**: ふだんの帯が画面の外に出たら、細い帯（戻る・小さな写真・氏名・ローマ字・状態・在留期限の札・受入れ機関・担当・編集・タブ・目次の行）を上に留める（`forms.js` の `initPersonBar`。IntersectionObserver で出し入れし、スクロールのたびの処理はしない）。JS が動かないときは出ない。目次の今いるセクション（細い帯の下からの画面の半ばまでに入ったセクション）に `aria-current="location"` を付け替える。ページの中のリンクで移るときは、細い帯の高さの分ずらして止める（`--sticky-offset` と `scroll-margin-top`）。動きは付けない（`prefers-reduced-motion` にかかわらず、移るときにアニメーションしない）。
4. **タブ**（U3-D4）: 概要・契約・支援・届出・帳票・帳簿・履歴（並びを変え、「基本」を「概要」に。URL と監査ログの `context.tab` のキーは変えない）。タブは URL ごとの画面なので、見本の `button role="tab"` ではなくリンクのまま。並びの名前（`aria-label`）は「区分」のまま（e2e が探す）。細い帯のタブの並びは「タブ」。
5. **概要のタブ**: 今やること → 1 本人の情報 → 2 在留情報（期限の知らせ）→ 3 旅券 → 4 住所・連絡先 → 5 雇用契約（いまの版の要約）→ 6 支援（次の定期面談・前の定期面談・相談の件数）→ 7 一括申請の項目 → 8 健康診断の書類（U3-D2。見本に無い 7・8 は残し、`id` も残した）。
   - **今やること**（U3-D3 と補い。`services/worker_overview.py`）: この人の未完了の届出タスク（期限の近い順に 5 件まで。関係するセクションへのリンクと「記録」か「開く」）、この人を入れたまだ Excel を作っていない一括申請（この人の行の不足の件数）、提出用の PDF の下書き（申請の書類の一覧の、今日を基準日にした不足の件数。不足が 0 なら出さない）。
   - **見る人の権限**: 5 雇用契約は契約を見る権限、6 支援は支援を見る権限、今やることの届出タスクは届出を見る権限、一括申請と下書きは帳票を作る権限があるときだけ出す（タブの権限と同じ。目次からも外す）。
   - **監査ログ**: 閲覧は今と同じ 1 件。5 雇用契約の要約に出した契約の版の ID を `context.shown.contract_version` に足した。

## 追記（U5: 契約・支援・届出・帳票・帳簿・履歴のタブ。2026-10-21）

1. **契約のタブ**（見本 05）: 1 雇用契約（いまの版を「期間と場所・労働時間と休日・賃金・窓口」の小見出しで。主な操作「新しい版を追加」と「…」〔添付・雇用契約の登録・終了の登録〕。契約が 2 つ以上なら契約の一覧）→ 2 版の履歴（版・適用の開始・変わったこと・届出〔変更は届出タスクの版の番号、第 1 版は締結の届出〕・差分を見る、差分）→ 3 契約の書類（報酬の説明の入力と、様式ごとの最新の生成物と署名の状態〔未生成・生成中・署名待ち・署名済み・生成済み〕と作る操作。名前は今の「第1-6号を作る」などのまま）→ 4 支援委託契約（受入れ機関の今日効いている契約を読むだけ。U5-D2）。
2. **支援のタブ**（見本 06。U5-D1）: 1 定期面談（期限の知らせ・次の期限・前の面談・監督者のカード、面談を記録する）→ 2 支援計画（今の折りたたみの部品のまま。版の一覧と差分）→ 3 支援の記録（新しい順に 10 件。「記録をすべて見る」で今の記録の画面）→ 4 相談（対応中）→ 5 交付（新しい順に 10 件。「交付をすべて見る」で今の交付の画面）。目次の右に「＋ 支援を記録する」。全部の記録・交付の画面には今の小タブ（計画・記録・交付）を残した。
3. **届出・帳票・帳簿・履歴のタブ**: 番号つきのセクションと目次にそろえた（中身は今のまま。履歴のタブは 1 担当者・2 申請用の写真・3 台帳の履歴）。
4. 監査ログ: 支援のタブの閲覧の記録に、表示した支援の記録・相談・交付の ID を足した。件数は今と同じ 1 件。

## 追記（U6: 入力の画面の型。2026-10-21）

1. **項目名を左に**: 720px 以上の入力の画面（`form.form` の `form-row`）は、項目名を左 200px・欄を右に置く。補足・誤りは欄の下。719px 以下は今どおり上下。必須は項目名の太字と「必須」の札（今のクラスのまま）。
2. **上に留める細い帯**: 外国人に関わる画面（`ui/base.html` を使い、context に `worker` がある画面。詳細のタブの画面は自分の帯を持つので除く）は、全体の検索の帯の代わりに細い帯（戻る・写真・氏名・ローマ字・状態・在留期限・受入れ機関・担当・タブ・入力の目次）を上に留める。テンプレートタグ `person_band_for`（`apps/workers/templatetags/worker_band.py`）。今いるタブは URL の名前から決める。
3. **下に留める帯**: POST の入力のフォームのすぐ下の `.form-actions` を下に留め（`form-bar`）、左に「入力が足りない項目 n 件」（押すと最初の空の必須の欄へ）と「注意 n 件」（形式の注意）、右に「キャンセル」「保存する」（U6-D2・D4: 名前は今のまま）。ボタンの数は増やさない。
4. **欄を離れたときの確かめ**（U6-D3）: 必須の欄（`required`）が空のまま離れたら、欄の下に「入力してください。」（`role="alert"`）と danger の枠。入れると消える。形式の確かめは今の `data-normalize` のまま（caution）。欄どうしの確かめは JS に写さない。最後の判定は今までどおりサーバーで、JS が動かなくても保存できる。
5. **番号つきのセクションと入力の目次**（U6-D1）: 見出し（h2）で始まる `section.card` が 2 つ以上の入力の画面に番号を付け、4 つ以上なら入力の目次を作る（外国人の画面は細い帯の中、ほかは入力の上）。足りない欄・誤りのあるセクションの目次に danger の点。短い画面（取消の理由など）はセクションが無いので変わらない。
